## 1. 渲染

### 1.1 CSM 阴影贴图过滤是 `GL_LINEAR` —— 与 acne/bias 耦合，暂不动
- **现象**：阴影里暗粒之间沿**光空间 texel 网格**出现「亮缝」（屏幕上随相机旋转）。
- **根因**：阴影贴图是 **RGBA32F 颜色纹理**（`.r` 存线性深度，当年为绕开 llvmpipe 下 depth 纹理采样不可靠）；「无遮挡」texel 存 clear 哨兵 **`1e16`**。过滤误设成 **`GL_LINEAR`**（`EnsureShadowFBO`，MIN+MAG）。PCF 本应按整数 texel 偏移逐 tap 采样，LINEAR 却把每个 tap 变成对 4 texel 的双线性插值 → 沾到 `1e16` 就判受光 → 亮从受光格渗出 ~1 texel。
- **旁证**：引擎其它 depth 纹理（`depth_tex_3d_` / `depth_tex_hdr_` / `scene_depth_tex_hdr_`）都是 `GL_NEAREST`，只有阴影这张是 LINEAR。
- **现状（2026-10-09）**：试改 MIN/MAG → `GL_NEAREST`（本地 commit `f2fb92e`，未 push）→ **Danis 在 sky light viewer 看到人体 body 露出 acne** → 判定「不敢妄动」→ **已回退，main 保持 `GL_LINEAR`**，本地分支已删。
- **🔑 关键认知**：`GL_LINEAR` 一直在**顺手扮演「阴影图模糊」**，把本来就有的 acne 糊掉了；去掉它就露出 acne + bias 不足。**所以「过滤」不是孤立 bug，它和 acne / bias 耦合** —— 要正确解决必须**连同 bias/acne 一起设计**，属单独一件事。
- **可能的修法（下次要动时的骨架）**：① 过滤/哨兵（NEAREST 或**有限哨兵**）；② 同时补 **bias**（自动几何偏置可能对掠射/自遮挡不够 → slope-scale bias / normal offset）。**二者一起调，别单独动。**
- **来源**：`memory/2026-10-09.md`。

### 1.4 CSM 阴影 pass 不按级联剔除 —— 每帧 6 趟全场景几何（性能）
- **现象**：大场景（典型是植被实例：25 棵 oak 实例）在**软件光栅**（llvmpipe，WSLg/容器里
  常见）下交互只有 ~0.7 fps；且**每多一级联约 +1.1 s/帧**，与物体数量近似线性。
  实测（1280×720，容器 llvmpipe，6 帧总时长含 ~1.5 s 初始化；每档跑 3 次取中位数；
  **测于 #224 合入前**，那时叶卡还是平面 4 顶点/卡 ⇒ 烘焙后约 4.07 万顶点/棵、25 棵 ≈102 万）：
  - 5×5 25 棵 + **5 级联（默认）**：9.4 s ⇒ ≈**1.4 s/帧**
  - 5×5 25 棵 + 1 级联：5.1 s ⇒ ≈0.6 s/帧
  - 3×3 9 棵 + 1 级联：3.9 s ⇒ ≈0.45 s/帧
  - 单株 + 5 级联：2.5 s ⇒ ≈0.15 s/帧
- **根因**：`Renderer::DrawShadowPass` 的循环结构是 `for (cascade) { for (cmd) 全量画 }` ——
  object3d / instanced_object / skinned **每一级都把整个场景重画一遍**，**不按
  `ShadowConfig::cascade_ranges[c]` 做距离剔除**。默认 `cascade_count = 5` ⇒
  主 pass + 5 级阴影 = **每帧 6 趟几何**（`kMaxCascades = 5`，见 `render_command.h`）。
  配合"每顶点沿关节链 texelFetch"的风 VS，顶点着色次数直接 ×6。
  次要放大器：叶卡双面 + alpha cutout 的 overdraw（实测关叶图几乎不降 ⇒ 不是主要矛盾）。
- **顶点数已变（2026-10-28，PR #224 合入后）**：叶卡改成解析式弯卡，9 顶点/卡 ⇒
  `oak_low` 烘焙后 **58 752 顶点/棵**（管 26 199 + 叶 32 553，实测烘出来的数字），
  25 棵 ≈**147 万**（+44%）。下面那组绝对耗时是在旧几何上测的，量级会更差。
- **2026-10-28 用新几何复测**（同一台容器 llvmpipe，25 棵 oak，`--capture` 出 3 张图，
  含初始化；**口径与上表不同，只看相对关系**）：`--shadow-cascades 5` = 11.1 s、
  `--shadow-cascades 1` = 5.0 s ⇒ **2.2×**。结论与上表一致：级联数是第一旋钮。
- **现状（2026-10-27）**：**引擎未改**。只在 vegetation v2 查看器加了规避旋钮
  `--shadow-cascades 1..5`（默认仍是 5）和 `--forest-grid`（降实例数）：
  `--shadow-cascades 1` 把 25 棵从 ~1.4 s/帧降到 ~0.6 s/帧，代价是阴影距离只有 8 m
  （2 级 24 m / 5 级 440 m）。另在 `JPOV::Init` 打了 GL 实现日志 —— 第一件要确认的事是
  "到底是不是 llvmpipe 在跑"（`GL: renderer=llvmpipe …`）。
- **可能的修法（按性价比排序）**：
  1. **按级联剔除**：每级只画与 `[cascade_ranges[c-1], cascade_ranges[c]]` 环带相交的物体。
     **前置工作**：命令上要有世界包围盒 —— `GltfObject` 有 `bounds_*`，但
     `InstancedObjectCommand` / `Object3DCommand` **只有摆放、没包围盒**，得先从 mesh 包围盒
     × 摆放推出（每帧一次，可缓存）。
  2. **交换双层循环**（每命令、级联在内层）：除剔除之外还能让 per-instance 数据每帧**只上传一次**
     （现状 6 次，见下"陷阱"）。
  3. **按平台自适应**：软件光栅统一降到 1~2 级、或降 shadow map 分辨率（`cascade_sizes`）。
- **⚠️ 陷阱（别踩）**：**不能"只在第一级级联上传实例数据"**。级联循环是「每级遍历所有命令」，
  同一块 `InstanceBuffer` 会被**下一条命令覆盖** ⇒ 在第 2 级跳过后就会画出别的命令的实例
  （树/道具整体错位）。要省必须换循环结构（见修法 2）或改参数纹理。
  同一条注释也写在 `UploadInstanceWindAttrs` 上方。
- **相关**：1.1（阴影过滤/bias 耦合）、7.3（条带不参与阴影生成）。三者都在
  "阴影 pass/CSM"这块，动其中一个要先想清楚另外两个。
- **来源**：2026-10-27 逐实例风 PR #237 的卡顿调查（Danis 报「25 棵 oak 交互很卡」）；
  细节见 `memory/2026-10-27.md` 16:37 那节。

### 1.5 蒙皮反射体的剪影：属性 pass 与主 pass 覆盖率差 1~3 px（红边已挡住，根因待查）
- **现象**：夜间/日间都可能出现 —— **镜面人（蒙皮反射体）轮廓上的一圈像素**在开了 SSR 时
  变成**纯红描边**（R=255,G=B=0），日间镜面场景实测 57 px（Danis 2026-11-02 23:17 截图）。
- **根因**：合成式 `hdr − A·env_term + A·ssr_L·weight` 只有在"hdr 里那份环境镜面"与
  `env_term` 用**同一套参数**时才保证非负。而在蒙皮反射体的剪影处，**属性 pass 的覆盖率/
  法线与主 pass 有 1~3 px 的不一致**：实测这些像素 `hdr` 的 5×5 邻域 std ≈ 0（一片背景），
  而属性纹理里 mask=1、SSR 覆盖率 A≈0.9 ⇒ fusion 减掉的 `env_term` 远大于 hdr 里实际
  存在的那份 ⇒ **负辐亮度** ⇒ tone map 把负通道压 0、正通道顶满 ⇒ 纯红。
  二分证据（同一机位）：关 SSR / 直通 hdr / 只看 A 覆盖率 / 只输出 `ssr_L·A` **都无红点**；
  **去掉镜面人**也无红点 ⇒ 只在"蒙皮反射体 × 合成减法"这个组合上发生。
- **现状（2026-11-02）**：已用**物理硬约束**挡住 —— 被减项逐通道不超过现有量：
  `removed = min(mask·A·ao·env_term, max(hdr,0)); out = hdr − removed + mask·A·ao·ssr_L·weight`。
  正常像素上 `removed ≤ hdr` ⇒ 与旧式逐位相同（5 张 SSR gold **一个像素未变**）。
  复测：同机位 4 个材质档红点 57/76/80/72 → **0**。
  **但那一圈像素的 SSR 结果仍然是用"别处表面"的参数算的**，只是不再变成负辐射。
- **疑似根因（未验证，按可能性排序）**：
  1. 两个 pass 的**背面剔除 / `gl_FrontFacing`** 在剪影临界带判定不同（剪影处正好是前后翻面处）；
  2. 蒙皮属性 pass 复用的实例缓冲/矩阵与主 pass 有细微差异；
  3. 属性 pass 的 `uAttrBaseColor/Metallic/Roughness` 与主 pass 实际用的材质（纹理/逐实例
     tint）不同 —— 非镂空变体没有 UV，只能给材质常量。
- **可能的修法**：先做一张"属性 pass 覆盖率 vs 主 pass 覆盖率"的差分调试图（mask 与
  `hdr` 是否同一表面），定位到上面 1/2/3 哪一条；再让两个 pass 的绘制状态/材质来源严格同源。
- **来源**：Danis 2026-11-02 23:17 报「暴红的像素又回来了」；复现机位 pos≈(4.45,1.32,6.46)。

## 3. 蒙皮 / 重定向

### 3.1 重定向（root-motion 尺度自适应）的已知残余
- **⚠️ 先澄清（别误读）**：重定向**已经处理** root offset ——
  `root_offset_t = Q_body · root_offset_s · (leg_t / leg_s)`，即 **朝向归一（`Q_body`）+ 尺度归一（腿长比）**，
  **2026-09-20 已落地**。骨长走目标 `SkeletonType` 自身长度；旋转经 rest 基准共轭 **100% 保留**（逐骨世界偏差精确一致）。
  **以上都不是残余。**
- **真正的已知残余**（`docs/jpov_root_offset_design.md` §4）：
  1. **标量腿长比是粗略近似** —— 更准应按「链长比」（根→脚 的骨长和之比）；步幅、接触点仍受影响。
  2. **接触密集动作需额外 IK 修正** —— scale adaptation 只对**模糊动作**（跑步/走路）够用，精确踩点（含**脚滑/悬空**）需 IK。
  3. **水平位移未做裁剪/居中** —— 大幅位移（跑步）角色会跑出画面（**预期行为**）。
  4. **沿链 `rest_offset` 差 → 微小脚入地/出地** —— 不处理（Danis 明确接受）。
- **来源**：`docs/jpov_root_offset_design.md` §4、`docs/jpov_retarget_design.md` §6.2/§6.3。

## 6. 测试 / 环境（不是引擎 bug，但会干扰开发）

### 6.1 JPOV 同进程二次 `Init()` 假失败
- **现象**：本机**无长驻 Xvfb** 时，`Finalize` 会杀掉自建 Xvfb 但**没 unset `DISPLAY`** → 同进程再次 `Init()` 假失败。
- **解法**：先起长驻 `Xvfb :99` + `DISPLAY=:99`。
- **来源**：`memory/2026-10-07.md`。

### 6.2 `Xvfb :99` 争用
- **现象**：自建 Xvfb 与测试内嵌 Xvfb 抢 `:99` → 大批 gold test **假 FAIL**（primitives2d / bone_mesh / pliers / text3d_depth_alpha）。
- **解法**：`pkill Xvfb :99` 释放，或起长驻 `Xvfb :99` + `--test_env=DISPLAY=:99`。⚠️ `pkill -f "Xvfb :99"` 会**自匹配到自己的命令行**，小心。
- **附**：多个 session 并发跑测试（不同 `ai_infra_*`）各自 bazel `output_base` 隔离、互不影响编译，但**都抢 :99**。
- **来源**：`memory/2026-10-09.md`。

## 7. 半透明条带（Strip3D）

> 采样数四档（4/8/16/32）落地后（PR #229，2026-10-26 合入），条带的**功能面**基本齐了；
> 下面这些是**有意推迟 / 还没量**的部分，都不是 bug。

### 7.1 条带消费的 CSM 没有 PCF 软化 —— 阴影过渡突兀
- **现象**：玻璃缸场景里，树投在缸壁上的阴影边缘是**软块状硬边**（不像 object3d 那边有黄金角软化）。
- **根因**：§19.15 的取舍 —— 单级联单次采样、无 PCF（`CsmTap` 每片元只比一次），理由是
  「条带是薄片、片元多」「shadow map 是给不透明几何生成的」。这个理由对**物理精度**成立，
  对**观感**不成立；fog 同样单次采样但雾本身软、看不出来，所以只有锐利的条带暴露。
- **现状**：**未修**，记在 GitHub issue **#226**（`fix(jpov/strip): 条带消费 CSM 缺黄金角(PCF)软化`）。
- **可能的修法**：复用 `ShadowPcfConfig::GoldenSpiralOffsets()` + object3d 的 `pcfShadow()`
  （12 tap / 半径 2 纹素），把 `shadow_pcf` 塞进 `StripCsmShadow`；**偏置要乘采样核有效半径**
  （否则 12 tap 各自偏置不足 → 斜面 acne）；保持「不开天光零成本」。
- **来源**：GitHub issue #226、`docs/jpov_strip3d_translucent_design.md` §19.15、2026-10-25 Danis 口述。

### 7.2 条带不采环境镜面 —— 反射色是常量
- **现象**：玻璃/薄膜的边反只会朝 `rim_color` 这个**常量色**靠，映不出天空、树、地面。
- **根因**：`StripFresnel::rim_color` 是写死的颜色；条带 FS 里**没有任何 env cubemap 采样**。
  #228 的环境镜面（IBL specular）只注入 PBR（object3d / instanced / skeleton）三份着色器，条带不在内。
- **现状**：未做（`docs/.../jpov_strip3d_translucent_design.md` §19.6 已列为已知限制）。
- **可能的修法**：把 #228 的 `SkyRenderer::DrawSkyEnvCube` 探针纹理按 **17 号单元**喂给条带 FS，
  在 `SkyLightRadiance` 之外再加一项「粗糙度近似反射」（条带没有 roughness，需要按 fresnel 的
  `power` 反推一个 mip 级别，或直接固定取 1~2 级）。
  ⚠️ 注意：真要做「水面/海洋」，这条路不够 —— 需要**平面反射 / SSR**。
- **来源**：PR #228、§19.6、2026-10-26 本轮 review。

### 7.3 条带不参与阴影生成（不写 shadow map）
- **现象**：玻璃/薄膜不会给后面的物体投影。
- **根因**：半透明片要写 shadow map 得单开一次 shadow pass（或 alpha-tested 变体），
  和「条带只是一个 effect pass」的定位冲突。
- **现状**：**Danis 明确先不搞**（2026-10-25 定）。
- **可能的修法**：真要做得给条带单独一个 `shadow_cutout` 变体 + 独立 depth FBO，
  按 α 阈值写深度；收益/代价要先量（见 7.5）。
- **来源**：§19.15 末尾、Danis 2026-10-25 口述。

### 7.4 UV 只能铺一遍 —— 沿长度不能平铺
- **现象**：条带纹理沿长度**正好铺一次**；做不出雨丝、标线虚线、重复布纹这类「周期性图案」。
- **根因**：顶点属性里的 `u = col / (samples−1)` 恒在 `[0,1]`；`TextureManager` 虽然有
  `repeat` 选项（`WRAP_REPEAT`），但条带拿不到 >1 的 u，所以 repeat 起不到作用。
- **现状**：未做。**这条正好卡住 4 点档最典型的用途**（雨丝/辅助线/道路标线）。
- **可能的修法**：批级或 per-strip 加一个 `tex_repeat`（沿长度平铺次数），FS 里
  `ModulateTexture(vec2(vUV.x * repeat, vUV.y))`；per-strip 就塞进 per-instance 数据纹理
  现有的空闲位（行宽 = samples + 9，9 个 knot 之后还有 3 个通道没用）。
- **来源**：2026-10-26 本轮 review（Danis 问「strip 还差啥」）。

### 7.5 四档没有 frame-time 基准 —— 「该选哪档」目前只能靠结构推断
- **现象**：没有任何一次条带性能测量（4/8/16/32 × 折线/平滑 × 天光开关）。
- **根因**：gold 渲染里 PBR/CSM/bloom 占大头，测不出条带本身的成本，所以一直没做
  （§19.12、§20 都写了「不编数字」）。
- **现状**：未做。**已知的结构性结论**：四档**片元成本相同**（同一份 FS，覆盖像素一样多），
  差别只在顶点/索引量（8/16/32/64 顶点）与顶点着色。
- **可能的修法**：一个独立 bench demo（固定机位、N 条带、无后处理），输出 CPU 展开+上传 与
  GPU pass 的毫秒数；四档 × 两插值 × 天光开/关 = 16 组。
- **来源**：§19.12、§20、2026-10-26 本轮 review。

### 7.6 gold 覆盖不对称：只有 16 点有 gold
- **现象**：4 / 8 / 32 三档**没有独立 gold**，画面只靠 viewer capture 人眼验收；
  另有 `strip_degenerate_test`（退化几何）覆盖它们「不崩、不污染」。
- **根因**：四档化是最后一步，先保证 16 点档行为逐位不变（10 张 gold），新档位的金图没补。
- **现状**：未做。
- **可能的修法**：每档一张固定构图 gold（同一相机/材质，只换档位），断言彼此「差异像素数落在
  区间内」（4 点最折线、32 点最平滑），而不是互相逐像素比。
- **来源**：PR #229、2026-10-26 本轮 review。

### 7.7 折线 pass 没有解析 AA（只有平滑 pass 有）
- **现象**：细条带在 `kPolyline` 下边缘更硬；平滑 pass 有 `fwidth` 裁形 AA，折线 pass 没有。
- **根因**：折线 pass 的轮廓直接来自顶点插值，没有「真实参数 vs 保守外扩」这一步，
  所以也没有可用来做 1px 覆盖度的 `v*`。目前靠**宽度剖面**（profile 两端收到 0）+ 后处理 SMAA。
- **现状**：有意为之（折线 pass 的定位就是「快、够用」）。
- **可能的修法**：给折线 pass 也加 `fwidth(vUV.y)` 的边缘覆盖度（代价：每片元多一次导数推导，
  把「折线＝更便宜」这条优势削掉一部分）。要做先量（见 7.5）。
- **来源**：§18.5、2026-10-26 本轮 review。

### 7.8 一个 batch 只能一个混合集合
- **现象**：「膜 + 加法高光」这种组合要发**两个** batch（两次 draw call）。
- **根因**：`StripBlend` 是批级字段，`kCoverage` / `kEmissive` 互斥（WBO 两套附件的语义不同）。
- **现状**：未做（§19.6 已列）。
- **可能的修法**：一条命令同时写两个集合（需要一个「混合模式」枚举 + FS 里两段写入），
  或者干脆接受两次 draw call（当前做法，成本可控）。
- **来源**：§19.6。

## 8. 粒子 flipbook（纹理图集采样）

> 现状分工（`src/particles/particle_renderer.h` 的 `CellUV()`、`src/particles/particle_system.cc`
> 的 `ResolveFrame()`）：**CPU 算分数帧号 → 逐实例 `misc.w` → VS `flat out` → FS 换 UV**。
> GPU 不取时钟。图集是 `tiles_x × tiles_y` **行主序网格**，帧 0 在图片**左上角**
> （`vrow = tiles_y-1-row` 做了 v 翻转）。左→右单行 = `tiles_y = 1` 的退化情况，已支持；
> `assets/fire/mp/flames_pairs_v4_12x6.png` 用的就是 12×6。
>
> 下面三条是同一条采样链在「**透明 + 平铺 + 有帧**」同时成立时才会暴露的缺陷。
> 火焰走加法集、透明区 RGB≈0、且不做平铺，所以一条都没踩到；sp_ui 的 Plate 三条全踩，
> 故先记在这里。

### 8.1 `CellUV()` 没有半像素内缩 —— cell 边界会吃到邻居帧
- **现象**：图集里相邻两帧在 cell 交界处互相渗色。火焰看不出来；透明底 sprite（按钮/图标）
  会在轮廓上出现**一像素宽的彩边/接缝**，且随帧号变化跳动。
- **根因**：`(uv + col) / tiles` 在 `uv = 0` 或 `1` 时正好落在 cell 边界上，双线性同时取到
  相邻 cell 的边缘 texel。当前没有任何 inset。
- **现状**：未修（粒子侧无可见影响，故不动）。
- **可能的修法**：按「cell 像素矩形内缩半像素」重映射：
  `uv_tex = (uv * (cell_px - 2.0) + 1.0 + cell_origin_px) / tex_size`，其中
  `cell_origin_px = vec2(col, vrow) * cell_px`。图集生成侧也可顺带留 2px 透明 padding。
- **来源**：2026-10-27 sp_ui 设计讨论（Danis 要求记入本文件）。

### 8.2 平铺（repeat）与 cell 是两次 UV 变换 —— 顺序错 / 导数断会出错
- **现象**：材质平铺 + flipbook 同时用时，出现「贴图整体错位」或「每个平铺接缝上一条糊带」。
- **根因**：① 顺序必须**先 `fract` 平铺、再取 cell**：
  `uv_tex = (fract(uv * tiling + scroll) + vec2(col, vrow)) / tiles`；先除 tiles 再 fract 会把
  平铺周期与 cell 周期搅在一起。② `fract` 在接缝处导数不连续，`texture()` 自动选 LOD 会在
  接缝上跳到最粗 mip ⇒ 糊一条线。
- **现状**：未实现（粒子不做平铺）。
- **可能的修法**：UI 是 1:1 像素 ⇒ 直接禁用 mip（无 mipmap 的 `GL_LINEAR` 或 `GL_NEAREST`）；
  要 mip 就用 `textureGrad` 显式传**未取 fract** 的解析导数：`dFdx(uv * tiling) / tiles`。
- **来源**：同上。

### 8.3 帧间 `mix` 在 straight alpha 下会从透明区漏色
- **现象**：帧 A / 帧 B 交叉混合后，轮廓外侧渗出一圈本不存在的颜色（往往发白或发脏）。
- **根因**：`mix(c0, c1, t)` 混的是 RGBA 四通道；透明像素的 RGB 在 PNG 里是**未定义**的
  （导出工具常留白/留杂色），alpha 为 0 也照样参与 RGB 插值 ⇒ 半透明中间帧带出那种颜色。
  火焰无感知，因为透明区 RGB≈0 且整体进加法集。
- **现状**：未修（同 8.1）。
- **可能的修法**：**图集生成侧**做 color-bleed / dilate（把 RGB 往透明区外扩 4~8px，alpha 保持 0）——
  推荐这条，引擎侧不用加混合模式；或者整条链走预乘 alpha。
- **来源**：同上。

### 8.4 图集的「行序」取决于消费者的 UV 方向 —— 照抄 vrow 翻转会把动画倒着放
- **现象**：flipbook 能放，但**每到一个行边界就跳一下**（16 帧 4×4 的情况：每 4 帧跳一次，
  循环接缝处跳得最远），看起来就像「最后一帧和第一帧不闭合」。
- **根因**：`CellUV()` 里的 `vrow = tiles_y-1-row` 是为**粒子**那条链服务的 ——
  它的 `vUV` 与纹理 v 方向的关系与本翻转成对。sp_ui 的 Plate 用屏幕坐标算 UV
  （`uv.y` 向下递增，0 = 板材顶部），而 stb + `glTexImage2D` 把 PNG 第一行放在 v=0，
  两者已经是同一朝向 ⇒ **再翻一次就整体倒过来**：先播图集最后一行、最后才回到第一行。
  这不是“不闭合”（phase 仍然回环），是**播放顺序被打乱**，观感就是跳。
- **现状**：Plate 侧已改为 `vrow = row`（不翻转），并在着色器里写清楚理由。
  ✅ 粒子侧**未动**（不知道它的 billboard vUV 朝向，不动无根据的代码）。
- **可能的修法（若粒子也有同样现象）**：先用「每格一个纯色、颜色编码 cell 序号」的
  诊断图集跑一遍（本轮的定位手段），确认渲染帧 → cell 的映射后再决定翻不翻。
- **验证方法（可复用）**：取 `t = i / fps`（i = 0..N），逐拍对比渲染图；
  **逐拍差必须是均匀的**（min/max 比值 ≈1），并且 `t=0` 与 `t=N/fps` 必须**逐像素相同**。
  本轮实测：sine 2.24~2.65（比 1.18）、ripple 1.76~2.02（1.15）、noise 1.49~2.07（1.39），
  三者 `t=0` vs `t=loop` 最大差均为 **0**；而修复前的 sine 是 2.4/2.4/2.4/**9.4** 循环，
  修复前若用旧「溶解」图集则是 0.37~4.68（比 12.6，本身就是跨帧差过不均匀）。
- **来源**：2026-10-27 Danis「flip book 最后一帧和第一帧不一样，不闭合」。

## 9. SSR（屏幕空间反射）

> 现状（2026-11-13）：命中判据（三源柱体）、升采样（双边）、材质（逐像素 F0/roughness）、
> 粗糙度预滤波（A 预乘 mip 链）、A 的 4 个淡出因子（掠射 + 预算 / P 贴边 / Q 贴边）、
> 3 个遮丑滤波器都已落地。
> 下面按「文档债 → 观感缺口 → 能力缺口 → 外部依赖」排序，全部**未开工**（除注明）。

### 9.1 设计文档落后于实现（文档债，优先级最高但最便宜）
- **现象**：`docs/jpov_ssr_v2_design.md` 停在 PR #241（2026-10-29），文件头却写着
  「本文件与实现同步维护」。11 月之后的东西一个都没进去：半分辨率 + 双边升采样、
  逐像素材质、`SsrFilter` 的 A 预乘 mip 链、柱体**三源取最厚**、掠射淡出、以及本 PR 的六项。
  实测：`grep 三源 / fade_budget / 补洞 / atrous` 在设计文档里 **0 命中**。
- **另有一处待拍板**：`ssr_renderer.h` 里那段「★ 待确认」——起点沿法线抬高 vs
  「DDA 从起点格的出格点开始、起点格永不参与判定」。**实现是后者**，设计文档 §5.3 没写。
- **下一步**：按实现补 §8/§9/§10，并把 §5.3 定稿（我按实现写，Danis 复核一句）。

### 9.2 模糊半径不随距离补偿 —— 远景倒影糊过头
- **现象**：屏幕空间的 mip 角分辨率在远处偏大，同一块金属在画面远端比近端糊得多。
- **原因**：`SsrFilter` 的 LOD 只由 roughness 决定（`lod = roughness × roughness_to_lod`），
  没有"这块像素的倒影在多远"这个量。
- **修法**：SSR 额外输出**命中距离**（`d_hit`），消费端用它把核宽换算成世界尺寸再选 LOD
  （footprint → LOD）。同时也能给遮丑滤波器一个物理化的半径依据（现在只能靠经验趟数）。
- **优先级**：观感缺口里最高，成本中等。

### 9.3 A 只有"覆盖率"，没有"边界指示"
- **现象**：反射区的边界上，消费端分不清「这里真的是反射的边」还是「这里漏检了」。
  现在的 A 在两种情况下都往 0 走。
- **修法（低成本）**：额外一位「4/8 邻域是否有命中」，作为边缘提示给消费端做额外收缩/回退。
  不改变 A 的语义（A 仍只表示覆盖率）。

### 9.4 屏外缺失 —— `A = 0` 的最大来源
- **现象**：轮廓外侧一圈探针色；正面朝向相机的镜子映"身后"，屏幕空间里根本不存在。
- **现状**：靠 env 兜底（正确但糊）。这不是 bug，是屏幕空间方法的定义边界。
- **唯一真解**：宽视锥低分辨率层（设计文档 §10 ②）——只服务「未知区」，可以粗、可以无阴影。
  成本 = 场景重画一遍，属于中期项。

### 9.5 稀疏几何的倒影成实心（桩模型固有）
- **现象**：树冠、栅栏这类稀疏几何映成实心块。
- **原因**：厚度 `T ∝ d` 远大于叶片真实厚度（§9.4 已记录为「可调不可消除」）。
- **修法**：更薄的自适应厚度或 depth peeling，收益已递减；**不建议**投。

### 9.6 没有时间累积 —— 噪点只能空间滤波
- **现象**：运动时噪点闪；SSR 的"毛刺/梳齿"只能用空间滤波器压（本 PR 的三条就是空间派）。
- **原因**：JPOV 写死「每帧从零、无跨帧状态」（要进 gold）。
- **结论**：**不做**，别再提 TAA/SVGF 的时间部分。

### 9.7 掠射时倒影锯齿/闪烁（分辨率固有）
- 几公里水面压进几像素，采样不足。只能靠更高的 `resolution_scale`（成本）或 9.2 的 LOD 补偿缓解。

### 9.8 本 PR 两条滤波器的已知取舍（不是 bug）
- **小波 ≥2 趟明显发虚 + 轮廓浅色光晕**（支撑半径 = SSR texel × 2^k）⇒ 默认 1 趟。
- **补洞只处理 1px 缝**：更宽的"洞"多半是真的没数据，硬补会凭空造出倒影。
- **离群抑制**只夹离群点，不改 A（不凭空造覆盖率）。

### 9.9 水 / 玻璃（lux_glass）的前置 gap —— 不在 SSR 内，但会挡住这条路
- 设计见 `docs/jpov_lux_glass_design.md`（PR #255）。要真做水/玻璃，先补 **L0**：
  粒子/火/条带的 WBO 都是 `with_depth=false` ⇒ `TransparentLayer::valid()` 永不成立；
  需要 att3 `R32F` 深度槽 + FS `location=3` 写 `Σ(z·α·w)`，并停掉各自 `Composite()`。
- **另一处必须 Danis 拍板**：加法集（α≡0）在现有 3 张纹理里**没有位置**（`Cavg·(1−T)` 会除零、
  光全丢）。A = 加第 4 张 `add` / B = 独立 over —— 决定之后 L0 才能动工。

## 10. 水体（水凝胶，2026-11-16 起）

> 契约（职责划分与光学口径）见 **`docs/jpov_water_contract.md`**。本节只列**已知缺陷与边界**。
> **已实现**：M1 = 水凝胶（水体介质：沿视线的吸收 + 注入）、M2 = 水皮（界面层：水下
> Snell 环内/环外 + `S_P(∞)`；水上探针反射 + `T=(1−F)/n²`）、M3 = 天球折射（鉴定开关）。
> **水皮还欠的**：SSR 接进来（`A·SSR+(1−A)·sky`）；~~波面法线~~ ✅ 2026-11-18 已做
> （纯高度场 Gerstner + flow map，契约 §2.5）；太阳镜面项已做（§10.9 / `docs/jpov_specular_bandwidth.md`）；
> 照明已收口成「只消费 `cmds.sun` / `cmds.ambient`」，见契约 §5.1。

### 10.1 单次散射 + 常量环境（模型边界，不是 bug）
- 注入源只有两项：太阳束（折射方向 + `(1−R)` + `cosθa/cosθw` + HG 相位）与**各向同性常量** ambient。
- 真实水体（尤其浑浊/深海）的渐近辐射度是**多次散射**的产物 ⇒ 强度偏低、角分布偏尖。
- 这一档误差在“光强基本对”的目标内，但**不能当成解了 RTE**。

### 10.2 `K_d` 是折合衰减，不是 RTE 本征值
- 环境光随深度用 `K_d = σa + (1−g)·σs`，不是解渐近本征值 ⇒ 浑浊水里有 1~2× 误差。
- 直射束用 `σt`（正确），两者不同口径 —— 这是有意为之，不是手误。
- ⚠️ **M1 现状**：视线侧（本 PR）的 ambient 项按常量 `L_amb` 积分、衰减率用 `σt`；
  `K_d` 那条属于**照明侧**（M2 未做）。两侧统一待 M2。

### 10.2b 介质内太阳项的界面增益 —— ✅ 已修正（2026-11-17）
- 旧写法 `gain = (1−R)/n²`（沿用最早设计，把**辐亮度**的 `1/n²` 错用在辐照度上）。
  进散射源要的是**法向辐照度** `E⊥`，正确系数是 `(1−R)·cosθa/cosθw`（**无 n²**）。
- 推导（功率分账，与公式无关的物理判据）：每单位界面面积的入射功率 = `E⊥,air·cosθa`，
  反射掉 `R` 后剩 `(1−R)·E⊥,air·cosθa`；进水后光束的**垂直截面 = cosθw**（Snell 折弯）
  ⇒ `E⊥,water = (1−R)·cosθa/cosθw`。
- 已改两处（`water_medium_math.h` / `water_medium_shader.h`，同源），并加两条单测：
  「垂直太阳 gain 必须恰为 `(1−R)`，且是旧口径的 `n²=1.777` 倍」（回归点）+「功率守恒
  `gain·cosθw == (1−R)·cosθa`」+「太阳越低注入越小」。
- 实测影响（`--capture-water-light`，太阳仰角 45°、同一水体区）：太阳项占水体亮度的
  **33% → 54%**（gain 0.551 → 1.28）；岩板中心处只差 ~1%（那里亮度主要由岩板本身贡献）。

### 10.3 视线折射：路径长度已算，图像仍不位移（L0）
- `len_w = len·|rd.y|/|dy_w|`：对同一深度的物体，**消光精确**（`Δy/cosθw`）。
- 不拐弯 ⇒ 水上看水下的物体**位置偏浅/偏近**；水下看水上也一样。
- 为什么这样可以精确（而不是近似）：水体水平均匀时，直线与折线经过同一组深度、`J` 与剩余衰减都只依赖深度 ⇒ 换元等于雅可比。**唯一损失是成像位置**。

### 10.4 不消费 CSM
- 介质里的太阳项没有阴影 ⇒ 岛影里会出现“物体有影、周围水在发光”。
- 升级时注意：消费 CSM 会把**闭式变成分段积分**（可见性沿视线分段），且水下 CSM 的口径本身待修。

### 10.5 形状化之后这套闭式作废（判据写死在这里）
- 现在用的是**水平均匀半空间**的闭式。一旦水体变成体素/任意形状：
  ① 换元不再成立（直线上的体素 ≠ 折线上的体素）；② 必须改为沿折射路径 DDA。
- 换的是 `MediumAt(ro, rd, z)` 的**实现**，不是槽位 —— 合成器与水皮无感。

### 10.6 逐通道透射 = 两次 draw（固定管线限制）
- 水体 σ 跨通道差 20+ 倍 ⇒ `T` 必须是逐通道，而固定管线一次做不了 `dst·T + L`。
- 于是两次 draw：`ZERO/SRC_COLOR` 乘 T，再 `ONE/ONE` 加 L。**加 L 那趟 alpha 必须写 0**（blend 对 alpha 用同一组因子，写 1 会把 dst alpha 累加成 2.0）。

### 10.7 雾只在水上（约束，不是假设）
- `τ = τ_fog + τ_water` 只在两者互不衰减对方时精确；交叉项 `∫e^{−(τf+τw)}(j_f+j_w)` **无闭式**。
- 处理方式是把雾场的定义域限在水面以上（水下 `CHECK`）⇒ 两者空间不相交 ⇒ 相加精确。
- **通用规律**：解析介质 ⊥ 离散介质时，交叉衰减无闭式；让离散方承担（它有 slice），或让两者空间不相交。

- **天球折射**：`WaterBendDir()` 作为天空 pass 的**后处理方向变换**（不是 `if(underwater)` 分支），各趟（`kFull` / `kEnvProbe`）一致，探针 cube 不弯，环边 padding 气侧 3° —— 见契约 §3。

### 10.11 水下物体的**照明**完全不经过水柱（不是「日盘像」，但看起来很像）

> 2026-11-17 Danis 问「透射角度上也有太阳的像，合适吗？」—— 水皮那层没有（`sun_spec` 只走镜像方向，
> 透射支路只有 `T·背景`）；看到的是**水下物体自带的 PBR 太阳高光/日照**。

- 现状：合成器只衰减**相机 → P** 那一段（视线侧）；物体本身的直射/高光/漫反射仍按**空气里**算。
  PBR 完全不知道有水体（`renderer` 也没把水传给 object3d）。
- 量级（默认 σa=(0.35,0.054,0.014)、σs=0.05 ⇒ σt=(0.40,0.104,0.064)；岩板深 1.7 m、
  太阳仰角 28° ⇒ 空气入射 62°、水中 41.5° ⇒ 光路径 1.7/cos41.5° = **2.27 m**）：
  日照应乘 `exp(−σt·2.27) = (0.40, 0.79, 0.87)` ⇒ 现在**红偏亮 2.5×、绿 1.27×、蓝 1.16×**，
  且水下物体应该明显**偏蓝**，现在是空气里的暖色。
- 太阳**方向**也没折射（空气 62° vs 水中 41.5°）⇒ 水下物体上的高光位置也是错的。
- 判据：这不是「日盘像」问题（那个在水皮上，已做），而是**照明侧**。属于 §10.2 提到的
  「照明侧」缺口的实体化。
- 便宜修法（可独立小 PR，均匀半空间有解析式）：
  `E_水下 = E_空气 · (1−R) · cosθa/cosθw · exp(−σt · depth/cosθw)`，太阳方向换成 Snell 折射后的；
  粗糙一点的版本只乘标量衰减、不改方向（能修颜色，修不了高光位置）。
- 完整做法（下一个 milestone）：水侧光照（折射方向 + 逐光源衰减 + 介质多次散射），与 §10.1 一起。

### 10.9 天体（日月盘）在反射里不可靠 —— SSR 也兜不住
- 探针 `SkyOutput::kEnvProbe` 按设计**不含日月盘** ⇒ 走探针时永远没有太阳的像。
- SSR 采的是 `color_tex_hdr_`（天空 `kFull` 先画、SSR 在几何之后跑）⇒ 日盘**确实在缓冲里**，但屏幕空间 DDA 会 miss（不在视锥 / 反射方向出屏 / 射线长度不足 / 被遮挡）⇒ 命中时有一条、miss 时整条消失 ⇒ 太阳的像**随相机转动时有时无**，看起来就像 bug。
- 正确做法：日盘必须是**独立光源项**（同一个 GGX，`α² = 斜率方差 + 日盘角半径²`），不要指望 SSR 采到它。
- ✅ **已落地（2026-11-17）**：`DirectionalLight::angular_radius` + 水皮解析日盘项（`C = F·L_refl + sun_spec`），
  平面水面也有 0.53° ≈ 6.4 px 的日盘像（实测 17×36 px 垂直拉伸的椭圆，拉伸比 1/sin(28°)≈2.1 对得上）。
  带宽口径 `a2 = (θ/2)² + 像素足迹`；详见 §11.6。
- 这不是水特有：**δ 光源 × δ BRDF 的通用问题与业界解法见 §11**。

### 10.12 水面波浪（2026-11-18 落地）的三个已知边界
- **介质仍按平面 `level_y` 积分**：波浪只改界面层（求交/法线）。波峰/波谷处界面与水柱
  有 O(波高) 的缝隙（浅层透射 ~0.98/m ⇒ 亮度差 ~2%，肉眼无感）。修法是沿折射路径 DDA
  ⇒ 并入 §10.5「形状化之后闭式作废」那条。
- **近处水面视觉重量偏弱**：俯视角大 ⇒ 菲涅尔 F≈2%~5%，反射几乎不可见，颜色主要来自
  「均匀介质 + 透射」⇒ 看起来像塑料板。真实近景水面靠**泡沫/次表面/水底细节**撑起来，
  泡沫是 part 2；次表面在契约里明确不做。**这是阶段性限制，不是波浪没生效**（远处掠射处
  碎光与 glitter 光带非常明显）。
- **不做 choppy（水平位移）**：求交必须单值高度图；choppy 会把求交变成隐式方程。
  波峰尖锐度目前只靠多波叠加与陡度，不做 Gerstner 的 Q 参数。

### 10.13 像素足迹里的 `max(|rd.y|, 0.15)` 地板（2026-11-19 记）

水皮的足迹公式是

```
footprint = t · (2·tanHalfFov / viewport_h) / max(|rd.y|, 0.15)
```

那个 **0.15 是人为地板**（当初为了“别让远处足迹无限大、整片海被谱截断成平面”）。
代价很具体：视线一旦比 8.5° 更贴水面（`|rd.y| < 0.15`），真实足迹 ∝ 1/|rd.y| 会继续增长，
但公式不再跟着涨 ⇒ **足迹被系统性低估** ⇒ 谱截断杀得不够 ⇒ 那一段可能出现
法线/位移的亚像素抖动。

- 按当前相机高度 15.8 m 估：`|rd.y| = 0.15` 出现在 **≈ 105 m**；再远全靠 `max` 兜着。
- 现在实际兜住这段的是 **fade（150..900 m）**，不是截断。实测（2026-11-19）：
  关掉 fade 后逐像素时间差分 0.36→0.39（几乎不变）、波幅 ×3 也如此 ——
  因为 24 m 的波被截断杀掉的时刻 ≈ 1125 m，和 fade_end 900 m 只差 200 m。
- **所以 fade 目前是「足迹公式缺陷」的保险丝**。要删 fade，顺序必须是：
  先修足迹（去掉地板，或改成各向异性真实足迹）→ 再让截断接管遮丑 → 最后删 fade。
- 修好之后 fade 会退化成纯艺术开关（“想让远处变平就开”），与物理无关。

### 10.14 法线场过滤（远处亚像素波 → 粗糙度，2026-11-19 落地）的边界

- **方差来源**：`MSS = 被足迹截断的斜率方差 + 未建模短波尾巴`。尾巴用 Cox–Munk
  `0.00512·U + 0.003 + 0.00192·U`，U 是 10 m 高风速，**0 = 不补**（默认）。
- **各向同性**：只用了标量 MSS；其实应该是 2×2 张量（沿风:横风 ≈ 2.7:1），否则
  远处 glitter 带是圆盘而不是沿风向拉长的椭圆。下一个 PR。
- **E_ss 是近似**：多散射补偿的 `E(μ,α)` 用 Karis 2013 EnvBRDF 拟合在 f0=1 退化得到，
  不是严格的 furnace 积分；要更准需要 32×32 LUT（Turquin 原文口径）。
- **env LOD 仍被钳在 1.5**：放开前必须先把探针下半球填对（否则地平线会混进地色，
  见 §10 开头那条“深色裂隙”）。
- **能量仍会变暗**：补偿只恢复积分能量；峰值按 1/α² 掉，所以高光看起来更宽更淡 ——
  这是正确的观感，不要试图“补回峰值”。

### 10.15 反射率/透射率随粗糙度的修正（`F_eff`，2026-11-19）

- **定义**：`R_eff(μo,α) = ∫ f_ss·F(ωo·h)·cosθi dωi`，`T_eff = 1 − R_eff`。掠射下远低于平面菲涅尔
  （2° 仰角：平面 0.80 → 0.36/0.26/0.17 对应 a2 = 0.017/0.05/0.15）。
- **实现是拟合，不是精确积分**：`R_eff ≈ mix(F(cosθ + 0.52·√a2^0.72), F(cosθ), smoothstep(0.05,0.5,cosθ))`，
  对 12×6 的 Monte-Carlo 表（GGX + Smith G1、n=1.333）平均误差 0.026、最大 0.074（20°~30° 偏暗）。
  要更准就换 8×6 LUT（Enterprise PBR 的口径）。
- **只用 G1 的可分离近似**做表；高度相关 G2（Heitz 2014）会略有差别。
- **太阳项也吃同一个 F_eff**：粗糙度上去以后日盘像整体变暗（不只是变宽）。
- **已知缺口**：反射仍是「单方向采样 + 有上限的模糊」，没有真正对 lobe 积分；LOD 被钳在 1.5。
  实测把上限临时放到 4：海/天亮度比 0.45 → 0.38（有用但不是主因，主因是风速对应的真实 MSS）。

### 10.15b 远场 F_eff 的两个后续（2026-11-20 修完守恒后仍然成立）

**① 细节短波的斜率预算与 Cox–Munk 未对齐（双重计数）。**
64 条细节以 kA=0.07 生成 ⇒ `Σ½(kA)² = 0.157`，而 U=8 时 Cox–Munk 的**总** MSS 只有 0.059
（≈2.6×）。短波项又按 Cox–Munk 全额加了一遍 ⇒ 远场 `var_p ≈ 0.226`，比物理值高 ~3.8×。
按物理应该 `Σ½(kA)² = α·CM`、短波项 = `(1−α)·CM`。
**没改的原因**：改完远场 R_eff 从 0.155 回到 0.30（更灰），与"远海要蓝"的观感相反 ——
留作"要物理正确"时的开关，等视觉侧定案。

**② `RoughFresnelAlbedo` 的拟合区间被外插。**
解析近似验证过 MSS ∈ [0.017, 0.15]（平均误差 0.026）。守恒修完后远场 `var_p = 0.226`
≈ 1.5× 上限，`R_eff` 是外插值（单调、方向正确，误差未验证）。
先不钳（钳到 0.15 会让掠射 R 从 0.155 涨回 0.196，正是要避免的"变灰"）；
若后续在低角度看到异常亮/暗，再考虑钳制或补一组高 MSS 的 MC 拟合。

### 10.16 拉宽 / 拉糊两个消费者：② 已落地、① 未采用（2026-11-23 按报障修复）

**2026-11-23 的结论**（报障：默认配置 + 风速 0.7、`report_cam_75m` 机位，海面有硬边）

- **实锤**（拍照 + 红框像素 + 逐变量 A/B）：那是一条**近 Nyquist 细节波的走样带**，
  不是几何/深度/介质 bug，也不是 CPU/GPU 分叉。
- **② 拉糊（本节原方案）已实现**：`env_lod = log2(2σ/texel)`，σ² = `var_p + normal_var_px`；
  上限按反射方向仰角放开（近地平线 1.5 级、仰角 >20° 放到 3 级，避免把探针下半球的地色卷进来）。
  **实测对这条硬边无效**（0.0% 像素变化）：反射方向扫过的是**平滑的天空渐变**，
  对线性函数做模糊等于没糊 —— 本节 2026-11-19 那句"糊了也看不出"是对的。
  但它对"远处法线噪声造成的探针闪烁"仍是对的做法，保留（成本只有一次 log2/sqrt）。
- **真正的修法是谱截断的 Nyquist 门限**：`kWaveLodPxMin` **2 → 3 px**（CPU / GLSL 同值）。
  2 px 是理论极限，逐像素中心采样实际需要 3~4 px；落在 2~3 px 的波只剩走样、没有可用信息。
  实测（`report_cam_75m`，t=148 s）：带状对比度 **31.1 → 11.3 / 255**（行 std 6.7 → 3.5）；
  被截掉的能量照旧经 `var_p` 进 BRDF（能量守恒），全场景 A/B 平均 |Δ| = **2.1/255**、
  |Δ|>8 的像素 **4.1%**（`kWaveLodPxMin=4` 时是 3.3/255、8.8%，收益相同但改动更大 —— 取 3）。
- **① 拉宽（`var_p` → 太阳 lobe）没有采用**：实测把 `var_p` 加进 `a2` 会让海面整体**提亮 18%**
  （lobe 变宽后更多像素命中太阳），而硬边对比度只从 31 降到 26 —— 那是"改观感"不是"修 bug"，
  要做得对得先补能量补偿（多散射 / 归一化），单独再做。
- **真因（2026-11-23 二次定位，上面那条只治了走样带）**：生硬的来源是**求交的兜底分支**。
  `amp_sum` 只累加**位移波**（细节波不进求交）；位移波被足迹全部截断后 `amp_sum == 0`
  ⇒ `span == 0` ⇒ 二分区间两端同号 ⇒ 走进"理论上不会发生"的兜底：`t = t_plane; return`，
  而法线留在初值 `(0,1,0)`、**`AddDetailWaveGradients` 根本没被调用**。
  ⇒ 一过门限整片水面变成完美镜面（连仍旧解析得出来的细节波一起丢），
  且断点随 `kWaveLodPxMin` 平移（2 px→80 m、3 px→63 m，`report_cam_75m` 实测）。
  修法：把「定 t」与「求法线」解耦（CPU `sample_at`/`finish`，GLSL `WaveNormalAt`），
  兜底只回退 t、法线照常按梯度求；`amp_sum == 0` 直接跳过二分（省 12 次全零求值）。
  回归：`WaterWaveMath.TruncatedMainWavesKeepDetailNormals`（旧代码红）+ 负向
  `WaterWaveMath.FullyTruncatedWavesAreFlat`（连细节波都亚像素 ⇒ 必须确实是平面）。

#### §10.16 后续：远场「过度变平」的 M1–M3（2026-11-23 Danis 定稿）

**现象与量化**（`e_light_air` + `report_cam_75m`，探针直连 `water_skin_math.h`）：
被足迹截断的斜率方差 `var_p` 在 40 m 就到 **0.011**、400 m 饱和在 **0.017**；

**口径更正（三条，都是这次才想清楚的）**

1. 亚像素细节必须经**三条**通道体现，我们只有 2 条：
   ① 反射率重分配（`water_skin_shader.h:242 RoughFresnelAlbedo`）✅

   ③ **太阳 lobe 变宽**（`:263` 的 `a2`）❌ —— 这条是远海碎光的全部来源。

3. §10.17-1（「`F_eff` 是半球方向反照率、不是对 lobe 的积分」）与 M1 是**同一件事的两面**：

   另：§10.17-5（多散射补偿）优先级从第 5 提到与 M1 同级；§10.17-3（各向异性）在 M1 之后
   才变成可见问题（远场眩光是圆盘，而不是沿风向拉长的椭圆带）。

**M1（lobe 拉宽）✅ 2026-11-23 已落地**（PR「M1+M2+M3：远场 lobe / 多散射 / glints」）：
`a2 = min(盘角² + footprint_a2 + normal_var_px + kGlintSmooth·var_p, 0.25)`，
CPU / GLSL 同源（`var_p` 已按入射面投影，来自 `WaveFilteredVariance` 的张量）。
默认就是正确算法，**不给关掉的开关**。`kGlintSmooth = 0.75`（见下 M3）。

**M2（多散射补偿）✅ 2026-11-23 已落地**：`ms = 1 + F_avg·(1−E_ss)/E_ss`（Turquin 2019 简化式），
实现成**同一条乘子同时作用在反射率 F 与镜面项**（保 R+T=1）：
`F = min(R_ss·ms, 1)`，`f_spec = f_ss·ms`。
- `E_ss(μ, α)`：**16×16 表**（NDF 重要性采样离线算；α=1、μ=1 → 0.307 与 Kulla–Conty 一致），
  `ggx_specular.h::kGgxAlbedoTable`；GLSL 端由 C++ 数组**格式化生成**字面量 ⇒ CPU/GPU 不可能漂。
- `F_avg`：`FresnelAvgDielectric(ior)`（水 ≈ 0.068），CPU 每帧算一次走 uniform。
- 回归：`test/lighting:ggx_albedo_test`（表 vs 独立数值积分 <2%、物理边界、单调性、F_avg 自洽）+
  `WaterSkinGpu.ReflectanceIncludesMultiscatter`（反射率逐位 = min(F_ss·ms,1)）。

**M3（glints）❌ 试过后废弃 / 各向异性 ⬜**（2026-11-23）
- **glints 试过，Danis 实拍判定不可接受 ⇒ 已从着色器删除**（同日）。做法当时是：把 `var_p` 当成分布、
  每像素抽一个面片（`GlintGaussian2` + `hash(pixel,time)`，控制变量法 `kGlintSmooth=0.75`：
  0.75 走解析带宽、0.25 走随机残差，估计量无偏）。
- **为什么不行（这是结论，别再重试同一条路）**：1 spp 抽样在屏幕上得到的是**白噪声**——
  Danis 原话「噪声太强，远近都有，远处尤其显著」。实测 `--capture-water-waves` 掠射图的
  高频能量：修 M1 前 0.597 → 加 glints 后 **2.76** → 删掉 glints 后 **0.624**。
  物理原因：真实 sparkle 来自**毫米级毛细波**（一个像素里成千上万个面片，相机/眼睛把它积掉，
  得到的是均值 + 轻微闪烁）；而我们谱里最细的波是 0.3 m —— 一个像素覆盖不到一个波长，
  抽样只能得到噪声、得不到「碎光」。**想要真 sparkle 得先有毛细波尺度，不是靠抖法线。**
- **各向异性 lobe（2.7:1 沿风）仍未做**：现在抖动/带宽都是**各向同性**的。做法已明确
  （对 `WaveSlopeTensor` 做 2×2 特征分解 → 主轴 + 两个方差 → 各向异性 GGX D/G），
  但它改的是眩光的**形状**不是能量，与 M1/M2 解耦，单独一次做完更安全。
- 现状（2026-11-23 Danis 验收口径）：**只走解析均值** —— 眩光是一条**平滑展宽**的光带（6~7°），
  没有逐像素噪声。它不「碎」，但这是**目前谱分辨率下唯一诚实的答案**。
  下一步若要「碎光」：给谱补毛细波段（λ ~ mm-cm，只进 MSS/glint 项，不进几何），
  再用**多样本 + 重要性采样**或 Yan 2017 的位置无关采样 —— 不是单样本抖动。

**验收判据（都可自动量）**
1. 远场（≥180 m）太阳眩光半角 **0.13° → 7°±1°**（拍 `--capture-ocean-lab` 量饱和带宽度）；

### 10.17 本 PR 没做的事（按优先级）

### 10.18 水下装饰几何不许做「共面薄垫」（2026-11-20 Danis 实拍）

**现象**：海面选型场的海底原本叠了 24 片 2~6 m 的"礁斑"（比沙底高 **1 cm**，albedo 0.55~0.8）。
两轮都被读成 artifact：

1. **黑洞**：砂底穿过 3.5 m 水后红通道只剩 ~17%，再叠一层暗 10~25%、**硬边、无纹理**的方块
   ⇒ 视觉上就是"水下的黑色方形洞"（实测块内 38/71/73 vs 块外 43/81/82）。
2. **Z-fight**：1 cm 的抬高远不够。GL 24-bit 深度、near 0.05 / far 1000 时
   `Δz ≈ z²·5.96e-7 m` ⇒ 76 m 只有 **3.4 mm/级**（1 cm ≈ 3 级），130 m 时 1 级，
   300 m 时 0.2 级。Danis 的机位（|pos|=76 m）关掉水后红框内就是**横向条纹交错 + 阶梯边**。

**结论 / 规矩**：

- 水下**不要**用"贴合大平面的薄垫"做装饰。要么**不叠**（画一整块底），要么做**有厚度的体块**
  （盒子/凸起，自身深度差 ≫ 阈值），要么用 `glPolygonOffset`（本项目未接）。
- 若非要抬，安全量级 **≥ 10×Δz**：76 m ≈ 3.4 cm、150 m ≈ 13 cm —— 到这个厚度早就"浮起来"了，
  所以实际结论就是**别叠**。
- 视觉侧同理：低对比水下场景里，**硬边 + 大块纯色 + 10~25% 的亮度差**就足以被读成"洞"，
  与"是不是 bug"无关。

**现状**：24 片礁斑已删除，场景只保留一整块 120×120 m 沙底（`skylight_viewer_app.h` 场景 4）。
**排查方法（可复用）**：关掉候选几何做 A/B 逐像素 diff（本次 12 个差异块与暗方块 11/11 重合），
比让视觉模型读图可靠得多。

## 11. 镜面高光的奇点（δ 光源 × δ BRDF）—— 通用问题，不是水特有

> 触发（2026-11-17）：查水面为什么不能做平行光高光。结论是**所有**「无限小光源 + 无限光滑表面」
> 都会撞上，与模型无关，只与 `α_eff` 有关。水只是最极端的例子（法线恒定、无 roughness）。

### 11.1 判据：缺的是「带宽」，不是「项」

完美镜面 + 平行光 = 两个 δ 相乘：

```
L_o = [E⊥/Ω_s · δ(ω−ω_s)]  ∗  [F·D(α)/(4 cosθi cosθo)]      α→0
```

两个 δ 卷积仍是 δ ⇒ **点值是无穷大，只有积分（一个像素覆盖的立体角）有限**。
渲染是点采样 ⇒ 拿到 ∞ 或 0，像素中心一动就翻转 ⇒ 闪烁 / 噪点，而不是「没有高光」。

因此 `total_specular` 这项**一直都在**（PR #60 起未改）；不可用的是它的**取值**。

带宽有四个来源，任意一个非零即可采样：

```
α_eff² = roughness² + θ_light² + σ_normal² + σ_pixel²
```

### 11.2 JPOV 当前状态

| 表面 | 各带宽项 | 结果 |
|---|---|---|
| 镜面地板（`metallic=1, r=0.02`） | `roughness`=0.02 足够 | **能算**（那条竖光就是它；月仰角低时纵向拉伸 `1/sin`，见 2026-11-01） |
| 水面（契约 §2.3：纯平面、无 roughness） | 四项全 0（只剩日盘角半径 4.65e-3） | **不可采样** ⇒ 契约写「不做」 |
| 水面 + 波浪 | **逐像素解析法线**（契约 §2.5） | ✅ **已做**：法线逐像素不同 ⇒ 日盘自然碎成 glitter；**不要**再叠解析 `σ_slope`（双计，见 `docs/jpov_specular_bandwidth.md`） |
| 水体介质（内散射） | 不涉及 | `∮p·L dω = p·E`，太阳立体角自动消去（§5.1） |

### 11.3 业界解法（四类，按“谁提供带宽”分）

**① 钳制型号 / 最小 roughness —— 最省，但是妥协**
- Amanatides 1992 最早提出：检测会走样的像素，**钳 Phong 指数**并乘 `max(n)/max(n')` 保住总能量
  （[hilite.pdf](http://www.cs.yorku.ca/~amana/research/hilite.pdf)）。
- Filament：`α = perceptualRoughness²`，并把 perceptualRoughness **clamp 到 0.089**（fp16 的
  `1/r⁴ ≥ 6.1e-5` 下限）；脚注明确写 **Frostbite 把解析光的 roughness 钳到 0.045 专为压高光闪烁**
  （[Filament §4.8](https://google.github.io/filament/main/filament.html)）。
- 反方意见（Nathan Reed）：钳到 0.04 太大，**只要不为 0**，取 1e-3~1e-4 即可；完美镜面应交给
  面光源而不是钳 roughness（[CGSE](https://computergraphics.stackexchange.com/questions/9123/)）。

**② 给光源角尺寸（解析带宽）—— 物理正确，但不自适应**
- 太阳不是点：角半径 0.2665°（直径 0.53°）⇒ `θ_sun² ≈ 2.2e-5`，是 `α_eff²` 的**物理下限**。
- 球光源用「代表点」近似（Karis 2013 / UE4；Lagarde & de Rousiers 2014 Frostbite）。
- 水面/海洋的经典口径与此一致：Cox–Munk 1954 把海面当斜率服从高斯的面元集合，glint 来自
  「倾斜到恰好把太阳反射进视线的那些面元」；太阳角尺寸与波面斜率方差在**方差域相加**
  （[Cox–Munk 参数化](https://coxmunk.readthedocs.io/en/latest)、
  [Ocean Optics Web Book](https://oceanopticsbook.info/view/surfaces/cox-munk-sea-surface-slope-statistics)）。

**③ 几何 SAA（per-pixel 导数 → 抬 α）—— 通用的那条**
- Toksvig 2005 / Hill 2012 / Vlachos 2015：用 `dFdx/dFdy` 估相邻像素半向量差，钳 roughness。
- **Kaplanyan et al. 2016**（HPG, *Filtering Distributions of Normals for Shading Antialiasing*）：
  把像素足迹投影到**斜率域**，直接对 NDF 做卷积。
- **Tokuyoshi & Kaplanyan 2019**（I3D, *Improved Geometric Specular Antialiasing*）：改在
  **投影半向量空间**求导，修正掠射/边缘处的导数误差；已被 Unity 2018.2+、Lumberyard 采用。
  2021 年 JCGT 又出了 projected-space NDF filtering 版本。

**④ 法线贴图滤波（把「看不见的高频」烘进 MIP）**
- LEAN mapping（Olano & Baker 2010）：存斜率一阶/二阶矩，用标准 MIP 线性滤波。
- GGAA（Chermain et al. 2021）：针对 glinty BRDF 的几何高光抗锯齿。

### 11.4 我们该取哪条（判据：是否自适应 / 是否守恒 / 是否损害锐度）

1. **不做通用 roughness 下限**：它同时把反射锐度换成稳定度，而镜面地板/水面最想要的正是锐度。
   只在**数值兜底**意义上保留（1e-3 量级，且只防 `1/α²` 溢出，不指望它抗闪）。
2. **`DirectionalLight` 加 `angular_radius`**（太阳/月亮 0.00465 rad，可覆盖）：物理下限，
   同时是 §10.9「日盘必须是独立光源项」的能量出处（`α² = roughness² + θ²`）。代价小，先做。
3. **水面用波浪的斜率方差做带宽**：`α² = σ_slope² + θ_sun²`；可另给一个**最小斜率方差**
   （≈0.02，语义上是「承认有不可解析的高频波」），而不是最小 roughness。
4. **几何 SAA 暂不做**：等真有法线贴图 / 高频几何再上（那时才有 `σ_normal` 可估）；
   现在没有法线贴图的资产，上了也测不出效果。

### 11.5 判据：什么闪烁该修、什么不该修

- **该修**：闪烁来自「亚像素 δ」——带宽为 0 导致命中/不命中翻转。
- **不该修**：闪烁来自**真实高频**（波面斜率、glint）—— 那是物理现象；1 spp 下它天然抖，
  业界靠 TAA/时间累积解决。**JPOV 每帧从零、要进 gold ⇒ 不可能靠累积**，只能用带宽把它压到
  可接受（这也是为什么 §11.4 第 3 条要保一个最小斜率方差）。

### 11.6 已定方案（下个 PR 修，Danis 2026-11-17 拍）

**① 角度归光源，强度归光照曲线，可见性归几何 —— 三件事不能互相代替**

| 量 | 归属 | 定稿 |
|---|---|---|
| 角半径 `θ` | **光源的几何属性**（常数/逐像素） | 太阳 **0.00465 rad**（0.2665°）、月亮 0.00452；`CHECK_GT(angular_radius, 0)` |
| 强度/色温 | 光照曲线 | 已有 `SunDirectionalIntensity()`（DNI PWL）+ `SunDirectionalColor()`，不动 |
| 可见分数 `v` | **阴影/几何** | PCSS/软阴影给的盘可见面积比 ∈ [0,1]，乘 specular（+diffuse） |

⚠️ **不从 `SkyCommand` 推导/插值 θ**：太阳角径与仰角**无关**（正午、日落一样大；年周期
  日地距离只变 ±1.7%，忽略）。用仰角插值 θ 会把“日落变暗”错实现在“盘子变小”上，
  penumbra 半径与日盘像尺寸一起错。
⚠️ **`θ→0` 不等于全暗，等于不稳定**：能量仍是 `F·E⊥`，只是集中到亚像素 ⇒ 爆/闪。
  全暗只有 `v→0`（盘被遮没）或 DNI→0（强度曲线）两条路。
⚠️ DNI 那条 PWL 本身是**艺术简化**（真实太阳贴地时还亮、只是红且被大气衰减）—— 写在这里，
  以后不要当成物理。

**② 带宽合并口径（必须写对，差一半）**

半向量是光与视线的**角平分线** ⇒ 光偏 `θ` 时 `h` 只偏 **`θ/2`**。JPOV 的 `distributionGGX`
用 `a = roughness²`、`a2 = a²`（= α²），所以直接：

```
a2_eff = a2 + (θ/2)²        // 写 θ² 会过宽 4 倍；写 α+θ 量纲就错
```

反射方向仍张开 `θ`（`r` 相对 `h` 是 2 倍）⇒ 镜面上日盘像大小 = 0.53°，自洽。
⚠️ GGX 的斜率方差是**无穷**（重尾）⇒ “方差相加”是工程近似（Tokuyoshi 2016/2019 就在修这个
  估计误差）；掠射下别指望它完全准。

**③ 关键数量级（改正过一次的错误认识）**

- 720p / 60° 垂直 FOV ⇒ **0.083°/px**；太阳圆盘 0.53° ⇒ **≈ 6.4 px（横向 7.4）** ⇒ **可分辨、稳定**。
- 真正亚像素的是 `r=0.02` 自己的 lobe：α=4e-4 rad ≈ 0.023° ≈ **0.28 px**。
- ⇒ 结论：**亚像素的是“材质太光”，不是“太阳太小”**。加入 θ 后从 0.28 px 变 6 px ⇒
  同时解决「值有限 / 能量对 / 不闪」三件事（11.5 里“水面无波时的日盘”那条按此修正）。
- `r=0.02`（镜面地板）：`α_eff` 4e-4 → **2.36e-3**（5.9×），峰值 **~35×↓**，面积 ×35 ⇒ 通量守恒。
  **不会爆亮**：GGX 的 D 归一化 ⇒ 带宽只能把同一份能量摊开，峰值单调下降。爆亮只发生在 δ 求值。

**④ `roughness = 0` 的真实行为（JPOV 现状，别记错）**

- 现在 **不是爆亮，是静默返回 0**：`a = r² = 0` ⇒ `a2 = 0` ⇒ `D = a2/max(denom,1e-7) = 0`
  ⇒ 平行光在完美镜面上**没有任何高光**（这也是网上“roughness=0 就没高光”的同一口径）。
- 加 θ 后：`a2_eff = (θ/2)² = 5.4e-6` ⇒ `D_peak ≈ 5.9e4`，有限值，日盘像 6 px ⇒ **奇点没了**。

**⑤ 点光源：`physical_radius` 已经存在，但只用了**一半**

- 现在是 Karis 2013 的**代表点**（`accumulateOneLight`）：只用球半径把 `spec_dir` 换到
  “反射方向离球最近的点” —— **只改方向，α 一点没变**。它解决的是“金属面在点光下全黑”，
  不解决带宽：`r=0` 时照样 `D=0`，镜子里看不到灯的圆盘像。
- 要真解决还需三样（下个 PR 一起或分步）：
  ```
  θ_pixel = asin(physical_radius / dist)     // 逐像素；近场可以很大
  a2_eff  = a2 + (θ_pixel/2)²                // 同一条公式
  v       = 盘可见面积分数                    // 同 §11.6① 的 v
  ```
- ⚠️ 太阳的 θ 是**常数**（极远），球光的 θ **逐像素**；近场（灯贴着物体）代表点近似会失效，
  那时需要解析球光 / LTC。这也是“球光在引擎里常被做成单独光源类型”的原因。
- ⚠️ `PointLight::linear_radius` 是**衰减半径**（影响范围），不是发光体尺寸，不能拿它当 θ。

**⑦ 对已有结论的影响（已处置）**

- ✅ **§10.9 / 契约 §2.3 的「平面水面下日盘是 δ 函数 ⇒ 不做平行光高光」已翻案并落地**：有 `θ` 后，
  静水也会出一个 **6 px 的日盘像**。它**属于水皮这一层**（进 WBO 的 `C`），且是**加法**、
  **不吃 SSR 的 `A`**（SSR/探针都不提供日盘）。
- 「波浪」与「θ」不是一回事：`θ` 给**静水单斑**，`σ_slope` 给**有风的 glitter 路**（多个小亮斑）。
  两者互补，不能拿一个当另一个。
- ⚠️ **解析法线 ≠ 法线贴图**（2026-11-18，详见 `docs/jpov_specular_bandwidth.md`）：`σ_slope` 是给「法线只到低频/法线贴图」的方案
  补带宽用的。JPOV 的波浪法线是**逐像素解析梯度**（`normalize(−∂h/∂x,1,−∂h/∂z)`），
  每个像素的反射方向已经不同 ⇒ 日盘像天然被打碎成 glitter。此时再把解析 `σ_slope`
  叠加进 `a2`，等于「法线已知却按未知处理」：既双计又把闪光抹平（实测有风日子盘像直接消失）。
  **结论：有解析法线时，`a2` 只留 `(θ/2)² + 像素足迹`。**
