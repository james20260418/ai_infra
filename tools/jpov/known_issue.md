## 1. 渲染

### 1.1 CSM 阴影贴图过滤是 `GL_LINEAR` —— 与 acne/bias 耦合，暂不动
- **现象**：阴影里暗粒之间沿**光空间 texel 网格**出现「亮缝」（屏幕上随相机旋转）。
- **根因**：阴影贴图是 **RGBA32F 颜色纹理**（`.r` 存线性深度，当年为绕开 llvmpipe 下 depth 纹理采样不可靠）；「无遮挡」texel 存 clear 哨兵 **`1e16`**。过滤误设成 **`GL_LINEAR`**（`EnsureShadowFBO`，MIN+MAG）。PCF 本应按整数 texel 偏移逐 tap 采样，LINEAR 却把每个 tap 变成对 4 texel 的双线性插值 → 沾到 `1e16` 就判受光 → 亮从受光格渗出 ~1 texel。
- **旁证**：引擎其它 depth 纹理（`depth_tex_3d_` / `depth_tex_hdr_` / `scene_depth_tex_hdr_`）都是 `GL_NEAREST`，只有阴影这张是 LINEAR。
- **现状（2026-10-09）**：试改 MIN/MAG → `GL_NEAREST`（本地 commit `f2fb92e`，未 push）→ **Danis 在 sky light viewer 看到人体 body 露出 acne** → 判定「不敢妄动」→ **已回退，main 保持 `GL_LINEAR`**，本地分支已删。
- **🔑 关键认知**：`GL_LINEAR` 一直在**顺手扮演「阴影图模糊」**，把本来就有的 acne 糊掉了；去掉它就露出 acne + bias 不足。**所以「过滤」不是孤立 bug，它和 acne / bias 耦合** —— 要正确解决必须**连同 bias/acne 一起设计**，属单独一件事。
- **可能的修法（下次要动时的骨架）**：① 过滤/哨兵（NEAREST 或**有限哨兵**）；② 同时补 **bias**（自动几何偏置可能对掠射/自遮挡不够 → slope-scale bias / normal offset）。**二者一起调，别单独动。**
- **来源**：`memory/2026-10-09.md`。

### 1.3 远景（解析）雾边界锯齿 —— 像素叠加未考虑抗锯齿
- **现象**：远景解析雾（空气透视 / 仰角雾）在与几何、天空的**渲染边界**处存在**锯齿**。
- **根因（Danis 指）**：**像素叠加未考虑抗锯齿** —— 雾的合成按逐像素**硬边界**处理，没有按**覆盖率（coverage）**做亚像素加权。
- **现状**：未修。
- **可能的修法**：合成时引入覆盖率 / 亚像素权重（或对雾的边界区域做边缘抗锯齿），让雾边界与几何边缘一致。
- **来源**：Danis 2026-10-10 口述。

## 2. 体积雾 / Fire-Fog

### 2.1 froxel 雾：16px 方格感 + z 分层带，双线性无法消除
- **现象**：`Nz=256 / tile=16`（定稿默认）下仍有**方格感**与 **z 向分层带（颗粒）**；`k=1 vs k=2`（超屏）方格感减半但「量化剪影」仍在。
- **根因**：双线性重建**无法超过网格分辨率**；k 只是空间加密，不解决量化剪影且代价 ×k²。
- **现状**：MVP 用**串行前缀** scatter；设计里的**金字塔 `L1→L4` + base-4 `O(log Nz)`** 有序前缀**未做**；16px 方格感的弥补手段（见设计 §10）也**未做**：
  ① depth-aware 双边上采样（救边，不增 XY）
  ② 半分辨率 / hero-beam
- **其它未决**：gold test 分支已 push 但**未开 PR / 未跑 CI**（等 gold 定稿）；Danis 说的 **"1.5m" 含义不明**（相机距离？离地高度？）。
- **来源**：`memory/2026-10-09.md`；设计 `docs/jpov_froxel_design.md`、`docs/jpov_tpz_volumetric_fog_design.md`。

### 2.2 Fire-Fog 试验分支结论：纯参考，不合入
- **内容**：点状雾 + 低分辨率 ZDist + 屏幕空间高斯 + 太阳 CSM god ray（PR #158，draft「参考·勿合入」）。
- **结论（Danis）**：**算法试验到此为止、纯参考**，不合入。噪声 ∝ 1/√M ⇒ 正解是**源头加样本**，屏幕高斯是事后补救、必糊 ray。
- **来源**：`memory/2026-10-09.md`。

## 3. 蒙皮 / 重定向

### 3.1 重定向（root-motion 尺度自适应）的已知残余
- **⚠️ 先澄清（别误读）**：重定向**已经处理** root offset ——
  `root_offset_t = Q_body · root_offset_s · (leg_t / leg_s)`，即 **朝向归一（`Q_body`）+ 尺度归一（腿长比）**，
  **2026-09-20 已落地**。骨长走目标 `SkeletonType` 自身长度；旋转经 rest 基准共轭 **100% 保留**（逐骨世界偏差精确一致）。
  **以上都不是残余。**
- **真正的已知残余**（`docs/jpov_root_offset_design.md` §4）：
  1. **标量腿长比是粗略近似** —— 更准应按「链长比」（根→脚 的骨长和之比）；步幅、接触点仍受影响。
  2. **接触密集动作需额外 IK 修正** —— scale adaptation 只对**模糊动作**（跑步/走路）够用，精确踩点（含**脚滑/悬空**）需 IK。
  3. **水平位移未做裁剪/居中** —— 大幅位移（跑步）角色会跑出画面（**预期行为**）。
  4. **沿链 `rest_offset` 差 → 微小脚入地/出地** —— 不处理（Danis 明确接受）。
- **来源**：`docs/jpov_root_offset_design.md` §4、`docs/jpov_retarget_design.md` §6.2/§6.3。

## 6. 测试 / 环境（不是引擎 bug，但会干扰开发）

### 6.1 JPOV 同进程二次 `Init()` 假失败
- **现象**：本机**无长驻 Xvfb** 时，`Finalize` 会杀掉自建 Xvfb 但**没 unset `DISPLAY`** → 同进程再次 `Init()` 假失败。
- **解法**：先起长驻 `Xvfb :99` + `DISPLAY=:99`。
- **来源**：`memory/2026-10-07.md`。

### 6.2 `Xvfb :99` 争用
- **现象**：自建 Xvfb 与测试内嵌 Xvfb 抢 `:99` → 大批 gold test **假 FAIL**（primitives2d / bone_mesh / pliers / text3d_depth_alpha）。
- **解法**：`pkill Xvfb :99` 释放，或起长驻 `Xvfb :99` + `--test_env=DISPLAY=:99`。⚠️ `pkill -f "Xvfb :99"` 会**自匹配到自己的命令行**，小心。
- **附**：多个 session 并发跑测试（不同 `ai_infra_*`）各自 bazel `output_base` 隔离、互不影响编译，但**都抢 :99**。
- **来源**：`memory/2026-10-09.md`。
