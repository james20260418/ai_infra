# JPOV 全局水面（水 / 海）· 设计

> 状态：**W1 已实现**（2026-10-27）。作者：James / Danis。
> 范围：一片**全局水平面**（y-up，世界 `y = level`）的渲染，含"水下遮蔽感"。
> 本版**不含**：折射、太阳闪烁、Gerstner 水平挤压、泡沫、水下粒子保活。
> 代码：`interface/water_types.h`（参数）、`src/water/`（渲染）、`src/renderer.cc`（pass 编排）。

---

## 0. TL;DR

水在渲染上不是"一个物体"，而是 **一个界面 + 一段介质**：

```
界面：菲涅尔反射（本版只有天光 cubemap 探针）+ 透射
介质：看下去时，水下那段视线逐通道 Beer-Lambert 吸收 + 散射  ← 这就是"水下遮蔽感"
```

于是它拆成两个 pass：

| pass | 什么时候跑 | 做什么 |
|---|---|---|
| `DrawSurface` | 有 `cmds.water` | **全屏三角形 + 每像素射线求交**：反射 + 吸收背景色；写 color + **MRT#1 场景深度** + 硬件深度 |
| `DrawUnderwaterMedium` | 相机在水面之下 | 整屏介质：整条视线上的吸收/散射 |

---

## 1. 链路位置（以及为什么只能在这儿）

```
shadow → sky(+env cube) → 不透明 3D
        → 【水面 pass】                     ← 这里
        → 粒子 → 体积火 → 条带             ← 三个 WBO pass
        → 【水下整屏介质（仅相机在水下）】
        → 远景雾 → froxel 雾 → highlight → bloom → tone map → SMAA → 2D
```

**水面必须在三个 WBO pass 之前**，理由是硬的：

- 不能更早：要吸收"水面之下的内容"，那些内容必须已经画完；
- 不能更晚：粒子 / 体积火 / 条带都靠 **MRT#1 做手动作深度测试**（WBO 目标没有深度缓冲），
  水面必须先把自己的深度写进去，它们才知道被水挡住。

**已知取舍**（Danis 2026-10-27 定）：因为水面在它们之前，**水下那些粒子/火/条带会被
水面深度剔掉**。要保住它们就得把水面挪到透明 pass 之后，那会反过来让"水面之上的效果"
被水吃掉、且吸收长度算不准（grab 里没有效果的深度）。本版取前者。

### 为什么**不**把水放进 WBO

| WBO 的能力 | 水的需求 |
|---|---|
| 同 pass 内**乱序**累积一堆碎片 → 一次解析成 `(预乘色, 透射率)` | 水是**单层平面**，没有排序问题 |
| 只保存一个**加权代表深度** `Σz·α·w/Σαw` | 水要对**背景**做逐通道吸收（需要背景的真实深度与颜色） |
| 只能"叠在已成画面上" | 水要**改写背景**（吸收；将来还有折射的 UV 偏移） |

一句话：WBO 解决"一堆碎片谁挡谁"，水解决"一个界面如何改写它背后的世界" —— 不是同一个问题。

## 2. 光栅化：全屏 + 解析平面（本版不做巨浪）

水面在数学上就是 `y = level`：**命中点是解析解，几何一点用都没有**。所以本版：

```
全屏三角形（3 顶点，gl_VertexID）→ 片元里逐像素：
  ndc  = gl_FragCoord.xy / uResolution * 2 - 1
  rd   = normalize(far_pt(ndc) - near_pt(ndc))          // 由 invVP 反投影
  t    = (level - camPos.y) / rd.y;  rd.y≈0 或 t<=0 → discard
  t    = min(t, max_distance)                            // 贴地平线的射线 t→∞，夹住
  P    = camPos + rd * t                                  // 命中点
  gl_FragDepth = ndcZ(P)                                  // 硬件深度
  FragSceneDepth = 同一个值                                // MRT#1 契约
  远端 25% 距离淡出到「地平线天光色」                        // 海天相接无硬缝
```

**为什么不用任何网格/quad**（都是"边界"带来的伪影，跟水面本身无关）：

| 做法 | 问题 |
|---|---|
| 单个大 quad | 远平面切一个平面 ⇒ 屏幕上是**曲线**边界；quad 直边在屏幕上仍是直线；超大三角形在 llvmpipe 上 varying 插值会退化（本项目已踩过，天空/雾都是因此改全屏 + 反投影） |
| 均匀细分网格 | 远处不够密 / 顶点爆炸；细分只为位移存在，没有位移时全是浪费 |
| 极坐标 LOD 网格（曾用于巨浪验证） | 中心洞、环间距、远场折角、外缘与真地平线之间的带 —— 全部随之消失 |

**代价**：写 `gl_FragDepth` ⇒ 这一趟 early-Z 失效。但它是独立 pass，本来就要为每个水面像素跑完整 FS，实际损失可忽略。

### 巨浪是可插拔的

将来要巨浪时，**只换「命中点 + 法线」这一段**（换成网格光栅化，或对高度场做 2~3 步牛顿迭代），
菲涅耳 / 吸收 / 深度写入 / 介质 pass 全部复用。见 `src/water/water_shader.h` 顶部「可插拔点」。
本版接口**不留** wave_* 参数（没有几何的位移参数是死 API）。

## 3. 水面片元（从水上往下看）

```
L      = 场景距离 − 水面距离              // 水下那段视线的长度（米）
T      = exp(−σ·L)                        // 逐通道吸收，σ 单位 1/m
under  = bg·T + scatter·(1−T)             // 吸收 + 单次散射（= 水下遮蔽感）
F      = F0 + (1−F0)(1−cosθ)^5            // Schlick，F0 = 0.02（IOR 1.333）
out    = under·(1−F) + sky(R)·F           // R = reflect(−V, N)
```

关键实现约束：**输入必须是抓帧副本**。水面写的正是 HDR FBO 本身（color + MRT#1），
采样自己的附件是 GL 未定义行为 ⇒ 每帧先 `glBlitFramebuffer` 两份（RGBA16F 颜色 + R32F 深度）
到 `WaterRenderer` 私有的抓帧 FBO。这一份副本将来加折射时直接复用（折射只是换个采样 uv）。

输出**关混合直接写**：因为背景色已经被逐通道吸收进 `under` 了，用 alpha blend 表达不了逐通道透射率。

## 4. 相机在水下

**画面亮度几乎全由「水面这一层的透射率」决定**（水雾只是加一层薄底噪）——
所以这一层的角度依赖就是全部观感。三个必须分清的量：

1. **理想平面界面**：`sinθt = 1.333·sinθi`，`>1` 没有折射解 ⇒ 全内反射（R=1）。
   这是**物理硬边**（临界角 48.6°，R 在 0.5° 内从 1 掉到 0.4）。
2. **真实水面不平**：界面法线有一组**斜率分布**，临界角被这个分布卷积开 ⇒
   过渡宽度 = 水面 RMS 斜率，不是艺术糊边。接口参数 `surface_slope_rms_deg`
   （0 = 理想镜面/可用于对照；6 ≈ 微风，默认；12 ≈ 有浪）。
   实现：`t = smoothstep(cosθc − 0.75σ, cosθc + 0.75σ, cosθ)`，`σ` 为弧度。
3. **窗外不是黑的**：进入水下的天光会在水体里**再散射一次**，所以 TIR 区是
   "被雾填亮的水"，不是虚空。⚠️ 散射是**宽带**的：水下的青蓝来自**吸收吃掉红光**，
   不是散射色偏青 —— 把散射色写成深青等于把颜色算两遍（旧默认就是这样，结果是窗外全黑）。

另外：该分支**不做**吸收 —— 整屏介质 pass 会统一做，否则双重衰减。

整屏介质：`c·T + scatter·(1−T)`，`T = exp(−σ·距离)`，距离由 MRT 深度反投影得到。
放在**所有 3D 内容之后**：水下时粒子/火/条带也在水里，它们也要被吸收；
水面自己（从水下看）同样要被吸收（= 隔着水看水面）。

## 5. 数据流 / 资源

| 资源 | 生命周期 | 说明 |
|---|---|---|
| 水面网格 VBO/EBO/VAO | `Init` 建一次 | 索引固定，顶点数不随窗口变 |
| 抓帧 FBO（RGBA16F + R32F） | 随 3D FBO 尺寸重建 | 每次水面/介质 pass 前 blit 一次 |
| 天光 cubemap | 复用 `env specular` 那张 128² | 水面自己消费；即使没开 `env_specular` 也要建 |

`Renderer::Render` 里新增的守卫：

- `has_3d` 计入 `cmds.water`（否则"只有天空 + 水"的帧整块跳过 3D）；
- `CHECK(water → sky)`：反射源就是天光，没天空宁可 crash 也不静默退化成黑镜子；
- `CHECK(water → tone_mapping)`：在线性 HDR 域合成，且依赖 MRT 场景深度。

## 6. 已知限制（v1 的账）

1. **水下粒子/火/条带会被水面深度剔掉**（见 §1 的取舍）。
2. **没有折射**：水面之下不位移（"水下的东西位置是准的，只是被吸收染色"）。
3. **没有太阳闪烁**：天光探针按设计**不含日月盘**（`SkyOutput::kEnvProbe`），所以水面
   永远不会出现太阳高光 —— 这也是"远看像一块哑光板"的主因。加太阳 GGX 高光是下一刀。
4. **波浪只有竖直位移**：没有 Gerstner 的水平挤压 ⇒ 浪尖不"卷"；也没有泡沫/白冠。
5. **地平线是硬直线**：水面网格铺到 900 m，外圈与真地平线之间那条 1~2 px 的地带是天空的
   地色。远景雾开着时能被吃掉，关着时可见（与"海天相接"的观感还有距离）。
6. **没有涟漪/焦散/悬浮颗粒**：法线恒为 `(0,1,0)`，所以水面是一个完美平面 ——
   水下仰望时窗口边缘是"斜率分布卷积"的平滑过渡，而不是被真实涟漪揉碎的样子。
   这三样是"像水下"的最后一段路。
6. **一次只能一片水**（全局单例，`DrawWater` 是覆盖语义）。

## 7. 下一步（按优先级）

1. **太阳 GGX 高光**（水面观感 80% 来自它；有了它法线微扰才有意义）；
2. **折射**：抓帧副本已经有了，只差"按法线偏移采样 uv + 越界/深度拒绝"；
3. **Gerstner 水平挤压** + 细节法线贴图（浪尖形状与微波纹）；
4. **保活水下粒子**：给三个 WBO pass 加"最近层深度"（WBO 的 `att3` 槽终于有用途），
   水面据此拒绝覆盖更近的效果、并按效果自己的 z 算吸收；
5. 泡沫 / 白冠（按浪高与斜率阈值）；
6. 水下相机时的"水面上表面"更精确的全内反射（目前是近似）。

## 8. 验收工件

`jpov_skylight_viewer --capture-water <dir>`（headless，固定机位）：

| 图 | 看什么 |
|---|---|
| `water_off` / `water_on` | 同一机位开关水面：水面确实在改写画面（也是"不设 water 就零开销"的对照） |
| `water_level_{10,20,30,45,default}` | 水位上下扫：水线在 box 上的位置与水下褪色强度跟着变 |
| `water_camera_under` | 相机在水下：整屏青绿 + 距离衰减 |
| `water_camera_under_lookup` | 水下抬头：水面 = 全内反射 + Snell 窗 |
| `water_camera_under_lookup_flat` | 把水面 RMS 斜率设 0（理想镜面）：对照出"过渡宽度"来自界面粗糙度，不是调参 |

交互面板（skylight viewer）：场景切成"水面打底"，滑条 = 水位 / 波浪幅度 / 天光反射量 /
吸收 σ(RGB) / 散射强度。
