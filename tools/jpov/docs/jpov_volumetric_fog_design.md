# JPOV 局部体积雾（Local Volumetric Fog）— 设计文档

> 日期：2026-09-29
> 状态：设计敲定，待实现（MVP = 球形雾 + 圆柱雾，闭式积分）
> 范围：新增一条**并列于后处理的局部体积雾通道**。MVP 支持球（sphere）与圆柱（cylinder）
> 两种雾体，**每个形状一次 instanced draw**，**闭式积分**，加法累加 + 末尾全屏合成。
> 本 PR 只合入本文档，不含实现代码。

---

## 0. TL;DR（给急读的 agent）

- **局部体积雾 = 用户像摆点光源一样在场景里摆「雾体」**（球形 / 圆柱）。每个雾体自带位置、尺寸、颜色、强度。
- **渲染 = 每个形状一次 instanced draw**（1000 个球雾 = **1 个 drawcall**），把每个像素的
  **消光 τ** 与**内散射 S** **加法累加**进两张缓冲；末尾**一次全屏合成**：
  `L = L_scene · exp(−τ_total) + S_total`，**在 HDR、tone map 之前**。
- **闭式积分**：密度剖面限制为「**距离平方的多项式**」，沿视线弦有解析解 ⇒ **零采样、零噪声、确定、可单测**。
- 用户只能配 **颜色 / 尺寸 / 强度**；衰减剖面是 **JPOV 锁定的菜单**（`kDome` / `kSharp` 等）。
- **MVP 明确不做**：froxel、SDF 沿弦采样、硬边密度、世界 3D 栅格当渲染载体、逐像素 index list、排序。

## 1. 背景与目标

### 1.1 需求（Danis，2026-09-29）

要一个「像点光源一样管理」的**局部体积雾**，用于：

- **工地 / 房间的烟尘弥漫**（若干浓淡不同的雾团）；
- **发光体周围的空气光**（光剑、篝火、灯笼——用发光体颜色驱动雾的内散射）；
- 一般性的局部雾团 / 蒸腾 / 扬尘。

核心诉求：「**给至多 1000 个雾体，像点光源那样摆放，一次画完**」。

### 1.2 为什么是「闭式」而不是「射线步进」

体积雾有两条主流实现路线：

| 路线 | 做法 | 代价 |
|---|---|---|
| **射线步进 / SDF 采样** | 沿弦取 N 个样本累加密度 | 采样误差、噪声、**窄特征欠采样→闪烁**、结果依赖采样数 |
| **闭式积分（本文选）** | 密度剖面选「距离平方的多项式」→ 沿弦有解析积分 | 剖面受限于多项式；换来零采样、零噪声、确定、可单测 |

选**闭式**的理由：雾体数量多、要确定、要好测（符合 JPOV「每步可独立自证」的架构口味），
而闭式恰好**没有采样噪声**，gold 图能逐像素锁死。代价（剖面受限）由 §6 的锁定菜单兜住。

### 1.3 与「粒子特效 pass」的关系（重要，别混）

本设计与已合入的 **[docs/jpov_effect_pass_design.md](jpov_effect_pass_design.md)**（粒子/火焰 MVP）**不是同一条通道**：

| | 粒子特效 pass（已有设计） | 局部体积雾（本文） |
|---|---|---|
| 载体 | 3D 场景里的**面片 / billboard** | **屏幕空间累加缓冲**（τ / S） |
| 深度 | 测深度、不写 | **不测不写**（穿透几何累加，靠深度裁剪求范围） |
| 混合 | additive / alpha 分批 | **一律 additive**（写进专用缓冲，不直接写画面） |
| 形状 | 逐条命令，每颗粒子一次 draw | **instanced，每形状一次 draw** |
| 术语 | 效果 = 「数据参数组合」 | 雾体 = 「点光源式的小对象」 |

两者**同属 effect 家族、都自包含子目录**（§10 的组织哲学一致），但**渲染姿态完全不同**，
因此各自独立，**不共用 shader**（延续 effect 文档的「照抄式复用」策略）。

## 2. 范围与非目标

### 2.1 范围（MVP）

- 形状：**球形雾（sphere fog）**、**圆柱雾（cylinder fog）**。
- 密度剖面：**JPOV 锁定的闭式菜单**（§6）。
- 渲染：每形状**一次 instanced draw**；加法累加到 τ / S 两张缓冲；一次全屏合成。
- 用户可配：**颜色、尺寸、强度**（§4）。
- 平台：OpenGL **3.3 core**（无 compute shader，见 §3.3）。

### 2.2 非目标（明确不做，附原因）

| 不做 | 原因 |
|---|---|
| ❌ **froxel 体积雾** | GL 3.3 无 compute；且 froxel 是为「全局大气散射」设计的整屏 3D 网格，画局部几团属杀鸡用牛刀 |
| ❌ **SDF 沿弦采样 / 步进** | 引入噪声与「窄特征欠采样→闪烁」；闭式在球/柱上零误差且更省（§6） |
| ❌ **硬边密度（uniform 球）** | 观感穿帮（硬圆盘）+ 无软抗锯齿；菜单只给软剖面。**硬边只在圆柱轴向允许**（端面常被遮/贴结构） |
| ❌ **世界空间 3D 栅格当渲染载体** | 采样分布不对（远处浪费、近处过粗）；**密度源**可以世界空间，但**渲染载体**是屏幕空间累加 |
| ❌ **逐像素 index list / 每像素 8 槽** | 多余中间结构；加法混合天然完成 broad-phase（§3.2） |
| ❌ **排序** | τ 可加、S 一阶可加 ⇒ **顺序无关**（§8.3）；排序纯属浪费 |
| ❌ **全局高度雾** | 那是另一条解析雾（远霾 / 贴地雾），可后续与本 pass 叠加，不在本 MVP |

## 3. 渲染架构

### 3.1 三段式

```
命令层（RenderCommandList）
   │  按点光源的方式携带 std::vector<FogSphere> / std::vector<FogCylinder>
   ▼
累加 pass（每形状一次 instanced draw）
   │  清空 τ / S；加性写两张缓冲；关深度测、关深度写
   ▼
合成 pass（一次全屏三角形）
   │  L = L_scene · exp(−τ) + S        （HDR 域）
   ▼
（既有）highlight → bloom → tone map → sRGB → 2D UI
```

### 3.2 为什么是「instanced 累加」而不是「index list + 逐像素遍历」

上一版讨论里曾设想「把雾体 index 渲到像素上（每像素最多 8 个）→ 后处理逐像素遍历」。
本设计**不采用**，因为：

1. **加法混合天然替你做 broad-phase**：每个雾体渲染它的**屏幕包围几何**，GPU 光栅化只会
   给「被它覆盖的像素」跑 shader。**没有上限、没有溢出、没有 index 存储、无需排序。**
2. **GL 3.3 没有原子 / SSBO / 链表**，「每像素 8 槽」只能靠多趟 stencil 硬凑，成本高、
   而且丢掉的是「最近 8 个」而非「贡献最大 8 个」。
3. **消光 τ 顺序无关**（§8.3），所以逐像素遍历根本不需要——直接加就行。

conclusion：**每形状一次 instanced draw + 加法累加** = 最省、最简、最可测。

### 3.3 GL 3.3 约束

- **无 compute**：本方案不依赖 compute（球/柱求交在 fragment shader 内解析完成）。
- **MRT 只能同一个 `glBlendFunc`**（逐附件 blend 的 `glBlendFunci` 是 GL 4.0 / `ARB_draw_buffers_blend`）：
  正好 τ 与 S **两路都加法** → 一个 `glBlendFunc(GL_ONE, GL_ONE)` 同时满足，无冲突。

## 4. 数据模型与公共接口

### 4.1 用户可配（仅三项 + 摆放）

用户说的是**场景语言**，不是实现语言：

```cpp
// 球形体积雾（点状雾）
struct FogSphere {
    Vec3    center;     // 摆放位置（世界坐标）
    float   radius;     // 尺寸
    Color   color;      // 颜色（介质色 / 内散射色）
    float   intensity;  // 强度（HDR，可 > 1）
};

// 圆柱体积雾
struct FogCylinder {
    Vec3    base;       // 底面圆心（世界坐标）
    Vec3    axis;       // 轴向（单位向量，约定 +Y 为「向上」）
    float   radius;     // 半径
    float   height;     // 高度
    Color   color;      // 颜色
    float   intensity;  // 强度
};
```

### 4.2 JPOV 锁定、用户**不**可配

| 字段 | 说明 |
|---|---|
| `profile` | 衰减剖面，取 §6 锁定菜单（MVP 固定 `kDome`，是否开放选择见 §14） |
| 相位各向异性 `g` | MVP 固定 `0`（各向同性，雾/烟的正确默认） |
| 深度策略 / 混合 | 全局统一（§3、§8），不给用户 |

> **设计原则**：用户配「颜色 / 尺寸 / 强度」这三项**直观量**；一切**观感风险量**
>（剖面硬度、采样、排序）由 JPOV 锁定，避免用户凑出「隐形闪烁」这类失败模式（§6.4）。

### 4.3 命令层

沿用 effect 文档的分层：**命令层无状态快照，不含业务名、不外泄 GL**。

```cpp
// render_command.h（新增，与 point_lights 并列）
std::vector<FogSphere>   fog_spheres;
std::vector<FogCylinder> fog_cylinders;
```

雾体的**状态**（生命周期、飘动动画、发射器）**不在命令里**，住在用户侧（同 effect 文档 §六）。

## 5. 几何：屏幕包围体扩张（顶点着色器）

每个雾体在 VS 里**扩张成一个覆盖它屏幕投影的四边形**（instanced：一份 VAO + N 份 per-instance 数据）。

- **球**：投影球心 + 半径 → 屏幕包围四边形（注意近平面裁剪 / 相机内的情况）。
- **圆柱**：投影其**包围盒** 8 角点取屏幕 AABB（**over-estimate 无害**，只多跑几行空 fragment）。

fragment 收到该像素的**视线** `(o, d)`（由 `gl_FragCoord` + 逆 VP 重建）后，在 shader 内
做**精确**的形状求交（§7）——所以**包围几何只负责「哪些像素要跑」，不负责形状精度**。

> 为什么不在 CPU 侧做屏幕分块（tiled light list）？MVP 用「包围几何自然裁剪」已足够，
> 且更简单、更精确（无 tile 边界 overdraw）。tiled 留作后路优化（§14）。

## 6. 密度剖面：闭式菜单（JPOV 锁定）

### 6.1 保闭式的唯一窍门：用「距离平方」的多项式

沿视线 `p(t) = o + t·d`，**任何点到中心的距离平方 `|p−c|²` 都是 t 的二次多项式**（无 sqrt）。
所以只要剖面写成 `f(距离²)`、且 `f` 是多项式，被积函数就是 t 的多项式 → **闭式积分**。

> **规则**：剖面用 **`u²`（距离平方归一化）** 写 ⇒ 保闭式；用 **`u` 或 `smoothstep`** 写 ⇒ 丢闭式。
> `smoothstep` 观感最漂亮但**无闭式**，故菜单**不提供**。

### 6.2 球形雾剖面

`u = d/r`（`d` = 到球心距离），弦 `[t0,t1]` 由球求交给出，`L = sqrt(r² − h²)`（半弦长，`h` = 视线到球心的垂距）：

| 剖面 | 形状 | `τ` |
|---|---|---|
| `kDome`：`1 − u²` | 中心最浓、到表面平滑归零的抛物面 | `σ₀ · (4/3) · L³ / r²` |
| `kSharp`：`(1 − u²)²` | 更「芯化」，边缘更快淡出 | `σ₀ · (16/15) · L⁵ / r⁴` |

**深度裁剪仍闭式**（§7.3），用**不定积分**在任意端点求值，不必假设对称弦：

```
kDome  :  F(t) = σ₀ · [ (1 − h²/r²)·t − (t − t_c)³ / (3r²) ]      t_c = 球心在视线上的参数（垂足）
kSharp :  F(t) = σ₀ · [ β²·u − (2/3)βa·u³ + (1/5)a²·u⁵ ]          u = t − t_c, a = 1/r², β = 1 − a·h²
τ([a,b]) = F(b) − F(a)
```

### 6.3 圆柱雾剖面（径向 × 轴向，分离式）

圆柱是**分离式**：`σ = σ₀ · f_r(ρ²/R²) · f_y(y)`（`ρ` = 到轴的横距，`y` = 轴向坐标，局部系）。

**径向 `f_r`**（同球的软边逻辑，`u_r = ρ/R`）：

| 剖面 | `f_r` |
|---|---|
| `kDome` | `1 − u_r²` |
| `kSharp` | `(1 − u_r²)²` |

**轴向 `f_y`**（`u_y = |y|/h`）：

| 剖面 | `f_y` | 次数 / 分段 | 观感 |
|---|---|---|---|
| `kUniform` | `1` | — 最简 | **硬端**（端面可见，仅贴结构 / 被遮时用） |
| `kDome` | `1 − u_y²` | 整段 4 次、**无分段** | 对称软端（中间最浓、两端平滑归零）→ **默认** |
| `kCoreRamp` | `1`（`u_y ≤ c`）+ 平滑降到 0 | **分段**（按 `|y|=c·h` 切 ≤2 刀） | 「柱身均匀 + 两端软」——最像真柱 |

**积分域（三步，清晰）**：

1. **径向支撑**：`ρ²(t) ≤ R²` → 一个区间 `[t_a, t_b]`（`ρ²(t)` 是开口向上的二次，只有一个谷）。
2. **轴向支撑**：`|y(t)| ≤ h` → 一个区间 `[t_{y0}, t_{y1}]`。
3. **交 + 深度裁剪**：`[T0,T1] = [max(t_a, t_{y0}, 0), min(t_b, t_{y1}, t_depth)]`。
4.（仅 `kCoreRamp`）在 `[T0,T1]` 内再按 `|y| = c·h` 切开。

> **支撑边界正好是剖面归零处** ⇒ 进出边界连续，不跳。

### 6.4 为什么锁定菜单、不给用户自由剖面

- **自由度越高，越容易凑出「高频窄特征」**（如「`r=3` 附近很浓」的环）。这类特征会让
  **采样器**欠采样→闪烁；即便闭式，也会让菜单外数学失守。
- 菜单**按定义保证**：软、单调/带限、闭式 ⇒ **堵死「隐形闪烁」这种失败模式**。
- 这是 minimal-surprise：**界面合法 = 结果可靠**；用户无法从合法输入造出「看着对、随机闪」的雾。

### 6.5 角上双零（观感说明）

圆柱用**分离式乘积**，角上（`ρ→R` 且 `|y|→h`）密度**双零** ⇒ 棱角被「削圆」。
这**通常更好看**（无硬棱）。要**锐角**就得上「到柱面距离场」，而距离场含 sqrt ⇒ **非闭式**。
**要闭式就必须接受圆润的角**——这是等价交换，不是 bug。

## 7. 逐像素积分（fragment shader）

### 7.1 视线与求交

- 由片元重建世界（或视图）空间视线 `(o, d)`。
- **球**：解 `|o + t·d − c|² = r²` → `disc = b² − cc`（`b = (o−c)·d`，`cc = |o−c|² − r²`）；
  `disc ≤ 0` 早退；否则 `L = sqrt(disc)`，弦 `[−b−L, −b+L]`。**每像素 ~15 flops + 1 sqrt。**
- **圆柱**：局部系下横截面解二次（无限柱）+ 端盖裁 `y` 区间；`dir` 分量接近 0 时走退化分支。

### 7.2 内散射与光照（`L_in` 在**顶点着色器**里每实例算一次）

**关键优化**：`L_in`（雾被照亮的结果）**每实例算一次**，别在 fragment 里算——
在 **VS 里**对每个雾体算一次（每实例只跑 4 次顶点）：

```
L_in = sun_color · shadow(center) · HG(cosθ_sun)
     + ambient_color
     + Σ_point_lights  atten(center) · light_color · HG(cosθ_l)
```

- `shadow(...)`：复用现有 **shadow map**（被山/墙挡住的雾不发亮 → 自然出**光柱**）。
- `HG`：Henyey-Greenstein 相位函数；MVP `g = 0` ⇒ 各向同性（常数）。
- **发光体（光剑/篝火）**：把 `L_in` 换成该发光体自身的颜色（按其亮度衰减），
  即「用发光体当这团雾的光源」，而非太阳。

于是**每像素只剩「求交 + 一次 exp」**，逐像素成本轻到可忽略（对比：若在 fragment 里采阴影，
重叠区会被打爆）。

### 7.3 闭式 τ 与深度裁剪

```
τ_i   = F_i(min(t1, t_depth)) − F_i(t0)      # F 见 §6.2 / §6.3，端点任意 ⇒ 裁剪仍闭式
T_i   = exp(−τ_i)
S_i   = L_in,i · (1 − T_i)
```

- **深度裁剪**：把弦末端 clamp 到场景深度（读现有 `depth_tex_hdr_`）。全在墙后的雾 `τ≈0` 自动消失。
- 读数端：**不测深度、不写深度**（穿透几何累加）。

### 7.4 累加写回（MRT + 加法）

```
fog_extinction (R32F)     += τ_i
fog_scattering (RGBA16F)  += S_i        # 逐通道
```

`glBlendFunc(GL_ONE, GL_ONE)`，`glDisable(GL_DEPTH_TEST)`，`glDepthMask(GL_FALSE)`。

## 8. 合成与顺序无关性

### 8.1 合成 pass

一次全屏三角形（复用现有全屏 VS 模式）：

```
T_total = exp(−fog_extinction)            # 注意：τ 已累加，只 exp 一次
L       = L_scene · T_total + fog_scattering
```

写回 **HDR 域**（tone map **之前**）——内散射是「光」，必须在线性 HDR 里加，才被 ACES 正确压、
才会被 bloom 吃掉光晕。亮度对齐现有 `LIGHT_INTENSITY.md` 锚点。

### 8.2 与现有链路的位置

| 顺序 | pass | 说明 |
|---|---|---|
| ① | 3D 不透明（sky → Object3D → SkinnedMesh → 图元 → 文字 3D） | 测+写深度 |
| ② | **体积雾（本 pass：累加 + 合成）** | 不测不写；读 `depth_tex_hdr_` |
| ③ | highlight pass（现有） | |
| ④ | bloom（现有） | 光柱 / 烟晕被 bloom 打光 |
| ⑤ | tone map + sRGB（现有） | |
| ⑥ | 2D UI（现有，永远最上层） | |

> **②在 ①之后**：靠 `depth_tex_hdr_` 正确遮挡（而非共享 draw）。
> **②在 tone map 之前**：HDR 亮雾被 ACES 正确压、被 bloom 吃掉。

### 8.3 顺序无关性（为什么不用排序）

- **总消光可加、顺序无关**：`∏exp(−τ_i) = exp(−Στ_i)`。累加 τ 后 **只 exp 一次**即等价。
- **内散射一阶可加**：`S_i = L_in,i·(1−T_i)`，稀薄时 `Σ S_i` 即正确；
  浓雾重叠会略偏亮（一阶近似），对烟尘场景可接受。

⇒ **所有雾体无需排序**（对比 alpha 粒子必须从远到近排）。这与 §3.2「加法混合免 broad-phase」互为表里。

## 9. 确定性与可测性（JPOV 的命门）

### 9.1 浮点加法非结合

- 加法混合的**累加顺序**影响最后几位。好在 **llvmpipe（软件光栅）图元顺序确定**，
  单次 instanced draw 内 instance 顺序也确定 ⇒ **gold 图仍逐字节可复现**。
- **记一笔**：这条依赖光栅化顺序，上真 GPU / 换后端要留意。真需跨平台严格一致，
  就得牺牲「无排序」——**不值，先不碰**。

### 9.2 对比：闭式 vs 采样

闭式**无随机、无采样** ⇒ 天然确定；这正是选它而非 SDF 采样的重要原因之一（§1.2）。

### 9.3 可单测

- **闭式积分核**（§6 的 `F`、`τ`）是**纯 CPU、GL-free** 的数学，可独立单测（含向量 fuzz）。
- 与「采样参考实现」对拍：球 dome 的 `τ = σ₀·(4/3)L³/r²` 可用数值积分高精度对拍（§13）。

**词汇对照（本文修正 Danis 初稿用词）**：

| 初稿 | 定稿 | 理由 |
|---|---|---|
| `ball_fog` | **`sphere_fog`** | 图形学术语用 **sphere**（ball 非术语）；球体 = sphere |
| `effect/`（作父目录） | **`volumetric_fog/`** | 本技术经典名为 **local volumetric fog / fog volumes**；虽与粒子同属 effect 家族，但渲染姿态完全不同（§1.3），用专门父目录更清晰 |

## 11. 渲染挂载点

见 §8.2 的表。要点复述：

- **在 HDR 之后、tone map 之前**（内散射是光）。
- **不测深度、不写深度、加法混合**（穿透几何累加，范围靠深度裁剪）。
- 合成吃 `depth_tex_hdr_` + HDR 颜色纹理，输出写回 HDR 颜色纹理。
- 与 bloom 的关系：**雾在 bloom 之前**，让光柱/烟晕被 bloom 打光。

## 13. 验收 / gold 自证计划

| 用例 | 验证什么 | 方式 |
|---|---|---|
| **单球 dome 闭式对拍** | `τ = σ₀·(4/3)L³/r²` 正确 | 纯 CPU 单元测试：与高精度数值积分对拍（相对误差 < 1e-4） |
| **单球渲染 + 解析参考** | fragment 端求交/积分正确 | 固定相机 + 平地，出 gold 图；与 CPU 参考实现逐像素比对 |
| **双球重叠 = 顺序无关** | τ 可加（§8.3） | 交换两球绘制顺序 → gold 图**逐字节不变** |
| **深度裁剪** | 半埋墙后的雾被正确裁 | 球一半在墙后，gold 图 + 像素计数（墙后区域无色差） |
| **单柱径向 × 轴向** | 圆柱求交 + 分离式剖面 | 三种轴向菜单各出一张 gold；轴向 `kDome` 与 `kUniform` 端面差异可量 |
| **1000 球 = 1 drawcall** | instanced 生效 | 断言 draw call 计数 = 1（球）+ 1（柱）；出图肉眼确认 |
| **关闭深度 / 非加法 blend** | 状态正确 | 单测断言 pass 结束后的 GL 状态（沿用 renderer_isolation 思路） |

> GPU 侧 gold 在 **Xvfb + llvmpipe** 下确定性输出（§9.1）；数学核在纯 CPU 单测。

## 14. 待定项 / 后续扩展

| 项 | 说明 |
|---|---|
| **剖面是否开放给用户选** | MVP：用户只配 color/size/intensity，profile 固定 `kDome`；是否在面板暴露 `kDome/kSharp` 待定 |
| **圆柱轴向菜单默认** | 倾向 `kDome`（无分段、最省心）；需要「均匀柱身」时再上 `kCoreRamp` |
| **全局高度雾叠加** | 远霾 / 贴地雾另做一条解析高度雾，可与本 pass 相加 |
| **mask 调制密度** | `σ_final = σ · (1 − revealed)`：探索推进时雾「退潮」（未探索地块那种玩法遮罩，与本 pass 相乘） |
| **发光体驱动 `L_in`** | 光剑 / 篝火 / 灯笼：把发光体颜色当雾的光源（§7.2） |
| **SDF 采样后路** | 若真要「环 / 壳」这类**非单调剖面**，届时再上「分段多项式精确积分」或「在剖面坐标上采样 + MC」（**不用**通用 SDF + 固定步长，那是必炸的） |
| **tiled light list** | 若雾体极多且需更省填充率，可上屏幕分块（CPU 侧建表），MVP 不需要 |
| **时间重投影 / 拖尾** | 挥动光剑的残影需跨帧保留（本 pass 每帧全量、不跨帧） |

## 附：本设计讨论结论来源

本设计由 2026-09-29 与 Danis 的多轮讨论收敛而成，关键决策点：

1. 从「屏幕空间解析雾」起步，扩展到「局部体积雾」。
2. 选 **闭式** 而非 SDF 采样：保确定、可测、零噪声。
3. 只做 **球 + 圆柱**（放弃 box 的自由度，换闭式与清晰）。
4. 渲染用 **instanced 加法累加**，**否决**「逐像素 index list / 8 槽」（多余且 GL3.3 难做）。
5. 「发光 = 光晕（bloom）+ 空气光（体积雾）+ 照明（发光体当光源）」三个职责分开；
   体积雾负责 bloom 做不到的「有视差、被遮挡、吃介质」。
6. 密度剖面是 **JPOV 锁定菜单**（`kDome`/`kSharp`/`kUniform`/`kCoreRamp`），用户只配 color/size/intensity。
7. 圆柱 = 径向 × 轴向**分离式乘积**；角上双零（削圆）是闭式的等价交换。
8. 顺序无关（τ 可加、S 一阶可加）⇒ 不排序。
9. GPU 端无随机、无采样 ⇒ llvmpipe gold 图可逐字节复现。
10. 目录/词汇定稿：`volumetric_fog/{sphere_fog,cylinder_fog}`（修正初稿 `effect/ball_fog`）。
