## 0. TL;DR

**不要"逐情形"烘焙 3D 纹理；要"逐物理原型"烘焙，用几何去驱动。**

- 火的"本体" = 一个标量场（soot 密度 / 温度）在**浮力 + 湍流 + 边界条件**下的演化。
  真正**变**的只有三件：**发射几何 / 尺度与各向异性 / 约束（浮力·风·障碍）**。
- **火本身（噪声结构、湍流谱、冷却曲线）几乎不随场景变** —— 变的是它被"贴"到哪个几何上。
  ⇒ **这就是全部复用空间。**
- 系统切成**三层正交族**：
  1. **原型族（要烘的"场"）**：`jet / area / pool / transient` —— **仅 4 族**。
  2. **修饰族（运行时几何驱动器，不重烘）**：风切 / 脉动 / 旋流 / 拉伸 / 平铺相位 / 生长-熄灭。
  3. **着色族（传递函数，几何无关）**：黑体橙焰 / 蓝预混 / 化学色 / 风格化。
- **分工**：**用户 = 提供/改原型族纹理（守资产契约）**；**JPOV = 几何驱动器 + 着色 + 运行时**。
  形态与**植物生成器一致**：范本 → 参数化 → 人机共驾调。
- **两条硬契约**（否则"通用"不成立）：**① 资产存物理量（密度+温度K），不存颜色；② 资产带家族标签 + 烘焙规约。**

## 1. 为什么不是"逐情形烘焙"

朴素直觉：给「点着的 box / 平地火区 / 摇曳的蜡烛 / 燃烧立柱 / 整颗燃树」各烘一份 3D 纹理。

**这是资产地狱**：N 种形状 × M 种风/尺度 × K 种色 —— 每新增一个组合就多一份体积资产，
迭代慢（每改一次要重烘）、体积大（每份数 MB~数十 MB）、且**根本不可能穷举**。

**正确的分解**：把**固有场**与**它贴在哪个几何上**解耦：

```
Fire(x, t) = 固有火场( warp(x, t) )  ×  几何遮罩 / SDF(object)  +  浮力 / 风
             └── 原型族资产（烘） ──┘    └──── 几何驱动器（运行时）────┘
```

**"固有火场"是少数几族的烘焙资产；"贴在谁身上"是运行时的几何变形。** 于是：

- **蜡烛 ↔ 立柱 ↔ 火把** = 同一份 `jet` 原型，只差 scale + 长宽比 + 侧摆。
- **box 顶面 ↔ 平地面火** = 同一份 `area` 原型（大面走 `pool`），靠**平铺 + 相位错开**。
- **燃树** = 复用小单元，**撒在枝干表面**（= 你粒子线里"表面发射"的同一原语）。
- **火线/火旋风/定向喷流** = 复用 `jet`/`area` + 一个**运行时 warp**。

## 2. 三层正交族（不要混成一条轴）

| 层 | 定义 | 是否需要新烘焙 | 归属 |
|---|---|---|---|
| **原型族** | 发射几何 + 动力学体制 | **是**（4 族） | 用户提供 / JPOV 范本 |
| **修饰族** | 同一原型的 warp/驱动 | **否** | JPOV 运行时 |
| **着色族** | 传递函数（温→色） | **否** | JPOV 通用功能 |

---

## 3. 原型族（烘焙层）—— 就 4 族

每族 = 一份（或少数几份）可循环/可播放的**3D 物理场资产**。

| # | 族 | 发射几何 | 动力学体制 | 坐标轴约定 | 可否循环 | 典型场景 |
|---|---|---|---|---|---|---|
| 1 | **`jet` 竖直射流** | 点 / 小面 | 自由浮力柱（层流⇄湍流） | 发射轴 = **+Y** | ✅ 稳态可循环 | 蜡烛、火把、燃烧立柱 |
| 2 | **`area` 面火单元** | 小幅面 | 短焰、贴升 | 生长 = **+Y** | ✅ | 燃料块顶面、小火区 |
| 3 | **`pool` 池火** | 大面积 | 长程卷吸 + **脉动 puffing** + 强自遮挡 | 生长 = **+Y** | ✅（含脉动周期） | **平地面火、火海** |
| 4 | **`transient` 瞬态团** | 点/体 | **生命周期**（出生→膨胀→熄灭） | 球/柱增长 | ❌ **有历史，不循环** | 爆炸、轰燃、点火增长 |

**关键区分**：

- **`area` vs `pool`**：`area` 是**小单元、可平铺**；`pool` **面积一大就出现长程对流卷吸 + 周期涡脱落 + 大范围自遮挡**，
  ⚠️ **不能靠平铺小单元糊过去**（会露重复、且没有大尺度涡）→ `pool` 需**双尺度**：
  **大尺度低分"母火"场（烘）+ 高分辨率细节（可由 `area` 单元叠加）**。
  **「平地着火区域」属 `pool`，不是 `area`**。
- **`transient` 是唯一"有时间史"的族**：不能循环，靠 `life ∈ [0,1]` 播放；与其余 3 族的"稳态循环"体制不同。

**"必须新增烘焙"的只有 `pool` 与 `transient`**（相对已落地的 `jet`/`area` MVP）。

## 4. 修饰族（几何驱动器）—— 不重烘，纯运行时

同一份原型，加下列 warp/驱动即"变身"。**这是复用的大头。**

| 修饰 | 作用 | 作用于 | 典型产物 |
|---|---|---|---|
| **风切 / 侧摆 wind-shear** | 横向剪切 + 相位推进 | `jet`/`area` | 摇曳的蜡烛、被吹斜的火 |
| **脉动 puffing** | 周期涡脱落 | `pool` | 池火的周期性冒团 |
| **旋流 swirl/whirl** | 绕轴旋转 warp | `jet` | 火旋风 |
| **各向异性拉伸 stretch** | 沿轴缩放 | `jet`/`area` | 立柱拉高、喷流拉长 |
| **平铺相位/旋转错开 tiling offset** | 逐块去同步 | `area`/`pool` | 大面积火区、火海 |
| **生长/熄灭 growth/decay** | 时间包络 | 全部（`transient` 尤甚） | 点火增长、熄灭 |
| **表面附着 surface-attached** | 火焰沿表面流动 | `area`/分布式 | 壁火、树干贴壁火 |

> **几何驱动器 = 把"用户声明的意图"翻译成对场采样域的变形。** 见 §7。

## 5. 着色族（传递函数）—— 几何无关，JPOV 通用

**几何全同，只换色/温。** 因为资产存的是**温度(K)**，着色就是一条 **温度→线性色** 的映射：

| 着色族 | 来源 | 备注 |
|---|---|---|
| **橙色扩散焰** | 黑体（与 `SkyCommand::ColorTempToLinear` 同源曲线，Tanner Helland） | 默认 |
| **蓝色预混焰** | 高温区段重映射（无烟） | 几何复用 `jet` |
| **化学/金属色焰** | 色带自定义（铜绿、硼绿） | |
| **风格化火** | 任意 ramp（紫火、绿火） | 游戏常用 |

**前提**：资产必须存**物理温度**而非烘死颜色 —— 否则着色被焊死（见 §6 契约①）。

## 6. 资产契约（"通用"成立的两条硬前提）

### 契约① 存物理量，不存颜色

用户的体积资产**必须**满足 **JPVOL2 通道语义**：

- `R = 密度`（σ，量纲 **1/m**，与雾同量纲）
- `G = 温度`（**开尔文**，当前 uint8 归一化 ×2000K）

⇒ **着色天然通用**：JPOV 用黑体把温度→色算出；用户换橙/蓝/紫火只换 ramp，**几何一个字节都不重烘**。

⚠️ **反例**：若用户直接烘 RGB，着色被焊死在资产里，JPOV 再也 tint 不动。**这是最需防的"打开方式错"。**

### 契约② 家族标签 + 烘焙规约

几何驱动器是**按家族**给不同处理的（`jet` 可拉伸、`pool` 要母火+细节、`transient` 是生命周期）
⇒ JPOV 必须知道这份资产**是哪一族**，才能选对驱动器。

**建议落地**：**sidecar 元数据**（`<asset>.jpovvol.json`），**不污染二进制格式**（保持 JPVOL2 稳定）：

```json
{
  "family": "jet",            // jet | area | pool | transient
  "loopable": true,           // 稳态族=true；transient=false
  "emission_axis": "+Y",      // 约定发射/生长轴
  "dims": [48, 48, 48],       // 各向异性在此声明（如立柱 [32,192,32]）
  "frames": 32,
  "sigma_ref": 8.0,           // 建议 1/m 基准（供 σ_scale 参考）
  "temp_max_k": 2000,
  "notes": "laminar candle-like jet"
}
```

**兜底**：注册 API 允许**运行时覆盖**（`RegisterVolumeTexture(path, FireAssetDesc)`），
sidecar 缺失时**默认 `jet/loopable`** 并在日志 WARN（不崩）。

## 7. 责任分工（用户 vs JPOV）

| 层 | 用户 | JPOV |
|---|---|---|
| **原型族纹理** | **提供 / 改**（守 §6 契约）；或从范本调 | 发 **4 份基线范本** + **烘焙/导入工具链**（JPVOL2 / Mantaflow 文档） |
| **几何** | **声明意图**（发射几何 / 朝向 / 尺度 / 风 / 是否贴壁） | **实现变形**（几何驱动器，§8） |
| **着色** | 选 ramp + 调旋钮（温标 / tint） | **通用黑体 + 传递函数** |
| **运行时** | 定性能预算 | raymarch / WBO / 步数 / LOD / 预算剔除 |

> **一句话**：**用户管"火的固有场"，JPOV 管"怎么长、什么色、怎么渲"。**
> 几何是**共驾**：**用户给意图，JPOV 给执行**。

## 8. 几何驱动器接口（含关键几何情形）

### 8.1 核心原则：**发射区 ≠ 生长方向**

> **生长方向永远是浮力方向（+Y，或风切后的方向），与表面法线无关。**
> **表面朝向只决定"烧不烧得起来"（upness 门控），不决定"往哪长"。**

```
field(x,t) = upness(surface) × prototype_field( warp(x, t; 意图参数) )
```

- `upness(surface) = saturate( dot(surfaceNormal, up) )`（或"SDF 向上 raycast 是否有开阔空间"）。
- **朝上的斜面**：仍走 **`area`** 族，发射区是斜面，**火焰沿 +Y 升起**（不贴法线倾）。
  upness 略小于 1 → 强度略降（物理上斜面的火焰确实略弱）。
- **向下/斜下的面（燃料底面、挑檐下）**：
  1. **upness ≈ 0 → 不产生上升火焰**（物理也对：底面没有向上焰）；
  2. **火焰由边缘/周界发射**，被 **SDF 裁剪** 后**贴边翻卷**（"火焰绕过挑檐在边缘逃逸"的观感）；
  3. 底面若要点"闷烧/余烬"，那是**附件层（embers）**的事，不属"火本体"。

⇒ **底面/斜下的"破解" = ① upness 门控 + ② SDF 裁剪 + ③ 周界发射**，不需要新的原型族。

### 8.2 分布式（表面着火）—— 接口不复杂，成本才是重点

**拆解**：把**"哪里着火"（发射采样）**与**"怎么烧"（火场）**分开。

```
SurfaceFireEmitter {
  mesh_id / sdf_id            // 目标几何
  burn_mask                   // 逐顶点 / 逐纹素 / 程序化的"燃料/已燃"标量
  cells_per_area              // 采样密度（面积加权）
  cell_family  : area | jet   // 用哪个小单元
  cell_params  : scale, phase_jitter, wind
  attach_mode  : detached | surface_attached
}
```

- **发射采样**（surface point sampling，面积加权）**是通用原语** —— 与粒子系统
  "在表面生成"**完全相同**的活，**不绑定任何具体 mesh 形状**。
- **火场**仍是通用 +Y 小单元（`area`/`jet`），逐点**相位错开**压重复。
- **接口本身不复杂**：输入 = "带 burn_mask 的 mesh + 单元参数"，输出 = 一组实例化小体。

**真正的两个难点（都不是接口问题）：**

1. **成本**：小单元数量可能爆炸 ⇒ **必须复用粒子线的低分辨率 WBO + 预算/剔除方案**
   （`jpov_fragment_overdraw_design.md` 的结论：透明 overdraw 只能靠 低分 + WBO + 预算治）。
2. **"贴壁"保真度**：真正的**表面贴合流动**（火焰沿弯曲树干表面流动）是研究级难题，
   近似 = **SDF 裁剪的上升场 + 表面法线导流**。

⇒ **拆成两档**：

| 档 | 模式 | 难度 | 场景 |
|---|---|---|---|
| **A（易）** | **detached 多射流**：表面采样 → 各点独立 +Y 小单元 | ✅ 接口现成 | **燃树、燃烧家具、多点着火** |
| **B（难）** | **surface-attached 连续流**：火焰贴合复杂拓扑流动 | ⚠️ 需 SDF+流场 | 壁火、弯曲树干贴壁火（**defer**） |

**结论（回答"会不会复杂到做不成接口"）**：
**接口简单**（就是"表面发射器"这个通用原语）；**难点在性能与贴壁保真**，且**燃树落在易档 A**。
所以分布式**不阻塞接口**，可先做 A、后做 B。

## 9. 与既有系统的关系

| 既有件 | 关系 |
|---|---|
| **JPVOL2 格式** | 资产载体；通道语义（R=密度/G=温度K）即契约①；本设计**不改二进制**，家族信息走 sidecar |
| **`VolumeManager`**（`#185`） | 资产注册/去重/生命周期；家族标签作为其 entry 的附加字段 |
| **`VolumeFireRenderer`**（`#185`） | 原型族的**渲染后端**（raymarch + 透明累积缓冲薄层） |
| **低分 WBO 粒子渲染器**（`#180`） | 分布式档 A（多单元）的**性能底座**（低分 + 免排序） |
| **植物生成器** | **形态参照**：范本资产 + 参数化生长 + 人机共驾；本系统 = "火的生长器" |
| **`TransparencyBuffer`(TAB)** | 原型族输出的薄层写进同一套透明累积缓冲 |

## 10. 分批实施计划（建议）

1. **P0（范本与契约）**：4 族范本报导（`jet`/`area` 已有；补 `pool` 母火、`transient`）；
   落 sidecar 元数据 + `FireAssetDesc`；`VolumeManager` 承载家族字段。
2. **P1（几何驱动器 v1）**：`jet` 的 scale/stretch/wind-shear；`area` 的 tiling+相位；
   **upness 门控 + SDF 裁剪**（§8.1）。覆盖：蜡烛 / 立柱 / box 顶面 / 平地面火（`area` 近似）。
3. **P2（着色通用化）**：温度→色 ramp 可切换（黑体/蓝/化学/风格化）+ 温标旋钮。
4. **P3（分布式档 A）**：`SurfaceFireEmitter`（表面采样 + burn_mask + 小单元）；燃树。
5. **P4（`pool` 双尺度）**：母火场 + 细节叠加；真·大面积火区/火海。
6. **P5（`transient`）**：生命周期播放；爆炸/轰燃。
7. **Defer**：surface-attached 连续流（档 B）、烟/火星/热畸变/bloom（附件层）。

## 11. 开放问题

- **`pool` 的"母火"与细节如何缝合**（双尺度合成 / 域分解）？需要一次专门实验。
- **`transient` 的时间轴**：烘焙时域 vs 运行时 `life` 曲线如何参数化（不同时长复用同一段）？
- **upness 用表面法线还是 SDF 向上可见性**？后者更准（挑檐下）但更贵。
- **风格化火**是否需要独立原型（还是纯 ramp 重映射足够）？
- **sidecar vs JPVOL 头部扩展**：长期看哪个更利于工具链生态。
- 与**附件层（烟/火星/热畸变）**的合成次序（在透明累积缓冲内还是外）。
