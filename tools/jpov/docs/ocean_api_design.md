# 海面「人类可读」接口设计（OceanState → 谱 → 渲染）

2026-11-20。目标：美术只写「风多大、吹哪边、这儿有股流」，谱/细节/亚像素全部推导；
flow map 变成「画速度场 + 一个记忆时间」，而不是调 flow_align / warp_amp 这些实现细节。

---

## 1. 先回答：三个量够不够？

**不够。** 三个量各管一件事，但缺了把它们变成"一片海"的另外几个量：

| 你给的 | 它真正决定 | 缺的那一半 |
|---|---|---|
| 风速度 | 风海的 **Hs、Tp**（经验关系） | 还要**风向**；只给风速等于不知道浪往哪走 |
| 波浪幅度 | 只是结果，不是输入 | 同风速在半封闭湖里是 0.5 m、在大洋是 2 m ⇒ 需要**风区/风时**（或"充分成长"开关） |
| 水流方向 | **只搬运/折射**，不造浪 | 流的**速度**、**空间结构**、**作用了多久** |

必须补的 4 项（按重要性）：

1. **风向**（wind-sea 的传播方向）。
2. **风区 fetch / 风时**（或一个 "fully developed" 勾）：决定同一风速下浪高与峰位。
3. **涌浪 swell**：不是本地风造的，是几百公里外传来的长波。**真实海最好看的部分在这**
   （长、规则、方向单一，与风海交叉）。只靠一套谱永远做不出"两套系统交叉"。
4. **水深**：λ > 2·depth 时深水色散失效，波长被截短、浪变陡（浅滩的白浪）。

另外两个"非物理但必须有"：

5. **随机种子**：同样的参数要给出同样的一片海（可复现）。
6. **相位时钟**：对齐镜头/素材时要能冻结到某一秒。

---

## 2. 分层：三层，只有第 1 层是给人写的

```
L1  OceanCondition   ← 美术/导演写这一层（风速、风向、涌、流、水深、种子）
      │  推导（一次，不是每帧）
      ▼
L2  OceanSpectrum    ← 可读、可覆盖（8 主波 + 64 细节 + MSS + warp 位移）
      │  每帧只做 uniform 上传
      ▼
L3  WaterWaves/GLSL  ← 现有渲染器，一行不用改
```

L2 必须**可见**（面板上显示 Hs / Tp / λp / RMS 坡度），否则美术永远不知道自己调出了什么。

## 3. L1 → L2 的推导（可直接实现）

### 3.1 风 → 有效波高与峰周期（SMB 经验式，U 取 10 m 高处风速）

```
充分成长上限：  Hs∞ = 0.283 · U²/g        Tp∞ = 7.54 · U/g        λp = 1.56·Tp²

风区受限 F：    Hs = Hs∞ · tanh[0.0125 · (gF/U²)^0.42]
                Tp = Tp∞ · tanh[0.077  · (gF/U²)^0.25]

风时受限 t：    Hs = Hs∞ · tanh[0.00565 · (gt/U)^0.4]（周期基本已饱和，只看波高）
                取 min(风区值, 风时值) —— 谁先饱和谁定
```

> ⚠️ 常数说明：常见写法 `Hs = 0.21·U²/g` 用的是 **19.5 m** 处的风速（PM 原始论文）；
> 换算到 10 m 后系数约 0.26~0.28，SMB 取 0.283。本文统一用 **0.283 + U10**。

U=8 m/s 的风区表（Hs 随 √F 长、到几百 km 才饱和）：

| 风区 | Hs | Tp | 峰 λ |
|---|---|---|---|
| 5 km（湖/港湾） | 0.37 m | 2.4 s | 9 m |
| 20 km | 0.64 m | 3.2 s | 16 m |
| 100 km | 1.13 m | 4.3 s | 29 m |
| 500 km | 1.64 m | 5.3 s | 43 m |
| ∞（充分成长） | 1.85 m | 6.2 s | 59 m |

面板两个滑条：`风速` + `风区 km`（0 = 充分成长），`风时 h` 放「高级」。

### 3.2 谱形：只决定"细节怎么分布"

关键不是选 JONSWAP 还是 Phillips，而是**两个归一化条件**：

1. `Σ A_i²/2 = Hs²/16`（总方差对，波高就对）
2. 峰位落在 `λp`（长波定形，形状决定"看起来像不像涌"）

推荐 8 条主波，λ = λp · {1.60, 1.25, 1.00, 0.80, 0.63, 0.50, 0.40, 0.32}，
初幅按 Phillips 形 `A ∝ λ^{-0.5}`（等价于等陡度偏长波），再整体缩放到条件 1。

### 3.3 方向

- 风海：`dir = 风向 + N(0, σθ)`，`σθ ≈ 28° − 12°·min(fetch/500km, 1)`（风区越大越整齐）。
- 涌：`dir = 涌向 + N(0, 8°)`（很窄 —— 涌是"长峰浪"）。
- **细节短波**：各向同性（64 条均匀方向）——它们代表"亚像素级的风吹皱"，没有方向记忆。

### 3.4 亚像素（不要漏）

`MSS = 0.00512U + 0.003 + 0.00192U`（Cox–Munk，我们已在用）。它决定远处"毛玻璃"的
程度；漏了它，远处会像镜子。

### 3.5 数值锚点（拿去对照现有预设）

| | Hs | Tp | 峰 λ | RMS 坡度 |
|---|---|---|---|---|
| 现有 **B** | 1.71 m | 4.67 s | 34 m | 22° |
| 现有 **A** | 1.66 m | 4.67 s | 34 m | 25° |
| U=8、fetch≈200 km | ≈1.4 m | ≈4.9 s | ≈37 m | — |
| U=8、充分成长 | 1.85 m | 6.15 s | 59 m | — |

⇒ 我们现在的谱 ≈ **U=8 m/s、风区 200~300 km 的年轻风海**（峰位比充分成长短、坡度更陡）。
这解释了为什么它看起来"碎"：不是 bug，是 fetch-limited。

## 4. flow map 的人话版（重点）

### 4.1 现状的问题

我们有两套互不相干的"流"：

| 机制 | 在哪 | 它干什么 | 美术怎么理解 |
|---|---|---|---|
| `flow_align` + flow map 纹理 | `WaterWaves::flow_*` | 把浪的**方向**往流上掰、加振幅 | "流把浪吹歪" |
| `warp_amplitude_m` + 4 条载波 | `WaterWaves::warp_*` | 把浪的**相位**整体挪 | "？？？"（没法画） |

它们其实是**同一件事的两个切面**：一股流既搬运浪（相位位移），也会在最粗糙的近似里
让浪偏向它。现在被迫分成两个滑条，所以谁也调不出想要的效果。

### 4.2 统一：一张速度图 + 一个记忆时间

```
u(p) = U(p) · τ          τ = 这股流「作用了多久」（秒，默认 5~10）
```

- `U(p)` = 表面流速度场（m/s）—— **美术画的/摆的就是这个**；
- `u(p)` = 位移场（米）—— 我们现有的 warp 输入；
- 于是 warp 幅度不再是一个孤立的米数，而是 `速度 × 时间`，**有物理量纲、可解释**。

举例：`U = 0.8 m/s、τ = 7.5 s ⇒ u = 6 m`，正好是 C 预设现在的 warp 6 m。

### 4.3 流场怎么给（三档，从易到难）

```cpp
struct CurrentField {
    // ① 整体漂移（一个方向 + 一个速度）
    float drift_dir_deg  = 0.0f;
    float drift_speed_ms = 0.0f;

    // ② 几个"涡"（美术直觉：这儿打个转）
    struct Gyre { float x, z; float radius_m; float tangential_ms; };
    Gyre gyres[4]; int num_gyres = 0;

    // ③ 手绘速度图（最高优先级；覆盖 ①②）
    uint32_t painted_velocity_map = 0;  // RG = (Ux,Uz) 方向×强度，B 备用
    float    painted_max_speed_ms = 1.0f;

    float memory_s = 7.5f;              // u = U·τ
};
```

三档可以叠加：漂移 + 涡 是解析求值（和现在的 warp 一样便宜），手绘图是采样。

### 4.4 纹理编码约定（踩过的坑）

`RG = (U/|U|max)·0.5 + 0.5`，`B` 填 128；解码 `(rg·2−1)·max_speed`。
**编码必须写进接口注释 + 测试用编码值**（我们曾用原始 (1,0) 存，解码成 (1,−1)，排查 4 轮）。

### 4.5 自动限带（把"漩涡"变成不可能）

`u` 是所有波共用的，短波会被 `k·u` 转爆。既然 `u = U·τ`，就直接给面板一个**健康度提示**：

```
γ_wave = k · |∇u|        （每帧算一次最大波长与最短细节）
γ > 1  → 面板黄条警告「流太急/记忆太长，短波会拉丝」，并把 warp 自动压到 γ = 0.25
```

这样美术永远拖不出"大理石纹"，只会看到"太急，自动收敛了"。

### 4.6 该退役的东西

- `flow_align`（把浪掰向流）：物理上只有强流才显著，视觉上容易变"整片朝一个方向"。
  **建议默认 0**，只保留给极端场景。
- `flow_wind_gain`（流强则浪大）：同上，默认 0；真实效果是"逆流变陡"，用 4.5 的 γ 已经覆盖。
- 单独的 `warp_amplitude_m`：不再暴露给美术（由 `U·τ` 推出；留一个内部覆盖位）。

## 5. 面板长什么样（建议）

```
左列                     右列
────────────────────     ────────────────────
风 风速 m/s              涌 开关
风 风向 °                涌 波高 m
风 风区 km (0=充分成长)   涌 周期 s
水 水深 m                涌 方向 °
流 漂移方向 °             派  Hs / Tp / λp（只读）
流 漂移速度 m/s           派  RMS 坡度（只读）

```

一共 13 个可写控件 + 3 个只读派生量 —— 比现在的 20 个实现细节滑条更少，但能表达的
海况多得多（因为有涌 + 风海两套系统）。

## 6. 落地步骤（改哪里）

1. `interface/render_command.h`：加 `OceanCondition` / `CurrentField`（纯 POD，无 GL）。
2. 新文件 `src/water/ocean_state.h`：`BuildOceanSpectrum(const OceanCondition&, const CurrentField&)`
   → 返回 `WaterWaves` + `SlopeVariance` + 派生摘要。**纯 CPU、可单测**（断言 Hs、λp、
   Σ(kA)²、方向散布、γ≤阈值）。
3. `WaterWaves` 增加 `current`（`CurrentField`）字段；`SampleWaveField` 里的 warp 改成
   `u = U(p)·τ`（解析路径 = 载波求值，纹理路径 = 采样）。CPU/GLSL 同源照旧。
4. viewer 面板换成上面那 13 条；旧的 warp/flow 滑条收进「高级」。
5. 单测：
   - `U=8, 充分成长 ⇒ Hs≈1.37±5%`；
   - `Σ A²/2 = Hs²/16`（合成后必须精确）；
   - `τ=0 ⇒ 与无 warp 逐字节相同`；
   - `γ` 上限触发时 warp 被压到 0.25（而不是出漩涡）。

## 7. 取舍（先说清楚）

- **不做完整 JONSWAP 积分**：常数不精确没关系，美术要的是"拖动有效、方向正确"。
  谱形差异对视觉的影响远小于 Hs/Tp/方向/涌的差异。
- **不做两套以上系统**：涌 + 风海够用；再多就回到"手动加波"的老路。
- **不做时变风场**：风区/风时是标量近似；真要阵风，用 `gustiness` 抖 MSS 即可。
- **流不改波高**（一阶物理正确）：想让"逆流浪变大"，让它通过 `γ` 的自动限带间接体现，
  别加一个假的放大系数。

## 8. `WaterConfig`（uniform 版，先做这个）

地域无差异时的**全部**水面输入，一个 POD、可序列化、可整体上传：

```cpp
struct WaterConfig {
    // ── 1. 波：风 + 涌 ────────────────────────────────────────────
    jpov::Vec2f wind_velocity = {0.0f, 0.0f};   // m/s，世界 xz；|v| = 风速，方向 = 吹向
    float fetch_km    = kInf;                   // 风区；kInf = 充分成长
    float duration_h  = kInf;                   // 风时；kInf = 一直吹
    // (dir_x, dir_z, 周期 s, 波高 Hs m)；波高 = 0 ⇒ 无涌
    jpov::Vec4f swell = {1.0f, 0.0f, 9.0f, 0.0f};

    // ── 2. 流（场修饰）──────────────────────────────────────────
    jpov::Vec2f current_velocity = {0.0f, 0.0f};  // m/s，世界 xz
    float current_memory_s = 7.5f;                // u = U·τ（**uniform 时不可见**）

    // ── 3. 介质 ────────────────────────────────────────────────
    jpov::Vec3f sigma_a = {0.50f, 0.054f, 0.014f};  // 1/m
    float sigma_s  = 0.04f;                         // 1/m
    float phase_g  = 0.35f;                         // HG 各向异性
    float ior      = 1.333f;
    float depth_m  = 30.0f;                         // 平底；影响色散与可见底
    float level_y  = 0.0f;                          // 水位

    // ── 4. 数值预算（不是物理量，但决定"碎不碎"）──────────────
    int  main_waves   = 8;
    int  detail_waves = 64;
    uint32_t seed     = 20261120;
};
```

### 8.1 三条语义约定（都是踩过的坑）

1. **风向 = 吹向**，不是气象的"来向"。涌的方向同理。给"来向"的 UI 必须在这里转一次。
2. **`fetch = ∞` 表示充分成长**，不要用 `0`（0 是"没有风区"，物理上无意义，
   而且和"无限"共享一个魔数是最容易出错的接口）。
3. **涌是 Vec4 而不是三个标量**：`(dir_x, dir_z, T, Hs)` —— 方向是二维的，
   拆成 `dir_deg` 会让"方向插值"在 ±180° 处翻转（做 map 时会炸）。

### 8.2 不属于 WaterConfig 的四样（在场景层）

| 东西 | 属于 | 为什么不能塞进来 |
|---|---|---|
| 太阳/天空/云 | `SkyCommand` | 水面只是消费者；同一份水配不同天光要能复用 |
| 曝光/色调映射 | `RenderCommandList` | 后处理，不是物理 |
| 海底（几何 + 材质） | 场景 | 水深是**水的属性**，底长什么样是**场景**的属性 |
| 相机 / 时间 | 调用方 | 波浪是时变的，但配置不该带时钟（要能冻结/回放） |

### 8.3 派生链

```
WaterConfig ──► BuildOceanSpectrum() ──► WaterWaves   （波：主波 + 细节 + 短波 MSS）
            └─► BuildWaterCommand()  ──► WaterCommand （介质 σa/σs/g/ior/depth + 水皮开关）
```

`WaterConfig` 里没有任何"渲染实现"字段（没有 warp 幅度、没有 flow_align）——
它们全部由 ①④ 推导出来。这是"语义好理解"的判据：**美术能用一句话解释每个字段**。

### 8.4 ⚠️ uniform 流的真实效果：看不见

均匀流速 `U` 让 `u(p) = U·τ` 变成**常数** ⇒ 整片浪只是平移，而统计均匀的浪场平移 =
和原来一模一样（伽利略不变）。所以：

- **v1（无 map）里 `current_velocity` 只影响"短波方向偏置"这一个副作用**，视觉几乎没有；
- 真正让流"看得见"的是 **∇u ≠ 0（空间变化）** —— 那是 v2 的事。

结论：v1 可以先**不暴露** `current_velocity`（留字段、默认 0），把预算花在风/涌/介质上；
v2 再用 map 打开。

### 8.5 v2（map）的架构原则：**map 调制"场"，不调制"谱"**

- **谱（8 主波 + 64 细节）保持全局唯一**：逐像素重建 72 条波的成本是不可接受的；
- map 只提供**慢变场**：`U(p)`（流）、`depth(p)`（可选）、`exposure(p)`（可选）；
- 每像素只多做三件便宜的事：采样 map、`u = U·τ`、`k·∇u` 的限带检查（都是几个 flop）。

`WaterConfig` 的字段都小（≈15 个 float），32×32 的 map 就是 2 张 RGBA32F 纹理；
**插值必须在物理量上做**（U、depth），不能在派生量上做（Hs、λp 插值后不守恒）。
