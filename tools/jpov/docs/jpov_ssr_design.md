# JPOV 屏幕空间反射（SSR）· 设计

> 日期：2026-10-26 ｜ 状态：**已实现（v1）** ｜ 决策人：Danis
>
> 关联：`interface/ssr_types.h`（配置）、`src/ssr/`（子渲染器 + 全部 GLSL）、
> `docs/jpov_env_specular_design.md`（环境镜面，与本模块互补）。

## 0. 一句话

把已经画好的**不透明 3D 画面**当成一张 2.5D 场景（颜色 + 深度），在屏幕空间里逐像素
发射反射射线，撞到的东西就当倒影**加法**叠回 HDR。Hi-Z 金字塔用来把「空区域」整块跳过。

## 1. 与「环境镜面（EnvSpecular）」的分工

| | EnvSpecular（#228） | SSR（本模块） |
|---|---|---|
| 反射内容 | 只有**天光**（程序化天空 cubemap） | **场景内几何**（真倒影） |
| 遮挡概念 | 无（全局乘子） | 有（深度图里的遮挡关系） |
| 视差 | 无（只跟法线有关） | 有（真射线） |
| 成本 | ≈0（6×128² 天空 + 一次采样） | 逐像素射线（见 §6） |
| 边界 | 无 | 只能在屏幕内、不能反射屏外/背后 |

**两者是同一个物理量的两种估计，本版是叠加关系。** 同时开会双计（画面偏亮），
所以 demo 里 **SSR 一开就自动关掉 env**（`skylight_viewer_app.h` 的 OneIteration）。

想做「命中用 SSR、没命中回退探针」需要材质侧参与 —— 前向管线里 SSR 必然晚于材质着色，
同帧无法回灌。正确做法是把反射项整体搬到后处理（材质只出属性），属于下一版。

## 2. 四个 pass

```
不透明 3D 画完（fbo_hdr_：颜色 + MRT#1 R32F 场景深度 + 硬件深度）
  ① attr       → 反射体的 (视空间法线, 粗糙度, F0) 写进属性缓冲（2×RGBA16F）
  ② hiz        → 深度逐级 2×2 取 min，建 4 级金字塔（level0 = 场景深度本身）
  ③ march      → 逐像素射线 → 反射缓冲（rgb = 反射色·权重，a = 权重）
  ④ composite  → 加法叠回 fbo_hdr_（只读反射缓冲、不读目标 ⇒ 无反馈环）
→ 半透明 / 粒子 / 体积火 / 条带 / 雾
```

放在这个位置的三个硬理由：
1. 它要读**已画完**的不透明颜色与深度；
2. 半透明物体不写场景深度、还会污染颜色 —— 绝不能进反射源；
3. 它必须在雾之前，否则倒影不吃雾、会从远景里"跳出来"。

## 3. 属性缓冲：为什么单独跑一遍，而不是给主 pass 加 MRT

给主 pass 加一张 G-buffer（MRT）是"正统"做法，但代价是：
`sky` / `object3d`×6 / `instanced`×4 / `skinned`×2 / `primitives3d` / `text3d`
—— 一共 15 个 shader 都要加一个 `layout(location=2) out` 并真的写它。
仓库有条铁律：**凡写该 FBO 的 shader 必须写全部附件**，漏一个就是未定义内容
（2026-09-30 的整屏 NaN 就是这么来的），而且症状只会在倒影里出现。

本模块改成**自己画一遍属性**：
- 顶点着色器**复用**主 PBR 的那两份（`Object3DRenderer::kMeshVs3dPBR` / `Full`）
  ⇒ 顶点变换、法线、切线逐字一致，不会错位；
- 深度附件直接挂**主 3D 的硬件深度纹理**做 `GL_LEQUAL` 测试（深度写关闭），
  ⇒ 遮挡关系与主 pass 完全一致，且不破坏主深度；
- 只画**标记了 `ssr_reflect` 的物体** ⇒ 成本 ∝ 反射体的屏幕面积，
  没收标记的物体一个像素都不付。

代价是多一遍反射体几何的绘制。**这个取舍是刻意的**：既有 gold 一个都不动，
出问题也只可能在倒影里。

## 4. 射线行进（Hi-Z）

### 4.1 数学

视图空间：相机在原点、朝 -Z；「距离」d = -z_view > 0。标准透视：

```
z_ndc = (f+n)/(f-n) − 2fn/((f-n)·d)        d=n → -1, d=f → +1
d     = 2fn / ((f+n) − z_ndc·(f-n))
```

**沿一条直线，1/d 在屏幕空间是线性的**（透视正确插值）。所以粗步进时只要知道线段两端的
距离，任意点的期望深度都是 `1/d = mix(1/dStart, 1/dEnd, t)` —— 一次 mix，零误差。
这是 Hi-Z 粗走能保证正确的关键；用「按步长累加世界距离」就会在粗层上漂。

法线约定（**最容易搞反的一处**）：可见表面的视空间法线**指向相机**，即
相机在原点、面在 z<0 ⇒ 法线 **N.z > 0**。属性 pass 只存 `N.xy`，下游按
`nz = +sqrt(1−x²−y²)` 重建。

### 4.2 行进

```
把 R 的终点投影回屏幕 → 裁到 [0,1]² → 得到屏幕线段（像素空间）
level = hiz_start_level
while (未走完 && 步数 < max):
    step = 2^level 像素
    取「走到下一步」处：dRay（由 1/d 线性插值得）、ndcRay
    ndcCell = 该像素在 level 层的最小深度
    if (ndcRay <= ndcCell)  → 光线在这一格**前面**，整格跳过，s += step
    else if (level > 0)     → 这一格可能相交 → level--，**s 不动**，用更细的步长重走
    else                    → level 0 单像素精度：
                              dRay − dScene <= thickness → 命中
                              否则 = 穿过薄物体，继续走
命中 → 在最后一步内二分 refine_steps 次 → 取颜色
没中 → 天空兜底
```

**为什么「下探时 s 不动」**：粗层的一步跨 2^level 像素，可能整格跳过命中点。
检测到「这一格可能相交」时退回格子起点、换更细的网格重走同一区域 —— 这是 Hi-Z
不漏检的原因。`level 0` 时格子 = 1 像素，深度比较就是**精确**的。

### 4.3 三个必须的守卫

1. **厚度测试**：光线钻到表面背后不足 `thickness_m` 才算命中，否则视为穿过薄片
   （树叶/栏杆）。不做的话水面/金属上会映出"漏光的树"。
2. **权重淡出**：粗糙度（超出 cutoff 直接不做）、屏幕边缘（那里没有可信数据）。
   ⚠️ **距离淡出只对命中生效** —— 没命中走的是天空兜底，它的质量与光线走了多远无关。
   第一版把两者一起淡成 0，出图与"关掉 SSR"逐像素相同（踩过）。
3. **反向射线**：`R.z > 0` 表示反射朝相机后方（正对着你的镜子映的是你身后）——
   屏幕空间里没有那块画面。这不是实现缺陷而是 SSR 的定义边界，处理方式与"没命中"一致：
   天空兜底（真实引擎里那是反射探针的位置）。

## 5. 接口

```cpp
// render_command.h
std::optional<SsrConfig> ssr;                       // 未设置 / enabled=false = 零开销
void DrawObject3DReflective(mesh, mat, center, up, front, scale);  // 标记反射体
```

`SsrConfig` 的旋钮（都在 `interface/ssr_types.h` 逐个写了语义）：
分辨率倍率 / Hi-Z 起始层 / 最大步数 / 细化次数 / 薄片厚度 / 最远距离 / 粗糙度上限 / 边缘淡出。

**为什么反射体是逐物体标记，而不是按 metallic/roughness 自动推断**：
成本 ∝ 反射体屏幕面积，而"这块表面该不该有倒影"是美术决定（大理石地板要、粗糙石灰墙不要）。
按材质猜会在"光滑但不想反光"的物体上花冤枉钱。

## 6. 成本

```
总成本 ≈ 属性 pass（∝ 反射体几何） + Hi-Z 建塔（≈1.33× 全屏降采样）
        + 射线行进（∝ 反射体的屏幕像素 × 步数） + 一次全屏加法合成
```

**关键**：只有标记了 `ssr_reflect` 的像素才发射线（属性掩码为 0 的像素在 march 开头的
第一个分支就 `return`）。所以「给一个方块开 SSR」的成本 ≈ 那个方块占的像素量，
与全屏无关。

实测（llvmpipe，1280×720，金属方块约占屏 3.4%）：
- 关 / 开 的整帧时间差异极小（方块像素 3.2 万 × 32 步 ≈ 100 万次深度采样）；
- 三档参数（Hi-Z(2,32) / Hi-Z(3,16) / 关 Hi-Z(0,64)）出图有可分辨差异，
  但整帧耗时都在同一量级 —— 因为反射体面积太小。

## 7. 已知限制（写清楚，别当 bug）

1. **只能在屏幕内**：屏外/相机背后的东西反射不出来（用天空兜底）。
   这也是"正对相机的镜面会变成天空色"的原因。
2. **没有互反射**：A 映出 B 时采样的是 B 的**最终着色结果**，不是"B 也照镜子"之后的样子。
3. **一个像素一条射线**：粗糙度 > `roughness_cutoff` 直接不做（做了也是噪点）。
   没有粗糙度模糊（多射线/模糊核都没有）。
4. **半分辨率会轻微外溢**：反射缓冲降采样后双线性上采样，反射体轮廓外 1~2 像素会被
   带一点反射。远景/半透明场景看不出来。
5. **反射体暂不支持**：蒙皮/实例化物体（只有 `Object3DCommand` 有标记）、
   带风位移的物体（属性 pass 不施加风位移，会与主 pass 错位）、alpha 非 kOpaque 的物体。
6. **没有时间累积/降噪**：JPOV 是「每帧从零构建」的纯函数式渲染，没有跨帧状态可用。
