## 0. 目标

用**拿来主义**逼近一个 CC0 篝火参考：以 **EmberGen 官方渲染**为标准答案，
把 JPOV 的体积火渲染（资产 + 后端 + 附件层）**逐条补齐机制**，直到渲染观感
**不弱于**官方；最终**在本地自烘一份等价 VDB 资产**（含 density/heat/flame 通道），
走同一套 A/B 达标。

方法论照搬「Tripo 模型渲染还原」：**先钉死标准答案 → 固定相机/帧 → 逐机制 A/B →
一律用像素量化验收**（不靠肉眼/vision 措辞——历史教训：vision 判读多次自相矛盾）。

## 1. 标准答案（Ground Truth）

**EmberGen 官方渲染**：`smallCampfire.mp4`（200 帧，1626×1152，纯黑底、孤立火 + 烟柱）。

- 来源：JangaFX EmberGen **免费 VDB（CC0，可商用）**
  `https://jangafx.com/software/embergen/download/free-vdb-animations`
  该套件自带 `.mp4` 官方预览渲染 + `.ember` 工程 + 200 帧 `.vdb` 序列。
- 它与我们手上的 CC0 VDB 是**同一份资产**，因此是「同一份 VDB 的官方标准渲染」——
  正适合做机器可比对的标准答案。

### 1.1 帧对应关系

| 环节 | 帧域 | 说明 |
|---|---|---|
| 官方 mp4 | `n ∈ [0, 200)` | 与 VDB 序列一一对应 |
| 源 VDB 序列 | `smallCampfire_%04d.vdb`，200 帧 | `n` 同上 |
| 我们入库的 `campfire.jpovvol` | `k ∈ [0, 80)` | 由**源帧 60..139**转换（`--start 60 --end 140 --ds 2`）|

⇒ **资产帧 `k` ↔ 官方帧 `60 + k`**。例：资产帧 0 ↔ 官方帧 60。

> ⚠️ 待 P1 核对：mp4 帧号与 VDB 帧号是否严格同序（EmberGen 导出默认同序；先用
> 端到端形状对齐确认一次）。

### 1.2 目标锚点（非 CC0，仅作"要像什么"）

`/james_pm/目标火焰.png`（520×497，123RF 水印）：照片级真篝火，含柴堆、余烬辉光、
被火照亮的地面、白热芯→黄→橙的色阶。这是**最终野心**（决定附件层 C 的验收），
**不作为像素比对基准**。

## 2. 机制清单（逐条可验证）

分三层。**A 层是"还原"的地基**（缺了它后端再调也白搭）。

### A. 资产 / 数据层

| # | 机制 | 现状 | 判定依据 |
|---|---|---|---|
| **A1** | **多场通道** | EmberGen campfire = 两个 grid：`flames`(火/反应，稀疏丝状) + `density`(烟，致密)。P0 时只带了 flames；**P1 已扩成 3 通道**（R=火密度, G=温度, B=烟密度）✅ | 参考图有**粗烟柱** |

### 3.1 统一量化指标（`tools/campfire_ab/ab_metrics.py`）

以「亮度阈值」取前景，双方同法：

1. **形状**：包围盒高宽比 `h/w`、前景面积占比 `%`。
2. **颜色**：前景均值 RGB、暖色相直方图、近白（>230）占比。
3. **竖向亮度剖面**：前景归一化后逐带平均亮度（火能量沿高度分布）。
4. （可选）对齐后轮廓 IoU。

> 判据口径：**“不弱于”= 上述指标朝参考单调收敛，且无回归**；每阶段记录数值。

### 3.2 逐帧 A/B（自动化 diff 范式）—— `ab_seq.py`

单帧 A/B 只能看“某一瞬间像不像”；真正的验收门禁是**逐帧**跑同一套指标：

1. **纯数值、无需 vision 模型** ⇒ 确定性、可无人值守，P1..P6 每补一条机制就看各
   指标曲线是否朝参考单调收敛（**自动验收门禁**）。
2. **只有逐帧才看得见的问题**：闪烁（帧间差）、循环接缝、烟随时间的演化。
3. **顺带验证帧对应**：`资产帧 k ↔ 官方帧 60+k` 是假设；映射错则曲线跳/乱，
   这条工具本身就是验证器。

产出：逐帧指标表（`ab_seq.csv`）+ 竖排拼图（`strip.png`）。

### 3.3 P1（第一步）：加上烟 —— 多场分离 + 烟受光散射

**问题**：P0 的资产只带了 `flames`（火），**烟整条丢失** → 参考图上方那根粗烟柱我们没有，
形态/亮度都对不上。且烟在**纯黑背景**下不发光也不散射 ⇒ 直接加进去也看不见。

**走过的坑（已排掉）**：先把 `density` 直接叠进 R（消光场）→ 火柱 σ 暴涨、整团糊成
一个亮块（两个 grid 绝对量纲差 ~300×，且烟与火在空间上重叠）。

**最终算法**：

1. **资产：3 通道**（`vdbseq_to_jpovvol.py --b-grid density`）——
   `R=火密度(flames) / G=温度(flames) / B=烟密度(density)`，**各场按自身全局 max 独立归一**
   （不归一的话 density(≈0.003) 会被 flames(≈1) 淹没）；JPVOL2 头原有 `channels` 字段，
   引擎读取扩到接受 2 或 3 通道（3 通道 = `GL_RGB8`，**必须把 `GL_UNPACK_ALIGNMENT` 设 1**，
   否则每行 3 字节不是 4 的倍数 → 行错位）。
2. **渲染：火/烟分流 + 烟受光散射** ——
   `σ = σ_fire + σ_smoke`（两者都吸收，`σ_fire=R·s`、`σ_smoke=B·s`）；
   **自发光只按火自己的光深注入**：`L += T·a_fire·Blackbody(G·Tmax)·emission_scale`，
   其中 `a_fire = 1−exp(−σ_fire·dt)`（总透射率仍按 `σ` 衰减）；
   烟额外加**均匀受光单次散射**：`L += T·smoke_scatter·σ_smoke·albedo·light_color·dt`
   （`light_color` 取中性偏冷灰 ≈ 环境散射光；不散射则纯黑底下烟不可见）。
   `smoke_scatter = 0` 或 2 通道资产 ⇒ 整条路径关闭（**零回归**）。

   ⚠️ **烟会盖住火 / 烟太亮 —— 同一个旋钮解决**：散射注入 ∝ `σ_smoke`，所以新增
   **烟消光倍数 `smoke_sigma_scale`**（`--ab-smoke-sigma`）同时压低烟厚与烟亮。
   按「上半 ROI 亮度对齐参考」扫出的初值：**`smoke_sigma_scale = 0.05`，
   烟受光色 `(0.46, 0.55, 0.88)`**（偏冷，对齐参考的灰蓝烟）。

   ⚠️ **真 bug（已修）**：最初自发光乘的是**总** `a`（含烟），而 `Blackbody()` 为防 NaN 把色温
   **clamp 到最低 1000K** ⇒ 烟区 `G=0 → 0K → clamp 1000K → 橙色` ⇒ **烟被渲染成火色**。
   诊断法：`--ab-emis 0`（关火自发光）单独渲染——烟自己确实是灰的 (88,90,94)，全图却 (159,117,96)。
   改成 `a_fire` 后：前景均值色 **(159,117,96) → (100,96,97)**（中性灰），与参考的灰烟一致。
3. **调参口**：`--ab-sigma / --ab-emis / --ab-smoke / --ab-light r,g,b`（便于扫参与复现）。

## 5. 已知简化（P0 范围内，不阻塞）

- A/B 火盒用**资产真实尺寸（各轴独立）**，**不做等比/立方盒**——立方盒会把非立方资产各向异性
  拉伸（P0 曾把 1.32×1.92×1.32 拉成 1.92³，x/z 放大 1.45× ⇒ 火“偏宽”）；另加取景下移 `--ab-y-shift`
  （默认 -0.10）对齐参考基线。两者均为**纯取景**，不动资产数据。
- A/B 用**正面固定相机**，与官方透视未做严格透视匹配；形状指标（h/w、剖面）
  不受影响，像素级对齐留到需要时再加。
- 参考帧**缩略入库**（供肉眼比对与仓库体积控制）；像素指标以缩略后双方同法计算，
  口径一致。
