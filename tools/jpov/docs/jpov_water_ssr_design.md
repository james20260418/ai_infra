# 水皮 SSR（水面倒影）设计 — 2026-11-27

> 范围：**水皮 V2 + 相机在水上**。V1 与水下支路不动（它们没有"镜面项 = 天光探针"这个前提）。
> 装置：`src/ssr/ssr_chain.h`（PR #279 的产物，**本 PR 一行没改**）。

## 1. 它解决什么

水皮此前的镜面项只有**天光探针**：`F · textureLod(uEnvCube, reflect(rd, N))`。
探针里没有岸、船、立柱、桥 —— 水面永远只倒映一片天。本次把这一项改成

```
refl_i = mix( env_i , L_ssr , A )        // 逐样本（F 逐样本，mean(F·E) ≠ mean(F)·mean(E)）
```

`L_ssr` / `A` 由 SSR 装置给出：`L` = 命中辐亮度，`A` = 覆盖率（命中覆盖 + 掠射/预算/贴边淡出 +
升采样软权）。于是：

- `A = 0` ⇒ **逐字节**等于旧的纯探针（单调改进，gold 兜底）；
- `A` 连续 ⇒ 兜底是逐像素连续的，没有"SSR 区 / 探针区"的接缝；
- 太阳的像（解析 GGX）一行不动（探针不含日月盘，SSR 也不负责它）。

## 2. 管线位置与三步顺序

```
不透明 3D ─┬─ 属性 pass（视空间法线）
           ├─ 实心 SSR（合成写回 HDR）
           ├─ 粒子 / 条带（WBO，不碰 HDR）
           ├─ ① 水皮 query 趟   ← 只算几何：水面窗口深度 / 视空间中心法线 / rough
           ├─ ② SsrChain #2     ← Source = 上面那三张实心纹理，Query = 水面的
           └─ ③ 水皮着色趟      ← refl = mix(env, L, A)
                              ↓
                        介质合成（不动）
```

**① 为什么必须新开一趟**：装置要在**着色之前**读到"水面在哪、朝哪"，而水皮是解析求交、
没有 G-buffer；它自己 WBO 里那条深度是着色**之后**才有的（时序上用不了）。
这一趟就是水皮的 G-buffer，成本 ≈ 一次求交 + 一次法线求值（**不跑 S 个样本、不算着色**）。

**② Source 的复用**：`Source` 就是实心 pass 用完的那三张纹理，不额外拷贝 ——

| 字段 | 纹理 | 语义 |
|---|---|---|
| `color_tex` | `color_tex_hdr_` | 已含实心 SSR 的修正；粒子/条带走 WBO 不碰它 ⇒ **天然"只有 3 实心"** |
| `depth_tex` | `scene_depth_tex_hdr_`（MRT#1） | 只有不透明几何 |
| `normal_tex` | `ssr_attr_tex_` | 视空间法线（非反射体写 a=0.5 也够用） |

代价：装置内部要再跑一次**源降采样**（半分辨率一个全屏 pass）。刻意没有给装置加
`PrepareSource()` 缓存 —— 那会引入"同一份 Source 只允许 prepare 一次"的隐式契约，
等实测证明这一步有成本再说。

**属性 pass 的闸门放宽了**：它原来"本帧一个 `ssr_reflector` 都没有就整条跳过"。
水皮要的是**遮挡物**的法线（射线会不会扎进某张面），与有没有镜面地板无关 ⇒
`DrawSsrAttrPass(..., need_for_source)`。

## 3. query 趟的三个口径（每个都可能整体错位，且"看起来还能用"）

| 输出 | 口径 | 错了会怎样 |
|---|---|---|
| 窗口深度（R32F） | 与水皮着色同一份 `s.t` → `1/z` 窗口深度（`(f+n−2fn/z)/(f−n)` 再 ×0.5+0.5） | 射线起点整体飘 ⇒ 倒影整体错位 |
| 视空间法线（RGBA16F，a=1 有水面） | 行 = `side / up / −fwd`，与属性 pass 的 `uWorldToView` **同源** | 反射方向被整体旋走（11-24"暗物倒影被天光洗白"是同一类错） |
| rough（RGBA16F，只读 .a） | 由**同一份 σ**（`√normal_var_px`）换算：2σ → 屏幕像素 → SSR 像素 → mip 级（`log2`），上限 0.35 | 太小 ⇒ 倒影满屏跳；太大 ⇒ 远处整片糊成探针 |

水皮之外的一切（F、多散射增益 M2、太阳像、α）都不变。

## 4. 参数（`WaterCommand::ssr`，`DefaultWaterSsrConfig()`）

**与 `cmds.ssr` 是两个独立实例**（水面的正确值与地板差得很远：几乎总是掠射、反射距离长、
没有逐像素材质）。默认**开**。`SsrConfig → SsrParams` 的映射抽成 `src/ssr/ssr_params.h`
（一份，两个消费端共用，避免"加一个旋钮改两处、漏一处静默不同步"）。

与实心不同的默认值：

| 字段 | 水皮 | 理由 |
|---|---|---|
| `roughness_cutoff` | **1.0** | 水面的 rough 已按波浪方差逐像素算好；再按阈值跳过射线 = 把远处倒影整片扔掉 |
| `max_distance_m` / `max_ray_pixels` | 1000 / 220 | 水面上的反射都很远（岸/船） |
| 三个遮丑滤波器 | 关 | 它们是为金属调的形状，先按原样看 |

## 5. query 法线：钳到地平线（默认开）+ 可选谱截断

### 5.1 为什么掠射水面的 query 法线需要特判

掠射时反射方向的仰角 `R.y = |rd.y| + 2α`（α = 波面朝相机的倾角）。α 为负的那一半波面会让
`R` **指到水面以下** —— 物理上那是"反射到别处的水"，而屏幕空间里既没有别处的水的颜色、
也没有它的深度（源只有不透明几何）⇒ 这些射线只会在屏幕里撞到**海底**或落空。
实测比例：10° 掠射 11%~12%、45°/5 m 2.3%、45°/40 m 2.9%（调试档 22 直接给这个判据）。

着色趟的 env 路径对此早有处理：`ClampReflectionAboveHorizon` 把方向抬到 +1°。SSR 这一侧必须
同口径，否则同一个像素上两条反射路径描述的是两个不同的世界。

### 5.2 做法：只钳方向，再反解法线

```
R  = reflect(rd, N)
if (R.y < sin 1°)  R ← ClampReflectionAboveHorizon(R)     // 与 env 同一条
N  = normalize(R − rd)                                    // 单位向量时反射对称 ⇒ 精确反解
```

于是查询法线的反射方向 **y 分量半正定（≥ sin 1°）**。这是刻意的"非物理法线"：只要 R 本来
在地平线以上，波纹对倒影的扭曲**原样保留**；只有"要反射到水下"的那些像素被抬到地平线。
开关：`WaterCommand::ssr_clamp_normal_above_horizon`（默认开，面板/A-B 可关）。

实测（cam20_25m，船 96 m）：

| | 全图高频噪声 HF | 倒影带变暗（信号） | 全图 \|Δ\| |
|---|---|---|---|
| 关钳位 | 0.57 | 23.1% | 3.99 |
| **开钳位** | **0.14** | **24.4%** | 0.84 |

⇒ 噪声 -75%、倒影强度不变，同时把"反射到水下/海底"的整片杂散贡献去掉了
（`|Δ|` 从 3.99 掉到 0.84 就是这个）。判据测试：`QueryNormalClampKeepsRayAboveHorizon`
（关掉钳位时必须存在低于地平线的像素，否则测不出东西）。

### 5.3 谱截断（`ssr_normal_truncate_px`，默认 **0** = 不截断）

同一件事的另一条路：query 趟复用波浪谱**已有**的截断机制（`ResolveWaveTruncation` /
`uWaveTruncatePx*`），让波长 < 3T~8T 像素的波不进 query 法线。

| T | 噪声 HF（带内） | 倒影带变暗 |
|---|---|---|
| 0 | 2.00 | 23.1% |
| **4** | 2.76 | 32.8% |
| 8 | — | 35.5% |

截断让倒影"更成块"（更多像素真的打在船上），代价是**丢掉倒影的波浪扭曲**；而铺开钳位之后，
它的边际收益在倒影带内几乎为零。所以**默认 0**，只留成 A/B 旋钮（Danis 2026-11-27：
"最不济我可以接受这个谱截断，但不太希望这样做，损失细节"）。

## 5.4 未解析的细节波怎么补：**只准改"糊多少"，不准改"在哪"**（2026-11-28 定案）

### 5.4.1 结论先行（Danis 2026-11-28 报障后重定）

曾经实现过"图像域补偿"（方案 A 的第一版，已全部删除）：
`Δn = N_全谱 − N_截断` → 消失点位移（把倒影整体滑一段）+ 3-tap 展宽（沿位移方向拉丝）。
验收时暴露两个不可修的现象：

1. **幽灵倒影**：船**上方（更远）**的水面出现船的倒影。机制：SSR 的 `(L, A)` 是"**这个像素
   自己的那条射线**打到了什么"的事实，`A` 的边界就编码了"这里打不打得到船"；把**采样位置**
   挪走却不重新求交 = 把船那格的事实搬到没打到的像素上。图像域 warp 与几何脱钩，无解。
2. **漏光**：该显示水体/环境的像素被邻域的亮命中抹亮。机制：3 个 tap 取**非预乘**的 `L`、
   `A` 单独平均（`mix(env, ΣL/3, ΣA/3)`），且展宽半宽 `2σ/θ_px` 在掠射时远超上限、**恒定顶在
   8 px** ⇒ 等于全屏 ±8 px 盲抹；而装置的输出里没有命中距离，任何滤波都无法判断"是不是同一块
   几何"。

**业界同样的坑**（不是我们实现没调好）：UE 的 planar reflection 用**完整镜像场景图**做 UV 扭曲，
仍然要额外提供 `Extra FOV`（"when normal distortion is causing reads outside the reflection texture"）
和 `Render Scene Two-Sided`（"hide artifacts where normal distortion would read under an object …
backface instead of the background which is potentially a bright sky"）。也就是说：扭曲只能在
**有正确数据的地方**读；我们做的是 SSR，本来就没有那份数据。

### 5.4.2 现在的做法：未解析斜率 → 粗糙度（方案 A）

判据一句话：**倒影的位置由解析得出的主法线决定；未解析的部分只贡献"宽/糊"。**

链路（全部已存在，本次只是把上面那层删掉）：

```
谱截断截掉的斜率 w = ½(kA)²·(1 − geom²)      // 主波 + 细节波都算，见 WaveSlopeTensor
        ↓
σ = sqrt(var_p + normal_var_px)               // 视线投影方差 + 像素内法线方差
        ↓
query 趟 rough.a = clamp(log2(2σ/θ_px / scale) / roughness_to_lod, 0, rough_max)
        ↓
装置：覆盖率预乘 mip 链（rgb = Σ(w·A·L)/Σ(w·A)，a = 覆盖率）
      + 双边升采样（1/z 屏幕仿射预测 + 法线夹角做值域权，超 hard_cut 硬拒）
        ↓
反射空间的模糊（跨剪影不会串色，A 随 mip 一起下降 ⇒ 边界自然软化）
```

两个**旋钮**（面板 + CLI，都是 `SsrConfig` 的既有字段）：
- `roughness_to_lod`（默认 8）：每单位 roughness 换几级 mip，越大越糊；
- `roughness_cutoff`（水面默认 1.0 = 从不跳过）：超过它就不发射线、直接交回探针 mip。
  "宽到单条镜面射线表达不了"的情况交给探针（完整球面，不漏光、无屏幕边界）。

另外 M1（`a2 = min(盘角² + footprint_a2 + 2·normal_var_px, 0.25)`）负责**高光**侧的同一条方差，
F_eff / α 负责能量侧 —— 三处吃的是同一份 σ，别合并、也别再加第四份。

### 5.4.3 判据（测试怎么锁）

- `water_ssr_gpu_test::QueryRoughCarriesTruncatedDetailVariance`：
  平水面无波 ⇒ rough 恒 0；一条长主波 + 两条**亚像素**细节波 ⇒ rough > 0
  （否则"被截掉的斜率没进粗糙度"= A 路线失效，而且画面表现为倒影突然变锐/出噪）。
- 反例（负向验证）：把 `rough_max` 设 0 ⇒ 该测试红。
- 视觉验收：船上方不该有倒影；倒影带里"远/模糊、近/清晰"，且暗区不被抹亮。

### 5.4.4 如果以后还要"倒影被水纹掰弯"

只能在**射线上**做，不能在图像上做：每像素 2~3 条按 `Δn` 抖动法线的射线各自真求交，再按 A
加权合成（Frostbite stochastic SSR 的穷人版），并需要装置额外输出命中距离做跨剪影拒绝。
代价是射线数 ×N，且没有 TAA 时会有噪声 —— 本项目暂时不做。

## 6. SSR 的命中语义（回答"反射线进了物体算不算 miss"）

- 命中判据是"射线在一个屏幕格里跨过了该格的深度筒"（厚度 = 同面并集 ∪ c·T ∪ t_min）；
- 朝向判据 `SsrHitFacing` = `dot(R, N_hit) < 0` ⇒ **扎进面**才是"正经正面命中"（立刻结束）；
- `dot ≥ 0`（从背面穿出）不算正面命中，但会作为 backface 候选**照样输出颜色**，
  只多一个 flag（由消费端决定用不用；水皮不用这个 flag）；
- 真正的 miss 只有三种：空格子（天空，射线穿过去，`kEmptyCell` 的反例保证不会当成远墙）、
  射线与该格深度差落在厚度筒之外（薄几何）、出屏 / 预算用尽。
- 实心 pass 不会"命中自己"：起点 `P += N·(d·1e-3)`，且 DDA 在 `start <= 0` 时**主动跳过起点格**；
  三个厚度源都只往"更远"扩（取 min）。实心对应的 artifact 是掠射自交梳齿，那是同面并集柱体要治的。
- 水皮不存在自交（水面不在源深度里）；代价是"水面反射水面"没有数据，只能回退探针。

## 7. 已知边界（都不是 bug）

1. **屏幕空间**：只反射**在屏幕上**的东西。所以 45° 俯视的默认机位里远处的船不在画面内 ⇒
   它的倒影也不会出现（这是 SSR 的定义，不是漏实现）。海景要看得用 10°/25° 的掠射机位。
2. 反射源不含条带 / 粒子 / 水皮自己 ⇒ 不会有"水里有水"、倒影里没有体积火。
3. 反射方向用**中心法线**（S 个样本只作用于太阳的像）。像素级高频波浪会让倒影"跳"，
   由 rough→mip 的模糊吸收；S 取 4 已经超出 SSR 能表达的分辨率（Danis 2026-11-27 判断）。
4. 水下支路（TIR + 深海积分）与 V1 完全没动。
5. 链路成本按**全屏面积**算，不是只算水面像素。
