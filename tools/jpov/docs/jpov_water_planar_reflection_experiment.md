# JPOV 水面（平面反射 B 方案）— 实验总结（2026-10-28）

> **状态：实验备份，不并入 main。** 分支 `feature/20261027-jpov-water-strip-quad`。
> 目的：把"水面长什么样、代价多大、哪些坑必须先填"这件事一次探清，下一轮按正经工程设计重做。
> 本文只记录**已验证的事实**（数字都是实测），不写设想。

---

## 1. 一句话结论

**水面 = 一块无限大的水平平面（逐像素求交）+ 平面反射（镜像相机重画不透明场景，
倒影天空用 `kEnvReflect`：大气 + 月盘/月晕、不含日盘）+ 解析 GGX 日盘高光/日晕 + Bloom。**

观感可用、物理基本自洽；**剩下的问题都是"要不要为它付这份成本"**，而不是"能不能做对"。

## 2. 交付形态

| 项 | 内容 |
|---|---|
| pass 位置 | froxel（点状雾）合成**之后**、highlight/bloom/tone map 之前，**独立子 pass**，就地 alpha 混合进 HDR FBO |
| 几何 | **无限平面**：全屏三角形（`gl_VertexID` 生成，无 VBO）+ FS 里解"视线 ∩ y=level" |
| 反射 | 镜像相机 + **斜近裁剪面 = 水面本身**（Lengyel），渲到独立 HDR FBO（RGBA16F + MRT 场景深度 + 24 位深度），天空输出 `kEnvReflect` |
| 采样 | `uv = 投影(水面点, 镜像VP) + vec2(N.x,N.z)·distort`，**fwidth 4 抽头**抗锯齿，投影出界按覆盖度淡回天空探针 |
| 太阳 | 解析 GGX 微表面：`α² = 未解析斜率方差(LEAN 二阶矩)×增益 + 日盘角半径²`；方向取**可见盘**（`ActiveDiscDirection`，日/月通用） |
| 日晕 | 与天空 `discGlow()` 同款 exp，**各向异性**（size / aspect），σ 用斜率方差加宽，强度按 `DniFactor(elev)/DniFactor(90)` 同步衰减 |
| 波浪 | 256² × **32 帧** 斜率+二阶矩图集（16 m tile），GPU mip + 各向异性 8×，**帧间线性插值** |
| 其他 | Bloom（太阳路的"晕"）、相机 HUD（报缺陷用） |

参数面板（水面场景）：天光仰角 / LEAN 开关+增益 / 日晕大小+长宽比 / 镜面天光 / 水下透射 /
太阳高光 / Bloom / 水 n / 水纹相位·波幅·波长·方向 / 最小透射（实验）。

## 3. 三个关键决策与理由（下一轮别重新论证）

### 3.1 为什么是"无限平面"而不是有限 quad
有限 quad 不管多大，都会在**它的远端边界 ↔ 真地平线**之间漏出天球下半球的 `ground_color`。
而且这在几何上无解：眼高 1.5 m 时地平线在 4.4 km、1.5 km 高时在 138 km（顶点距离 → ∞）。
⇒ 只能逐像素求交。副产品：没有"水面尺寸"这个参数了。

### 3.2 为什么选 B（倒影不含日盘 + 解析太阳）而不是 A（倒影带盘、纯镜子）
- A 的问题：日盘在倒影贴图里只有 ~11 px，靠 uv 扰动拉不出"太阳路"，扰动加到 0.15/0.35 才出现
  断续"碎镜片"。**单点采样 ≠ 对斜率分布的卷积**，高频亮源必然碎。
- B 的问题：需要解析项，且必须与倒影**互不重叠**（同一个太阳不能出现两次）。
- 视觉评审排序：**B > A(d=0.35) > A(d=0.15) > A(d=0.02)**（Danis 定 B）。

### 3.3 为什么不用硬件 mip 抗锯齿
给倒影纹理开 `MIN_FILTER=LINEAR_MIPMAP_LINEAR` + 每帧 `glGenerateMipmap`（RGBA16F）
⇒ **整帧画黑**（连不用水的模型场景都黑，且无 GL error）。这是 llvmpipe 的坑，实测两次。
⇒ 抗锯齿改为 shader 内 `fwidth(ruv)` + 4 抽头。

## 5. 踩过的坑（每条都是真金白银，下一轮直接避）

1. **相机基手性**：镜像相机的 `up'` 必须是 `cross(right, fwd)`；写成 `cross(fwd, right)` 得到 `−up`，
   表现是"整屏一个像素都不画"（不是画错位置）。诊断法：把 `discard` 换成纯色 `return`，一眼看出上下颠倒。
2. **斜近裁剪面**：不把 near 平面换成水面，水下盒子会出现在倒影里（镜像相机在水面下）。
   公式 `z' = α·(c·v) − w`、`α = 2·far/(c·v_far)`；用"水下点应被裁、水上点应保留"做数值验证。
3. **`uSunColor` 与方向必须分开上传**：把颜色写进 `else if` 分支 ⇒ B 路线高光整项失效（Danis 一眼看出）。
4. **探针下半球是"陆地"语义**：掠射反射被波面按到地平线以下 ⇒ 采到暗地色 ⇒ 天际线黑边。水面必须自夹。
5. **bloom 的 draw buffer**：`glPushAttrib(GL_COLOR_BUFFER_BIT)` 存的是当时 FBO 的 draw buffer；
   `glPopAttrib()` 必须先绑回**同一个 FBO**，否则把 `COLOR_ATTACHMENT0/1` 还原到默认帧缓冲 ⇒ GL 1282。
6. **llvmpipe + RGBA16F + mip 生成 = 整帧黑**（见 3.3）。
7. **HUD/UI 必须假设"可能没有字体"**：gold 测试的 App 不注册字体，画 CJK 直接 FATAL
   （`jpov_pcf_shadow_gold_test` 被打到过）。
8. **`fbo_3d_w_` 在 HDR 路径是 0**（只有 LDR 的 `Ensure3DFBO` 写它）—— 依赖它做尺寸会静默拿 0。
9. **Xvfb**：跑 GPU 测试前自己起 `Xvfb :99 -ac +extension GLX +iglx`，用 `--test_env=DISPLAY=:99`；
   否则每个测试各自抢 `:99` ⇒ 大面积假红。
10. **交付**：`output/` 的二进制必须与 `bazel-bin` 对 md5（跑 `build_jpov_skylight_viewer.sh`）。

## 6. 已知问题 / 未做（下一轮的正经清单）

### 6.1 正确性 / 观感
- **马赛克残余**：倒影采样已用 4 抽头压制，但相位扫描里仍有局部突变尖峰（4498→4362、2573→2456），
  未归零。已排除：tile 各向异性、flipbook 帧插值。怀疑最快八度（cycles=7）在 0.04 相位步下走了 ~16°，
  属真实运动；**需要一个"高光能量守恒"的量化判据**（亮度总和 + 直方图偏移），不能只看眼睛。
- **倒影只含不透明 3D + 天空**：粒子、体积火、条带、froxel 雾都没进去（各自有自己的 WBO/FBO 目标，
  要参数化目标 FBO 才能一起拍）。
- **采样扰动是经验量**（`refl_distort`）：没有按斜率做透视一致的推导；掠射会拉伸。
- **单张 16 m tile 会重复**（远处能看出周期），工程上要叠 2~3 个尺度/方向不同的 tile。
- **无吸收/散射**（"绝对干净的水"），水下物体只是被一层淡色膜按 α 混掉。
- **全分辨率倒影**：未做半分辨 + 粗糙度 mip；没做 tile culling（倒影 pass 里关掉了，走全光源）。

### 6.2 物理口径（有意为之，别当 bug 追）
- 倒影天空 `kEnvReflect` **不含日盘/日晕**（防与解析项双计），**含月盘/月晕**（夜里月亮就该是镜子里的像）。
- 高光/日晕方向跟**可见盘**（`discDirRemap` 之后），不是真实太阳方向 —— 为了与肉眼看到的盘对齐。
- 夜里高月亮 + 浅视线**没有月光路**是几何必然（需要 28° 波面倾角，我们只有 10°）。

## 7. 下一轮建议（正经版）

1. **先定需求边界**：只做"看得到海"的观感，还是要吸收/散射/泡沫/岸线？（后者是另一套介质管线）
2. **倒影管线参数化**：把"目标 FBO + 是否含粒子/雾"变成 pass 参数，倒影才能"拍下几乎所有东西"；
   顺便支持半分辨率 + 粗糙度链。
3. **采样模型**：把"投影 + 斜率扰动"换成"投影 + 按斜率分布的多抽头/重要性采样"，并把扰动强度做成
   `tan(slope)` 的解析式（现在是经验常数）。
4. **波浪**：多尺度 tile 叠加（打散重复）+ 逐八度的时间插值（现在整条时间轴共用 32 帧）。
5. **能量判据**：给水面做一个"相位扫描能量守恒 + 频谱稳定"的自动化 gold（这次是肉眼 + 像素计数）。
6. 若继续保留解析太阳：把"日盘角半径"接进 `SkyCommand`（现在硬编码 0.00465）。
