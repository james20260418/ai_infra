## 0. 一句话

在**主帧已画完的不透明颜色 + 深度**上，对每个像素沿镜面方向做**屏幕空间体素行进**，精确给出「这个像素应该反射到哪一格」；拿不到的部分**如实报告不知道**（A=0），由消费端回退到既有的环境镜面项。

---

## 1. 目标与非目标

### 1.1 目标

| 目标 | 含义 |
|---|---|
| **确定性** | 同输入 ⇒ 逐字节同输出。无历史、无抖动、无时序、无随机。可进 gold。 |
| **廉价** | 成本 ∝ 镜面像素面积，**与镜面数量无关**（一个不透明像素只有一条射线）。 |
| **不猜** | 模块只报事实（命中 / 拿不到）。厚度是唯一允许的假设，且只有**一个**参数。 |
| **可组合** | 与分辨率无关：调用方任选分辨率调用，模块内部不降采样、不升采样。 |
| **零副作用** | 不读环境探针、不写 HDR、不改输入、不读自身输出。 |

### 1.2 非目标

- 不做透明/半透明物体的反射（它们不写场景深度，且会污染颜色）。
- 不做多次弹射（一次弹射即止）。
- 不做时间累积 / 降噪 / 半分辨率重建——这些是 TAA 时代的手段，JPOV 写死「每帧从零构建」。
- 不做屏幕外内容的重建（那是另一类技术，见 §10）。

## 2. 模块契约

```cpp
// ── 输入（全部只读）──
struct SsrInputs {
  // 反射源：不透明 3D 已画完的 HDR 颜色。
  // 必须在「半透明/粒子/雾/Bloom 之前」，否则倒影会吃雾或含半透明的自己。
  unsigned int color_tex;          // RGBA16F
  // 场景深度：MRT#1 的 gl_FragCoord.z（R32F）。必须与 color_tex 同采样点。
  unsigned int depth_tex;
  // 反射体的视空间法线 .xy（z 由 sqrt(1-x²-y²) 重建，z>0 朝相机）。
  // 水面要的是波浪扰动后的法线，所以必须走纹理而不是从深度求导。
  unsigned int normal_tex;

  float near_plane, far_plane;
  float tan_half_fov_y, aspect;

  // 厚度模型：T = thickness_coefficient * d_hit（见 §5）
  float thickness_coefficient;     // ≈ N_px · 单像素角度，典型 0.006 ~ 0.012
  float min_thickness_m;           // 数值下限，防 T→0（不是物理量）

  float max_distance_m;            // 射线长度上限（建议 = far）
  int   max_steps;                 // 成本上界（与正确性无关，见 §4.5）
};

// ── 输出（模块内部分配，懒创建，尺寸变化时重建）──
struct SsrOutputs {
  // 与输入同分辨率、1:1 像素对应。
  //   rgb = 镜面方向命中处的颜色（RGBA16F，HDR、未加雾、未 tonemap）
  //   a   = 1 表示「这是屏幕数据给出的答案」；0 表示「拿不到」（见 §6）
  unsigned int radiance_tex;
};
```

### 2.1 契约（逐条，实现时照抄）

1. **分辨率一致**：输入什么分辨率，输出什么分辨率；内部不降采样、不升采样。分辨率选择是调用方的成本旋钮，模块不感知。
2. **`rgb` 是纯辐亮度**：不乘 Fresnel、不乘 `F0·A+B`、不乘 AO。调用方**乘一次、只乘一次**。
3. **`a == 0` 时 `rgb` 无意义**（写 0 只是避免未初始化内存）。**禁止**用 `rgb == 0` 判断状态。
4. **模块不读环境探针**。`a == 0` 的兜底、以及任何「柔和过渡」都归 composite，避免环境镜面项出现第二份实现。
5. **决定论**：同输入同输出；无历史、无抖动、无时序、无上采样。
6. **不改输入、不读自身输出**（同一 pass 内读写同一张颜色纹理会产生反馈环）。
7. **成本可解析界定**：`O(log 屏幕长度)` 次金字塔采样 + 常数次叶层操作，硬上界 `max_steps`。**步数只影响性能，不影响正确性。**

### 2.2 本版不接收 mask

模块对**全屏每个像素**各发一条射线，成本 ∝ 屏幕分辨率（不是 ∝ 镜面面积）。
这是刻意的：契约要能一句话说完（「给每像素一个镜面方向上的颜色」），而 mask 属于策略。

将来若需要「按镜面面积计费」，加一个 `mask_tex` 是**纯优化**（`mask == 0` ⇒ 直接写 `a = 0`、不发射线），不改变语义、不改变契约其余部分。

## 3. 几何基础：屏幕空间射影几何

### 3.1 三个量对屏幕弧长 σ 的依赖（必须分清）

视空间 `d = −z_view > 0`，`z_ndc = A − B/d`，其中 `A=(f+n)/(f−n)`、`B=2fn/(f−n)`。

沿屏幕足迹用参数 σ（像素弧长）：

| 量 | 对 σ 的依赖 | 严格性 |
|---|---|---|
| 屏幕位置 `u, v` | **线性** | 射影把 3D 直线映成屏幕直线 |
| 世界/视距 `d` | **双曲线** `1/(aσ+b)` | 这就是「z 看起来不线性」的来源 |
| 深度倒数 `1/d` | **线性** | 恒等式，非近似 |
| NDC 深度 `z_ndc` | **线性** | `z_ndc` 是 `1/d` 的仿射函数 |

推导（可自查，也是硬件「透视正确插值」用的同一个恒等式）：

1. 3D 直线的视空间坐标与 `d = −z` 都是参数 `t` 的**仿射**函数；
2. 投影后 `ndc.xy(t) = (a + t·b)/(c + t·e)` —— 仿射除仿射 = **Möbius（分式线性）**，所以像**是一条直线**（形状），但参数化不是线性的；
3. 把 `q = ndc.xy` 反解回 `t`，再代入 `d = c + t·e`，得到 `1/d` 是 `q` 的分式线性函数；沿屏幕直线 `q = q₀ + σ·ê` 展开后，**`1/d` 对 σ 是一次的**。

一句话：**形状是直线（射影变换），参数化的非线性全部落在 `d` 上，而不落在 `1/d` 上。**

**实现含义**：

- 射线在格子内的深度区间端点用 `mix(1/d_in, 1/d_out, t)` 求是**精确**的，不漂。
- **绝不能用 `mix(d_in, d_out, t)`**。掠射时误差可达两个数量级（例：d 从 1 m 到 1000 m，中点真值 2.0 m，线性插值给 500.5 m）。

### 3.2 唯一破例：`d → 0`（射线穿过相机中心平面）

Möbius 在 `d = 0` 有极点，过了它投影点会翻到另一支，线性插值失效。所以：

```
若 R.z > 0（射线朝相机方向走）：
    rayLen = min(max_distance, (−near − P.z) / R.z)      // 裁到近平面前
```

数学极点其实在 `d = 0`，裁到 `near` 是更保守的工程裁剪（近平面内深度缓冲无有效数据）。**裁剪只缩短 σ 的取值范围，不破坏线性性。**

### 3.3 什么时候这条数学失效

| 条件 | 破坏线性性 |
|---|---|
| 线段跨过 `d = 0` | ✅ 必须裁 |
| 屏幕矩形裁剪 | ❌ |
| 任意 FOV / 宽高比 | ❌（只改方向） |
| 镜头畸变 / 鱼眼 / cube 面投影 | ✅ JPOV 是纯针孔，不涉及 |

## 4. 世界模型：体素桩（voxel pillar）

### 4.1 定义（这一句定义后面所有争论）

> **世界 = 每个屏幕像素对应一根从前表面 `z` 开始、厚度 `T` 的实心方柱（截面 = 该像素的屏幕足迹，沿视线方向延伸）。**
> **柱体内颜色处处相同，取该像素的颜色。**

不再使用「双线性深度面」。推论（这些都是模型的**性质**，不是 bug）：

- 没有背面信息（单层深度图没有）；「背面」只能被建模为「柱体到 `z+T` 为止」。
- 侧壁存在（柱体被挤出），且侧壁颜色 = 该柱的颜色。
- 阶梯：相邻柱的前表面可以跳变，模型不插值。

### 4.2 为什么选桩模型而不是双线性面（关键决策，别再重新论证）

当初选双线性的两个理由与它们各自的代价：

| | 双线性面 | **体素桩** |
|---|---|---|
| 平面精度 | 精确（`1/d` 对屏幕坐标仿射） | 半像素级（阶梯） |
| **命中判据** | 「求根 + 判断是否**留在**厚度带内」 | **「区间是否重叠」（是否**碰到**盒子）」 |
| 判据是否依赖每格穿透量 | **是** ⇒ `T` 被迫变成分辨率参数 | **否** ⇒ `T` 是纯几何量 |
| 侧壁 | 无（轮廓处是伪造的斜坡） | 有（真几何） |
| march 内是否有解方程 | 二次（每格） | **无** |
| 加速结构保守性 | min-mip = 角点 min（凸组合，成立） | min-mip = 叶子 min（**平凡成立**） |

**决定性证据**（同一组数字，相反结论）：

> 200 m 外的墙，每格穿透量 1.2 m，`T = 0.5 m`：
> - 双线性 + `g_exit ≤ T`：`g_exit = 0.95 > 0.5` ⇒ **判定穿过**（墙在倒影里变透明）。
> - 体素区间重叠：射线区间 `[199.8, 201.0]` ∩ 盒子 `[200.0, 200.5]` ≠ ∅ ⇒ **命中**。

原因：双线性判的是「是否留在带内」，体素判的是「是否碰到」。前者要求 `T >` 每格穿透量，后者与穿透量无关。**这是放弃双线性的真正理由**——不是精度，是判据的鲁棒性。

### 4.3 代价（已知、可接受）

| 代价 | 严重度 | 说明 |
|---|---|---|
| 平面精度 → 半像素级 | 低 | 颜色本来就按格取，误差只影响「选哪一格」 |
| 颜色是最近邻（无插值） | 低-中 | 高对比倒影会略有锯齿；需要时可另做 2×2 抽取，但不要与几何重建混阶数 |
| 侧壁被涂成柱体颜色 | 低 | 轮廓外侧约 1 格宽的「正面色边缘」 |
| 掠射阶梯感 | 低 | 被「按格取色」部分抵消 |

## 5. 行进与命中

### 5.1 每格判据（整个 march 的核心，三行）

沿屏幕做 2D DDA（Amanatides-Woo），逐格：

```glsl
(z, T) = 该格的深度与厚度;
(d_lo, d_hi) = 射线在格子内的距离区间;        // 1/d 线性 ⇒ 端点是精确解；顺序按 min/max 整理

if (d_hi < z)      continue;   // 整段在盒子前方
if (d_lo > z + T)  continue;   // 整段在盒子后方（穿过去了）
return color(cell);            // 命中，取该格颜色
```

**三行里没有一次解方程。** 因为我们只需要知道**命中了哪一格**，不需要知道落在格内的哪个点——而颜色本来就按格取。

> 注：双线性版本那个「格内二次闭式求根」是为「命中在格内多精确」服务的，而那个精度对最终颜色没有贡献。桩模型把这一整层需求消掉了。

### 5.2 命中后的颜色

`color(cell)` = 该格中心的颜色（`texelFetch` 或 `textureLod(..., 0)` 的最近邻）。**不插值**，与模型一致（柱体内颜色恒定）。

### 5.3 起点自交（必须处理）

射线起点就在反射体自己的表面上（`g ≡ 0`），任何数值抖动都会立刻命中自己。所以：

```
P += N * (d * 1e-3)      // 沿法线沿离，相对量（不是世界常量）
```

**这是数值卫生，与厚度 `T` 是两件事，不要合成一个常数。**

### 5.4 三态结算

```
HIT      : 某格的区间重叠             → rgb = 该格颜色, a = 1
SKY      : 全程在屏内、没碰到任何盒子 → a = 0 ★
UNKNOWN  : 出屏 / 出视锥 / 起点贴边   → a = 0
```

★ **SKY 输出 `a = 0` 是刻意的**：模块不持有天空探针（见契约 4），天空由消费端的
`EnvSpecularTerm` 给出，而那里对「真的什么都没有」恰好是正确值。若将来需要区分，
加一个**只用于调试**的原因位（`HIT / SKY / OFFSCREEN / TOO_SHORT`），不参与计算。

### 5.5 加速：Hi-Z（必须）

**跳过条件（保守、精确，用 `1/d` 而不是累加 `d`）：**

| 情况 | 条件 | 需要的金字塔 |
|---|---|---|
| **射线整段在格子前方**（水面最常见，占绝大多数跳过） | `d_hi < min_z(block)` | **min-mip** |
| 射线整段在盒子后方 | `d_lo > max_z(block) + T_max(block)` | max-mip（可选，次要） |

- 桩模型下 **min-mip 平凡保守**：每根柱是常数，块内 min = 叶子 min。不需要任何 padding 或重建修正。
- 水面场景 95% 的跳过来自第一条（反射射线往天上走，天上 `z = far`）⇒ **先只做 min-mip**。
- 每下探一级剩余格数减半 ⇒ **成本 O(log 屏幕长度)**，不是 O(像素长度)。
- `max_steps` 是硬上界，**只影响性能不影响正确性**（这条很重要：以后调性能不会悄悄改变画面，gold 不会被性能调优带崩）。

实现注意：GLSL 330 **没有 `textureGather`**（那是 4.00）；叶层取 4 个角/或 1 个 `z` + 1 个 `T` 用 `texelFetch`。

## 6. `A` 的语义：**覆盖率**，不是**正确率**

这是本文最容易被误解的一节。

| 错误类型 | 后果 | `A` 的表现 |
|---|---|---|
| 射线出屏 / 出视锥 | 没数据 | **A = 0（显式）** |
| 厚度 `T` 不对 | 误判命中 / 误判穿过 | **A = 1（静默）** |
| 单像素穿透量 > 物体厚度 | 薄物体不遮挡 | **A = 1（静默）** |
| 屏幕外的几何 | 倒影缺失 | **A = 0（显式）** |

**推论**：A 只回答「这次答案来自屏幕数据吗」，不回答「这次答案对不对」。厚度错误**永远不会**让 A 变 0——它是静默错误。所以：

> **`A` 不是质量指标，是覆盖率指标。** 用它做统计（「我的倒影有多少是真的算出来的」）有效，用它做正确性担保无效。

## 7. 与既有环境镜面项的关系（兜底）

消费端（composite）唯一知道材质的地方：

```glsl
vec3 base = EnvSpecularTerm(N, V, roughness, metallic, base_color);  // 既有的 IBL 探针项
vec3 L    = mix(base, ssr_radiance, A_soft);                          // 见 §8
color += (F0 * AB.x + AB.y) * ao * L;
```

`EnvSpecularTerm` 在 `uEnvEnabled == 0` 时返回 0（黑），于是这一行**自动覆盖**两种底色：

| 场景配置 | base | 行为 |
|---|---|---|
| 开了 `env_specular`（现状） | 天光探针 | 过渡到 Env |
| 没开 `env_specular`（#228 之前） | 0 = 黑 | 过渡到黑 |

不需要分支。但必须在文档里写清一条配置警告：

> **在没有 `env_specular` 的场景里启用 SSR，`A = 0` 的区域会退化成纯黑**（等于回到金属黑块）。SSR 应视为「env_specular 的精确化」，不是它的替代。

**定位**：

```
SSR 在有屏幕数据的地方，用精确命中替换探针估计（严格更准）；
在没有数据的地方，原样退回 EnvSpecularTerm（等于今天的行为）。
⇒ 整体单调改进：最差情况 = 今天的画面，不引入新的失败模式。
```

## 8. 消费端：柔和与兜底（属于 composite，不属于本模块）

`A` 是 0/1，模块不平滑（「知之为知之」）。**柔和全部在消费端做**，因为只有消费端知道材质、知道这一帧的观感取舍。

### 8.1 三步流水

```
A₀ = ssr.a                       // 0/1，模块的原始答案
A₁ = median3x3(A₀)               // 去孤立混沌点（证据合并：邻域都说知道 ⇒ 这里就是知道）
A₂ = jointBlur(A₁, r ≈ 1~2 px,   // 生成过渡带
               range = same_surface)
L  = mix(EnvSpecularTerm(...), ssr_radiance, A₂)
```

- **不要用膨胀（max）**做软化：膨胀会让单个混沌点在它的半径内拥有满强度，正是要避免的噪点扩散。
- 中值还天然避免「两面相邻的镜子互相污染」——它只看 8 邻域，且范围项（`same_surface`）会拒绝跨轮廓。

### 8.2 `same_surface` 判据（一体性）

**不能用 z 的一阶差**（掠射平面 `Δz` 可达几个数量级），**光看法线也不够**（曲面镜的法线连续变化，会被切碎）。

正解是 **`1/z` 的二阶差分 + 法线**：

```glsl
// 沿 p → q 取三点 p, mid, q，令 w = 1/z
d2 = |w(p) − 2·w(mid) + w(q)| / max(|w(p)|, ε);

same_surface(p,q) = (d2 < εd) && (|N_p − N_q| < εn);
```

为什么二阶差分是对的：

| 情形 | `Δz`（一阶） | `w` 的二阶差分 |
|---|---|---|
| 掠射平面（z 从 1 m 到 ∞） | 巨大 ❌ | **≈ 0** ✅（`1/z` 对屏幕坐标仿射 ⇒ 二阶差恒为零） |
| 曲面平滑变化 | 中等 | 很小（∝ 曲率 × 步长²） |
| 轮廓处跳变 | 大 | 跳变量级 ✅ |

`(d2 < εd)` 处理轮廓与深度跳变；`(|ΔN| < εn)` 处理「深度连续但表面折起」（墙角、折边）。

### 8.3 这个判据同时是升采样的范围项

同一个 `same_surface` 用于（a）`A` 的联合模糊、（b）任何跨分辨率重建的颜色加权。**一个概念、一个实现**，不要写两份——否则主路径与升采样路径的分叉症状极难定位。

### 8.4 过渡带宽必须随分辨率伸缩

```
厚度 T 大   ⇒ A=0 区域小 ⇒ 过渡带相对不显眼
厚度 T 小   ⇒ A=0 区域多 ⇒ 过渡带会在镜面上连成片
输出分辨率低 ⇒ 过渡带 = 1 个低分像素 = 2~4 个全分像素 ⇒ 相对更宽
```

所以带宽按**像素数**给，不按物理尺寸。

## 9. 厚度 `T`：唯一允许的假设

### 9.1 为什么不做数据驱动的厚度（三条独立理由，全部否决过）

| 方案 | 否决理由 |
|---|---|
| **模型 AABB 沿视线跨度** | ① 蒙皮/变形物体要用**变形后**的 AABB ⇒ 把 SSR 和蒙皮管线耦死；② 非凸物体（椅子、碗、树）全变实心；③ 耦合本身就是债——每加一种变形/实例路径就多一处要同步 |
| **per-object 厚度** | 同上，且**插值出来的表面不属于任何物体**，厚度无定义 |
| **背面深度 pass（`z_back`）** | **技术上正确且零耦合**（正面剔除 + depth only，走同一条顶点管线，蒙皮自动对），但要一次额外几何 pass。**列为 §10 的首选扩展**，不是 v2 的起点 |

### 9.2 `T ∝ d`（本版采用）

```
T = clamp(c · d_hit, min_thickness_m, +∞)
```

- `d_hit` 必须是**命中点**的距离，不是反射体像素的，也不是格子平均值。在轮廓格内 `d_surf` 可以差 50 倍，用错端点 `T` 就错 50 倍。
- **`T ∝ d` 的好处：不需要物体身份**。「跨越两个不同深度物体时用谁的厚度」这个问题在这套模型下**不存在**。这是它比 per-object 方案好的地方。
- 在桩模型下 `T` 是**纯几何量**（因为判据是区间重叠，与每格穿透量无关），所以 `c` 只影响「允许多少拉黏」这一件观感的事。

### 9.3 `c` 的取值

```
c = N_px · θ_px        θ_px = 垂直 FOV / 屏幕高（弧度/像素）
```

`N_px` = 允许的拉黏像素数。1080p / 60° FOV 下 `θ_px ≈ 0.00097`：

| `N_px` | `c` | 观感 |
|---|---|---|
| 6 | 0.006 | 边缘较锐，薄物体略穿 |
| **10** | **0.010** | **默认，约 10 px 的拉黏** |
| 16 | 0.016 | 薄物体更实心，拉黏明显 |

**按 `θ_px` 折算意味着分辨率变化时观感一致**——不要写死一个绝对系数。

### 9.4 已知代价（如实记录，别当 bug）

| 现象 | 机理 | 处理 |
|---|---|---|
| **薄物体倒影被加粗** | `T > 真实厚度` | 恒定的 `N_px` 像素，可调 |
| **薄于单像素穿透量的物体不遮挡** | 屏幕空间固有边界（一格跨几米，看不见 3 cm 栏杆） | **接受**，这是分辨率边界不是模型缺陷 |
| 稀疏几何（树冠、栅栏）倒影成实心 | `T` 远大于叶/杆的真实厚度 | 接受；需要时走 §10 的 `z_back` |

## 10. 可选扩展（按性价比排序，本版不做）

| 扩展 | 解决什么 | 成本 | 备注 |
|---|---|---|---|
| **① 背面深度 pass（`z_back`）** | 厚度从假设 → 测量；薄片自动 `T≈0`；轮廓假命中消失 | 一次 depth-only pass（**无 CSM 包袱**：不采样阴影、不着色） | **首选**。注意它对稀疏几何仍然会把树冠算成实心（前后叶片之间的深度差） |
| ② 宽视锥低分辨率层 | 屏外缺失（水面 `A=0` 的最大来源） | 一次低分渲染 | 只服务「未知区」，可以粗、可以无阴影，所以不背 CSM 包袱 |
| ③ 第二层颜色+深度（depth peeling） | 被完全遮挡的背景 | 一次带颜色的额外 pass | 收益已明显递减 |
| ④ 场景三维表示（体素/SDF） | 全部 | 不同量级 | 那已经不是屏幕空间方法 |

**约束**：每加一层都在往「把场景重画一遍」的方向滑一步，而那条路的终点是已被否决的镜面相机法（见 §12 决策记录）。

## 11. 验收与测试计划

### 11.1 必须先做的两个 GL-free 单测（CPU，无 GL 上下文）

1. **`1/d` 线性恒等式**：随机 1000 条射线 × 随机 near/far/aspect/FOV，断言
   `mix(1/d₀, 1/d₁, t)` 反投影回视空间与真实 `P + R·(t·len)` 的相对误差 < 1e-6。
   **负向**：改用 `mix(d₀, d₁, t)`，掠射样本误差必须 > 100（证明测试真在测）。
   同时断言 `z_ndc` 线性插值与 `1/d` 线性插值互相一致。

2. **体素区间判据**：构造「厚墙 / 薄栏杆 / 轮廓跳变」三组解析场景，断言 HIT/PASS 的判定与解析结论一致。
   **负向**：把判据换成「首次跨越即命中」，薄栏杆那组必须红。

### 11.2 GPU 像素测试

3. **平面解析 gold**：平地 + 已知平面物体，断言命中**格**与解析解一致（桩模型下解析解是「哪一格」）。
   负向：故意把 `1/d` 换成 `d`，误差必须超阈值。
4. **确定性**：同一帧跑两次，输出逐字节相同。
5. **`A` 的三态**：构造「命中 / 出屏 / 起点贴边」三种像素，断言 `A` 分类正确（用调试原因位验证）。
6. **拉黏标定**：改 `c` 时，薄物体倒影的加粗像素数应**线性**变化（把「10 px」变成一个可断言的数量，而不是感觉）。

### 11.3 不做什么

- 不做性能 gold（llvmpipe 上的绝对耗时没有参考价值）；只断言 `max_steps` 不改变输出。
- 不把 `A` 的覆盖率做成固定阈值（它依赖场景内容）；只记录并观察趋势。

## 12. 决策记录（已经论证过、不要重新论证）

| 决策 | 结论 | 理由（摘要） |
|---|---|---|
| 双线性深度面 vs **体素桩** | **桩** | 命中原「是否留在厚度带内」依赖每格穿透量 ⇒ `T` 被迫成为分辨率参数；桩的原「区间重叠」与穿透量无关。见 §4.2 的墙/栏杆对照 |
| 厚度来自 **AABB** | ❌ 否决 | 蒙皮要用变形后 AABB ⇒ 强耦合；非凸物体全变实心；性价比最差 |
| 厚度来自 **per-object 数据** | ❌ 否决 | 插值表面无归属；且同样强耦合 |
| 厚度来自 **背面深度 pass** | ⏸ 延后 | 正确且零耦合，但要一次几何 pass；列为 §10 首选扩展 |
| **`T ∝ d`** | ✅ 采用 | 唯一不需物体身份的方案；在桩模型下 `T` 是纯几何量 |
| 模块内部**降采样** | ❌ 否决 | 分辨率是调用方的旋钮；模块内降采样会把「源分辨率」一起降掉（v1 失败的直接原因） |
| **升采样要法线+深度引导** | ✅ 记录 | 但真正关键的是**命中深度**而不是反射体深度（同深度相邻像素可反射完全不同距离的物体）；本版通过「调用方自己决定分辨率」绕开 |
| `A` 平滑放在模块内 | ❌ 否决 | 模块报事实，处置归消费端 |
| `A` 二值 vs 连续 | ✅ 二值 | 连续量由消费端用中值 + 联合模糊产生；「不知道」= `A≈0` |
| 兜底颜色用 **black** | ⚠️ 只在无 env 场景 | 黑是能量错误（像侧壁涂黑漆）；有 env 时兜底天光探针 |
| 兜底用**锐利天光** | ❌ | 结构错误（漏光）且常能量过高 |
| 射线路径 clamp（沿射线取最后一个有效点） | ⏸ 未采用 | 曾提议作为轮廓光环的修法；Danis 判断「A 交给消费端柔和 + 兜底」更稳，采纳该判断 |
| 48.6° 锥（Snell window）硬切 | ❌ 不做 | SSR 只管全角度算；衰减镜面项由用户负责。**若要切，必须连续过渡**（锥边界处 Fresnel 仅 ~4%，硬 `if` 会留下可见圆锥接缝） |
| **步数影响正确性** | ❌ | 桩模型下每格判定与步长无关；`max_steps` 只影响性能 |

## 13. 已知穿帮与边界（水面场景，按可见度排序）

| # | 现象 | 成因 | 是否本版解决 |
|---|---|---|---|
| 1 | **轮廓外侧一圈探针色**（倒影亮边） | 射线穿过轮廓后，它该看的东西不在屏幕上 | ❌ 属「屏幕外无数据」，见 §10②。在「物体后面是天空」时**自掩不可见** |
| 2 | 薄物体倒影恒定加粗 `N_px` 像素 | `T ∝ d` 偏大 | 可调 `c`，不可消除 |
| 3 | 地平线附近横向脏带/拉丝 | 掠射时 `1/d` 数值跨度大，射线贴着自己表面飞 | 起点沿法线抬高 + §8.2 判据 |
| 4 | 掠射时倒影锯齿/闪烁 | 几公里水面压进几像素，采样不足 | 分辨率固有；靠消费端足迹模糊吸收 |
| 5 | 稀疏几何（树冠）倒影成实心 | `T` 远大于叶片厚度 | §10① 也不能完全解决（前后叶片深度差） |

**正面结论**：水面是这类镜面里对 `T ∝ d` **最友好**的场景——反射内容以天空为主（探针即真值，薄模型的漏光被自掩）、反射物体多为大块竖向结构（不依赖厚度判据）、掠射时反射本应模糊（把 `N_px` 的误差吸收掉）。

## 14. 管线接法

```
① 不透明 3D pass
      → HDR color(RGBA16F) + MRT#1 场景深度(R32F)
      + 属性 pass 写 normal（反射体）/ roughness / F0 / mask
                    ↓
② （可选）box 金字塔：源 = HDR color 的副本
      ★ 顺带解决反馈环：SSR 采副本，composite 就可以原地写 HDR
                    ↓
③ SSR（本模块，分辨率 = 调用方决定）
      in : color, depth, normal, camera, c, max_distance, max_steps
      out: radiance.rgb = 命中格颜色；.a = 0/1
                    ↓
④ composite（全分辨率，唯一知道材质的地方）
      L = mix(EnvSpecularTerm(...), ssr.rgb, A_soft)
      color += (F0·AB.x + AB.y) · ao · L
                    ↓
⑤ strip → 粒子/体积火 → 雾 → Bloom → tonemap
```

**三条硬约束**（违反任何一条都会出难查的 bug）：

1. **④ 必须读副本/金字塔，不读正在写的 HDR**（否则同 pass 内读写同一缓冲 = 反馈环）。
2. **② 必须在 strip 之前**：strip 是半透明、不写场景深度、颜色会污染 ⇒ 进了反射源就是「倒影里有半透明的自己」。
3. **① 的源必须是未加雾的**：雾在 ⑤ 加，反射跟着反射体一起被雾化（近似但正确）；反过来会让远景倒影「跳出来」。
