## 0. TL;DR（急读版）

TPZ 是一条**逐像素**、**无世界网格**、**不依赖 TAA**的局部体积雾渲染线。三层，每层都是「有界工作量」：

1. **Tile 化**：屏幕切 tile，CPU 剪枝出每 tile **≤ K（16）个**雾体 → 给每像素一个 overdraw 硬上限。
2. **Per-pixel Z-segment 化**：每个像素在自己的可见列表上，把每团雾沿**未裁剪球弦**均匀切成 **M（默认 4）个 `fog_segment`**；**打散所有段 → 按 z 边界切"基本区间" → σ 加权 → 前到后合成**出该像素的 `(T_total, S_total)`。
3. **深度正确的屏幕空间高斯（可选后处理，v1 不做）**：blur 时只让**z 上真正共享**的部分相互作用。

一句话：**把 froxel 从「世界网格」拆成「屏幕 tile + 每像素稀疏 z 段」**。代价从「网格量化闪」换成「段级 popping + 后处理复杂度」，总负担更轻、也不吃 TAA。

**v1 范围 = L1 + L2。** L3 是第二阶段，先定性目标再上。

> **ZDist 扩展（2026-10-05 晚）**：L2 的段列表可**连续化**为**逐像素深度函数 `ZDist`**——两个**单调可加**的分段线性函数 `τd`（光学深度累积）+ `Ed`（源累积 RGB），≤8 控制点，末端积分得颜色，玻璃事件在积分时插入。屏幕空间高斯基于 ZDist 做**深度正确**混合。详见 **§14**。

## 1. 命名与业界定位

### 1.1 为什么叫 TPZ

`scrept` 业界给这类"把技术三要素压成一个词"的命名是有先例的：**froxel = frustum + voxel**（Bart Wronski / Frostbite，2014）。

**TPZ = Tile · Per-pixel · Z-segment** —— 正好命名本技术的三个轴：屏幕空间切块、逐像素、z 轴分段。简洁、可读、不与既有术语撞车。

备选名（记档，最终采 TPZ）：
- **Tiled Per-Pixel Deep Fog**（更描述性，但长）
- **Segmented Volumetric Fog**（会与"分段密度剖面"混）
- **PFZ / Deep Fog**（Deep Fog 与 Deep Shadow Map 易混）

> 模块名用 **`point_fog`**（Danis 定）：雾体"像点光源一样摆放"，与 `point_light` 对仗。
> 注：v2 文档曾倾向用 `sphere_fog`（图形学术语用 sphere 而非 ball）。**本线以 `point_fog` 为准**——它描述的是"摆放范式"（点状），形状仍可是球/柱。

### 1.2 业界对照（TPZ 不是全新发明，是已知零件的重新组合）

| 层 | 业界对应 | 出处 / 说明 |
|---|---|---|
| **L2 每像素 z 段表** | **Deep Shadow Maps** | Lokovic & Veach (SIGGRAPH 2000)。每个像素存一条**可见度函数**（分段表示，甚至自带 **tile directory**）。TPZ 的 per-pixel segment list = 雾版的 visibility function。 |
| L2 排序段表 | **Per-pixel Linked Lists (OIT)** | Yang et al. (NVIDIA, 2010)，每像素存**排序**的透明片元链表。 |
| **L1 tile 剪枝** | **Forward+ / Tiled Forward** | Olsson et al. 2012 / Harada 2012。按 tile 建 light list 限流，与 JPOV 现有 `BuildTileLightIndices` 同构。 |
| L1+L2 组合 | **Froxel 的近亲** | Wronski 2014。froxel 用世界网格；TPZ 用屏幕 tile + 每像素稀疏 z 段替代网格。 |
| L2 深度结构 | **Deep Screen Space / Deep G-Buffer** | Nalbach et al. 2014 等，屏幕空间保留"多层深度"的表达。 |
| **L3 深度敏感模糊** | **Cross-bilateral / depth-aware upsampling** | 体积雾降采样-再上采样的标准做法；TPZ 把它升级成"按 z 重叠"的深度正确版。 |

**TPZ 的主张**：把上面这些已知件**拼成一条不依赖 TAA 的逐像素雾线**，核心是 **L2 用"解析边界"（雾的几何）而不是"网格边界"** 来切 z —— 这正是它避开 froxel 格量化闪的根因。

## 2. 哲学：三层「有界工作量」

> Danis 原话（2026-10-05）：*"画家在考虑一个像素的颜色时，也不可能透视 20 多层，考虑特别多的合成。"*

渲染的复杂度必须**逐层封顶**，否则病态输入（1000 团重叠）会炸：

```
L1  屏幕空间 tile 化     →  每 tile 需要考虑的透明体 ≤ K     （横向封顶）
L2  像素上 z-segment 化  →  每像素参与的 fog_segment ≤ S_max   （纵向封顶）
L3  深度正确的邻域借鉴    →  每像素借鉴的邻居 ≤ 核宽           （滤波封顶）
```

三个封顶叠加 ⇒ **每像素总工作量有硬上限**、**无 TAA 也稳定**、**性能可预测**。这套"有界 + 确定"正是 JPOV 一贯口味（每步可独立自证、gold 图可逐字节复现）。

**与 froxel 的分野**：froxel 是"**先量化再积分**"（世界网格 ⇒ 格量化闪 ⇒ 强依赖 TAA）；TPZ 是"**沿雾的几何解析分段再积分**"（边界连续 ⇒ 天然不闪 ⇒ 不吃 TAA）。

## 3. L1 — Tile 化（屏幕空间剪枝 + cap）

### 3.1 职责

把"哪些雾体可能影响哪些像素"在 **CPU 侧**算成 **tile 索引表**（Forward+ 式）。全屏 pass 每像素只遍历**本 tile 的 ≤ K 个**雾体。

**K（tile cap）= 16**（暂定）。这是"每像素 overdraw 硬上限"，也是 L1 存在的**核心理由**——
纯包围几何 instanced（架构 A）无法在 shader 内自我限层，A 提供不了这个 cap。

### 3.2 继承 v2 的实现细节（不重复造轮子）

直接复用 `jpov_volumetric_fog_design.md §5`：
- 与 `object3d_renderer.cc` `BuildTileLightIndices` **同构**（`kTileSize=16/32`、每 tile ≤K、先到先得）。
- **索引 uint16**（不是灯的 uint8；雾要支持 ≥1000 团）。
- **切线锥解析覆盖**（球）而非 8 角 AABB：`sinθ = r/d` → 屏幕半径 `≈ (H/2)·(r/√(d²−r²))/tan(fovy/2)`，又快又紧。
- 覆盖**宁多勿少**（漏盖 tile → 漏光/暗带）。
- 属性走**缓冲纹理**（`texelFetch` 随机访问），不是 VAO。

### 3.3 TPZ 新增要求：**成员集必须稳定**

v2 没有强调的一点：**L1 的成员进出必须滞后（进易出难 / 滞后带）**。

理由：L2 的合成**不是纯加法**（见 §4.3），一个雾体突然进/出 tile 列表，其贡献**凭空出现/消失** → 屏幕上一条"缝"。而**缝是 L3 补不回来的**（缺一块，空间传播没法凭空补，见 §6）。

⇒ **L1 的稳定性本身就是"不闪"的一部分**，不能只当性能优化。

### 3.4 重要度排序（cap 取舍）

cap 满了丢谁 = 数组顺序 = **调用方预排**（与灯同一约定）。雾的 important = `σ·段长·屏幕覆盖`（≈ 对 τ 的贡献）。近处优先是合理近似。

## 4. L2 — Per-pixel Z-Segment（每像素 z 段）

### 4.1 `fog_segment` 数据模型

每团雾、每条视线，沿**未裁剪球弦**均匀切 M 份，产生 M 个 `fog_segment`：

| 字段 | 含义 | 单位 / 说明 |
|---|---|---|
| `z_min` | 段起点（视深） | **线性视深（米）**，与 CSM / scene depth 同基准 |
| `z_max` | 段终点（视深） | 同上 |
| `sigma` | 段消光系数 | 1/m，标量（v1 单 σ；不拆吸收/散射） |
| `color` | 段中心采到的**内散射亮度 `L_in`** | **Vec3(radiance)**，**不是已积分量** |

派生量（实现里预存，省重复 exp）：

```
L   = z_max − z_min
T   = exp(−σ·L)
S   = color · (1 − T)
```

**M 默认 4，可配置。** 采样位置 = **子片段中心**（中点法则，O(L²) 误差，软雾够用）。

### 4.2 每段属性怎么来

- **`z_min/z_max`**：球求交给弦 `[t0,t1]`；在其中按 `t0 + (i+0.5±0.5)·(t1−t0)/M` 切 M 段（细节见 §4.4 连续性）。
- **`sigma`**：用**衰减类型（profile）**在该段中心处求值（§7）。
- **`color` = `L_in`**：段中心世界位置 → **采 CSM 阴影**（sun×shadow 是高频项，必须逐像素；见 §7.2）→ `L_in = sun·shadow·phase + ambient + Σ点光`。

### 4.3 ⭐ 合成：先"打散 → 切基本区间 → σ 加权 → 前到后"

> Danis 原话：*"一个弦上的雾气叠加方式并不是满足加法法则的，因此强烈建议把 16 个雾气的 M 段打散后统一处理。"* ——**完全正确**，这条是本设计的正确性核心。

**关键事实**：**不同雾体的 segment 会在 z 上重叠**。此时**不能**"排序后顺序合成"——那等于把两团雾先后叠起来，顺序本身有歧义，且光学厚度稍大就偏。正确做法：

**Step 1 — 收集边界**：所有（裁剪后）段的 `z_min`/`z_max` 入池。
**Step 2 — 切基本区间**：排序去重 → 连续点对 `[a, b]` 构成"基本区间"，使**每个区间内所有覆盖它的雾都是均匀常数**。
**Step 3 — 区间属性**（σ 加权，**不是相加！**）：

```
σ_interval = Σ_i σ_i                 （覆盖该区间的所有段）
c_interval = Σ_i σ_i·c_i / σ_interval  （σ 加权平均，v1 单 σ）
T = exp(−σ_interval·L)
S = c_interval·(1 − T)
```

**Step 4 — 前到后合成**（透射率连乘，**非加法**）：

```
T_acc = 1;  S_acc = 0
for interval in z 升序:
    S_acc += T_acc · S_interval
    T_acc *= T_interval
L_out = L_scene · T_acc + S_acc
```

> ⚠️ **最容易写错的两处**：① 同区间多团要 **σ 加权平均 color**（不是相加）；② 合成是**乘性透射率 + 前到后**（不是 v2 的纯加法近似）。
>
> **这就是"非加法"的含义**：`exp(−(τ1+τ2))` 只是"总消光可加"这一层仍成立；但**内散射 `S` 的合成必须带透射率权重**，v2 里 `Σ S_i` 的一阶近似在浓雾重叠时会偏亮——TPZ 用区间切分修正它。

### 4.4 连续性（"不闪"的命门）

**四条件**（相对 v2 §6 的不闪清单，TPZ 版）：

1. **切 M 段必须在"未裁剪球弦"上做**，再对每段**裁剪**到 `z_scene`。
   ❌ 若在"裁剪后的弦"上重新切 → 遮挡边界一动，M 个采样点**整体跳** → 反而闪。（v2 风险 2）
2. **段中心位置是视线的连续函数**（球求交 + 均匀分 = 连续）。
3. **阴影采样值连续**（→ VSM 的话题，见 §8）。
4. **L1 成员集稳定**（§3.3）+ **tile 表世界对齐**。

**判据**：只要"采样点随几何连续不突变"，单像素积分结果即不闪。**偏差 ≠ 闪烁**——M 小会有"连续的分层偏差"，但不会闪。

### 4.5 上限与合并（S_max = 20）

- L1 给每像素 **≤ K=16 团**；理论上 16×4 = **64 段** > 20。
- 但**切基本区间后，重叠的雾会被合并**（很多小区间并成一条），实际段数远小于 64。
- 仍超 20 时：**按重要度 `σ·段长` 保留**，并把 σ/color 接近的相邻区间**合并**。
- ⚠️ **触顶丢段 = 段级 popping**（与 L1 的"缝"同源），必须**埋点 + 滞后**。

### 4.6 深度裁剪

- 段 `z ≥ z_scene`（不透明）→ 丢弃或截断到 `z_scene`。
- 全在墙后的雾 → `τ≈0` 自动消失。
- **τ 饱和早退**：`T_acc → 0` 时后续区间不可见，可 break（病态重叠自收敛）。

## 5. 数据模型与配置

### 5.1 用户可配（简单"衰减类型"配置法）

```cpp
struct PointFog {
    Vec3  center;        // 摆放位置（世界系）
    float radius;        // 尺寸
    Color color;         // 介质色 / 内散射色
    float intensity;     // 强度（HDR，可 > 1）
    FogProfile profile;  // 衰减（剖面）类型 —— "衰减类型"配置法的核心
};
```

> **配置哲学（继承 v2 §4.2）**：用户只配**直观量**（颜色/尺寸/强度/**衰减类型**）；一切**观感/性能风险量**由 JPOV 锁定。

### 5.2 JPOV 锁定（不给用户）

| 参数 | 默认 | 说明 |
|---|---|---|
| `M`（每团段数） | **4** | 弦上均匀分段数；质量旋钮 |
| `K`（tile cap） | **16** | 每 tile(每像素) 雾体上限（L1） |
| `S_max`（段上限） | **20** | 每像素参与合成的 segment 上限（L2） |
| tile 尺寸 | **16 或 32** | CPU/GPU 旋钮，最优点 ≈ 平均团屏幕半径 |
| 相位 `g` | 0 | v1 各向同性 |
| L3 深度高斯 | off | 第二阶段 |

### 5.3 命令层

```cpp
std::vector<PointFog> point_fogs;   // 与 point_lights 并列
```
- 无状态快照、不含业务名、不外泄 GL（沿用 effect 家族分层）。
- 雾体的寿命/飘动/发射器住**用户侧**。
- 属性预烘进**缓冲纹理**；每帧可预烘每团的慢变项 `L_in`。

## 6. L3 — 深度正确的屏幕空间高斯（可选，v1 不做）

### 6.1 想法（Danis）

> *"屏幕空间高斯时，一个像素 a 被邻居 blend 时，邻居只有 z 和 a 深度'共享'的部分产生相互作用。"*

即：blur 的权重不看"表面深度的差"，而看**两像素的雾在 z 上真正重叠了多少**。对**局部点雾**（不是铺满全屏的雾）尤其对：两个不同表面深度的像素，可能共享"前面那段雾"，应当能互相 blur；而"只有一个像素有的那段雾"不该被抹过去。

### 6.2 ⚠️ 一个反噬（必须先认清）

> **你只能对"还没在 z 上积分掉"的内容做深度正确的模糊。**

L2 输出的是 `(T_total, S_total)` —— **z 结构已经丢了**。此时再怎么给邻居加权，也只是把两个**已经积完分的**结果重新加权，回不到"只 blur 共享 z 段"。想真做到，必须把每像素的 z 内容**保留到模糊那一刻**：

- **(a) 每像素保留 K_z 个粗 z-band 的 `(T,S)`**（= 每像素一根极细 froxel 柱）→ 逐 band 模糊 → 重组。
- (b) 对 segment 列表做 deep-image 式**跨像素配段** → 需要共享 z 基准，基本等价于 (a)。

**而 (a) 需要把 z 量化成共享的 K_z 带 —— 共享 z 带正是 froxel 格量化闪的根源。**
⇒ **L3 的全量版有把 L2 好不容易避开的"格量化闪"重新引回来的风险。**（除非带界是"雾自身的解析边界"而非固定网格，但跨像素解析配对很贵。）

### 6.3 折中（v1 形态）

- **参与度加权的单层 bilateral**：权重 = 两像素雾支撑在 z 上的重叠度（如基于 `min(z_surface)` 的连续量）。便宜、连续（不引入闪烁），但**只重加权、不重积分** ⇒ 近似。
- **对 L1 的"缝"依然无解**（缺一块，blur 补不回）。
- **必须先指明它治的具体 artifact**（VSM 低分辨率走样？段级 aliasing？blob 轮廓？），否则不做。

### 6.4 结论

**v1 = L1 + L2。** L3 是"可选、小半径、先定性目标"的第二阶段。它是唯一会 reintroduce 闪烁/复杂度的环节，别让它拖垮第一版。

## 7. 雾体光照与剖面（继承 v2）

### 7.1 `L_in` 的拆分（v2 §7.2）

- **慢变项**（ambient + 近邻点光）→ **每团每帧预烘一个 Vec3**。
- **sun × shadow（高频）→ 必须逐像素**（团心烘它出不了光柱）。
- 相位：v1 `g=0`（各向同性）。

### 7.2 阴影采样 → CSM（v1 用现成 CSM，VSM 搁置；见 §8）

段中心世界位置 → 投影到 CSM → 采阴影 → 乘 sun。**这是唯一的高频项，也是闪烁的可能来源**（段中心移动 + PCF 台阶）。

### 7.3 衰减类型（profile menu，JPOV 锁定）

继承 v2 §6 的"距离平方多项式"闭式剖面（`kDome` / `kSharp` / `kUniform` / `kCoreRamp`）。
- TPZ 这里**只需要"在给定距离处求 σ"**（因为段是均匀假设），**不一定要闭式积分**——但保留闭式合同，便于单测与 gold。
- 剖面必须**软、带限**，堵死"高频窄特征 → 欠采样闪"。

## 8. VSM 决策记录（2026-10-05）

**结论：通用软影 VSM 弃用（同意 Danis）；点雾 v1 也不上 VSM。**

- **通用软影**：VSM 的 Chebyshev 在**深度不连续 + 高方差**处必然低估可见度 → **light bleed**；遮挡物一多、方差一大就压不住。模型缺陷，调参根治不了。`feature/20261003-jpov-vsm-shadow`（Danis 的 MVP）**未合入 main，搁置**。
- **点雾里 VSM 的原角色**：不是软影，是**给一个空间平滑(带限)的阴影值**，兑现"无 TAA 不闪"。
- **为什么 v1 仍不上**：雾是**低对比**软效果，采样点影子跳一下，雾只跳 `(1/M)·Δ·(σL_in)`；M=4、雾薄时可能根本看不见。先把它当**可测 artifact**。
- **真闪时的补救（按序）**：① **方差钳制版 VSM**（min/max variance clamp，~10 行）；② 雾专用的**小半径预滤波**；③ 极致才 **MSM(4 矩)**。**且始终只服务点雾、不碰主阴影**（主阴影留 PCF）——这样"漏光"只影响雾亮度，比物体阴影漏光可接受得多。
- **代价要认清**：v1 不强求"无 TAA 一定不闪"，降级为"**除半影带外不闪**"。这是真实取舍。

## 9. 与 v2 设计的关键差异（供 review）

| 项 | v2（`jpov_volumetric_fog_design.md`） | TPZ | 理由 |
|---|---|---|---|
| z 处理 | **无 z 结构**，逐团加法累加 `τ`/`S` | **每像素 z 段 + 排序合成** | v2 的 `ΣS_i` 是 o(τ²) 近似，浓雾重叠偏亮 |
| 顺序 | **顺序无关、不排序** | **前到后排序**（≤20 段） | 透射率连乘需顺序；换来正确 |
| 段 | 每团 1 次闭式积分 | 每团 **M=4** 段（中点采样） | 让 `L_in(t)` 的 t 依赖（阴影）可被采样 |
| 每像素上界 | K（团） | K（团）× M（段）→ **S_max=20** | 有界工作量 |
| 剖面 | 闭式积分必需 | 只需"求 σ"，保留闭式合同 | 段是均匀假设 |
| L3 | 深度敏感高斯（笼统） | 明确"z 重叠"语义 + 反噬警告 | 先定性目标 |

> v2 的闭式积分核**仍可复用**（作为 `sigma(距离)` 求值器 + 单测锚点）；但渲染载体从"逐团闭式累加"改为"z 段合成"。

## 11. 性能（有界性论证）

- L1：CPU `≈ N·Ā/s² + O(N logN)`；大团支配，旋钮 = 减 K / 增大 tile（v2 §13）。
- L2：GPU `≈ 像素 × min(K_covered, S_max) × (CSM 采样 + 分组)`；**硬上限**。
  - 排序：≤20 段 → ≤40 边界 → 插入排序，固定长度数组，GL3.3 静态循环 hold 得住。
  - 排序/合并可能带来寄存器压力 → 注意。
- L3：`像素 × 核宽² × K_z`（若做），可选。
- 对比：≈「1–3 个全屏 pass + 亚毫秒 CPU」（llvmpipe 下 ×50–100）。

## 14. ZDist —— 逐像素深度函数表示（2026-10-05 晚，Danis 设计 + 评审）

### 14.1 背景：为什么引入 ZDist

L2 原本是「排序段列表 + 前到后合成」。Danis 提出把这些内容统一装进一个**逐像素深度函数 ZDist**：

- 让叠加**可加、乱序**（免排序）→ 简化 GPU 代码；
- 为「**深度正确的屏幕空间高斯**」提供天然载体（在**函数域**按 z 重叠混合）；
- **有界内存**（≤8 控制点）；
- 末端积分时**可插入玻璃事件** → 统一合成器。

> **业界对标**：**Deep Shadow Maps**（每像素可见度函数）、**Fourier Opacity Mapping**（Jansen & Bavoil 2010，透射率函数 + 可加更新、顺序无关）。ZDist = FoM 的**分段线性 + 单调**版本（规避 FoM 的振铃 / 负不透明度）。

### 14.2 数据模型（⚠️ 关键是 `τ`，不是 `T`）

每像素存两个**单调不减**的分段线性函数（z 从墙深 `z_max` 起累积到雾最浅 `z_min`）：

| 符号 | 含义 | 通道 | 叠加性 |
|---|---|---|---|
| `τd(z)` | **光学深度累积** `∫ σ_t dz`（**不是透射率 T**） | 标量 | **加** |
| `Ed(z)` | **源累积** `∫ E dz`，`E` = 每长度内散射/发射亮度 | RGB ×3 | **加** |

- ⚠️ **必须存光学深度 `τ`（可加），不能直接存透射率 `T`（乘性）**。否则退化成「薄介质一阶近似」（浓雾/火会**过亮、段间无自遮挡**）。Danis 2026-10-05 确认「应该是 τ，笔误」。
- 控制点 ≤ **8**（含 `z_min`、`z_max`）。
- `T = exp(−τd)`、`E = dEd/dz` 是**派生量**，末端才用。
- 4 个单调函数 = `τd` + `Ed`(RGB)。

**末端积分（得最终颜色）：**

```
τ_total = τd(z_min)                              # 总光学深度
T_total = exp(−τ_total)
S_total = exp(+τd(z_min)) · ∫ exp(−τd(z)) dEd(z)  # 对分段线性函数做 Stieltjes 积分
L_out   = L_scene · T_total + S_total
```

**玻璃 / 反射事件在积分时插入（§6 的统一合成器）：**

- **透射玻璃面** → `τd` 在该 z 处一个**跳变**（`Δτ = −ln T_glass`）；
- **反射光 / 发光** → `Ed` 在该 z 处一个**台阶**（点源 = 冲激 ⇒ 积分后为阶跃）。
- 因为都是「往单调函数上叠加单调增量」⇒ **仍单调 + 可加 + 乱序** ⇒ 与雾火同栈，**不排序**。

### 14.3 累积（乱序可加）与两阶段降采样

- 每个雾/火 segment（或采样点）产生一份 `(σ, E)` 剖面，**以加法叠加**进 ZDist ⇒ **乱序进入**，与顺序无关。
- **两阶段**（Danis 2026-10-05）：
  1. **精确累加**：FS 里用**够大的缓冲区**把 ZDist 精确累起来（不受 8 点限制）；
  2. **再降采样**到 ≤8 控制点。
  - 这避免了「边插边砍」的**链式漂移**（评审点 2）。降采样用**最小误差**原则；误差度量应对「**最终 exp 积分**」负责，而非函数 L2。
  - `z_min`/`z_max` 恒保留（保总量守恒）。

### 14.4 采样噪声与 M（可配置）

- **单采样升级 = 一个雾个体产出多个 Z-segment（M 个）**，多个 segment 进入 ZDist。
- **平衡**：`M ↑` ⇒ 单帧 ZDist 更准、噪声更少 ⇒ **屏幕空间高斯负担 ↓**。故 **M 设为可配置旋钮**（Danis 2026-10-05）。
- 噪声由谁收敛：在 **M（单帧精度）↔ 屏幕空间高斯** 之间分配（TAA 暂不考虑，见 §14.7）。
- 采样方式**锁定为「分层抖动」**（M 均匀分割 + 段内抖动），见 §14.10。

### 14.5 屏幕空间高斯（函数域、深度正确）

- **就地混合函数**：中心 `ZDist0` 吸收邻居 `ZDist_i`，**只在 z 重叠处**作用；邻居 range 不足处，**按「观测 = ZDist0」补全**（Danis：这是最合理的，逐 z 补全太贵 → 用下式**等价**实现）。
- **增量加权平均**（把 `ZDist0` 当先验、`ZDist_i` 当观测的凸组合）：

```
a = Σ_{j<i} w_j          # 已累积权重（≈1）
b = w_i                  # 当前邻居权重
Z0f ← (a · Z0f + b · Ẑ_i) / (a + b)      # Ẑ_i = 邻居覆盖处取自身，未覆盖处取 Z0f
```

- `w_i` = **高斯权重 × z 重叠系数**（无重叠跳过；重叠占 Z0 的 z-range 100% → 系数 1）。
- **归一化必须**（评审点 4）：否则能量随邻居数增长。
- **学名**：「增量式求平均」= **增量/在线加权平均（incremental / online weighted average，running weighted mean）**；其「先验×a + 观测×b」形式 = **Kalman 式线性更新（convex / linear-blend update）**。

### 14.6 与「排序段列表」的关系

ZDist **等价**于把 §4 的段列表**连续化 + 可加化**：§4 的「σ 加权基本区间合并 + 前到后」是它的一个**离散解**；ZDist 用**单调可加累积 + 末端 exp** 表达同一个积分，且**免排序**。

### 14.7 TAA 变体（暂缓 —— Danis 2026-10-05：再议）

- 变体：采样抖动移到**时间域**，直接对 ZDist 纹理 TAA。
- ⚠️ **致命点**：降采样让控制点**逐帧跳变** ⇒ 历史重投影无稳定对应 ⇒ **ghost / flicker**；不是简单替换，是**新子系统**。且破坏「确定 = gold」契约。

### 14.8 评审风险（已响应）

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 存 `T` 而非 `τ` → 浓雾过亮 | ✅ 存 `τd`（§14.2） |
| 2 | 降采样 order-dependent / 漂移 | ✅ 两阶段：精确累加后重建（§14.3） |
| 3 | 单采样噪声谁收敛 | ✅ M 可配（§14.4）；TAA 再议 |
| 4 | 高斯未归一化 → 能量涨 | ✅ 增量加权平均归一化（§14.5） |
| 5 | TAA 控制点不匹配 → ghost | ⏸ 暂不做（§14.7） |
| 6 | 玻璃(反射 S)与一阶近似的复合误差 | ✅ 用 `τ` 域后为精确（§14.2） |

### 14.9 ZDist 采样点：锁定 8（Danis 2026-10-05）

- ZDist 控制点**锁定为 8**（含 `z_min`、`z_max`）。
- 哲学：8 = 「画家一像素顶多考虑 8 层雾」的**有界层数**。
- ✅ **锁定决定：8 不变。**
- （备选 / 后话，**暂不采用**）若日后要更省内存：① 降至 ≤6；② **level-sampled**（存 `τd` 达固定 8 个 τ 档位对应的 z，= Deep Shadow Map 的 transmittance-function 表达，**单调性免费**，语义最贴「8 层」）；③ `Ed` 存 **half** / 亮度+色度；④ Fourier / 矩压缩（FoM，需 clamp 振铃）。
- ❌ **不用固定 z 网格**（会 reintroduce 格量化闪）。

### 14.10 采样：分层抖动（stratified jitter）—— 「M 均匀分割 + 段内抖动」plus 版（Danis 2026-10-05 锁定）

- **病根**：M=3 **纯随机会结块 + 低频误差**，而屏幕空间高斯**只擅长抹高频误差** ⇒ **错配**。
- ✅ **锁定做法**：把雾/火弦按 **M 均匀分割**（§4.2），然后**每段内部再加抖动**（不再取段中心固定点，也不整弦随机）⇒ **覆盖均匀 + 抖动去驻波**，杀掉结块。
  - 等价于把 §4.2 的采样点从「段中心」升级为「**段中心 + 段内抖动**」。
  - `M` 仍**可配置**（§14.4）。
- **（建议 / 待评估，未锁定）**：
  - **蓝噪声 / 低差异序列当种子** `f(pixel_id, instance_id)` ⇒ 邻居**去相关** + 跨帧**确定**（保 gold）。
  - **按重要性分配采样预算**：总预算 ≈8~12，按「`弦长 × 屏幕覆盖 × 强度`」分给各 instance（**弦长=唯一先验，当一等输入**）。
  - **前端加权 + 对偶对**（`u`、`1−u`）。
  - **确定性正交采样**（Gauss–Legendre）：无噪声，但可能「洋葱圈」。
- **目标**：把每像素误差做成**零均值 + 高频 + 跨像素去相关**，再喂高斯；**仍确定、可 gold**（很可能连 TAA 都不需要）。
