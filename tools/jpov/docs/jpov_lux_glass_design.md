## 0. 一句话

把「反射」和「透明合成」这两个**已经验证过的组件**解耦成服务，再相乘：

- **SSR 不再假设反射体来自不透明 attr pass**，而是消费一张全屏 **querry**（这个像素要不要反射、从哪起、法线多少、粗糙度多少）；
- **透明层不再是雾合成器的私有输入**，而是**公共契约**（每像素一个「薄片」：颜色 + 覆盖率 + 代表深度），合成器按像素消费它，SSR 沿射线消费它。

有了这两条，水与贵玻璃（都**不做折射**）就都退化成「一个 WBO 层 + 一个反射源」，数量不再受管线结构限制。

## 2. 为什么「水皮必须插在 SSR 之前」是个伪矛盾

一度认为的冲突：

> 水要享受反射 ⇒ 必须在 SSR 之前；但水的颜色要进 WBO 而不是背景板 ⇒ 必须离开 HDR。

实际不成立，因为 **SSR 需要的是水面的「位置 + 法线」，不是水面的「颜色」**。

`SsrRenderer` 的输入只有四样：颜色、`w` 深度、法线、相机。其中"颜色"是**取命中点颜色**用的——反射射线打到的是水面**上方**的世界，那一带的颜色本来就在不透明 HDR 里。水面自己的颜色对 SSR 完全没有用处。

⇒ **需要出现在 SSR 之前的是水面的 G-buffer，不是水面的着色。** 着色可以放到 SSR 之后，那时反射纹理已经有了。

### 2.1 但真要复用 SSR，有一个必须先拆的坑

`src/ssr/ssr_shader.h` 里 `uW` 一张纹理同时当两个角色：

```glsl
SsrWAt(ray, sigma)        // 射线在这一格处的 w —— 由原点 w 推出
texelFetch(uW, cell)      // 这一格柱子的深度 —— 命中判据
```

射线原点 w 就是从这张图的**原点格**读的。让水面写进这张图，射线一出原点格就会撞到水面自己那个柱子（水面 `z → z+T`）⇒ **自命中**。

所以真要在同一趟里复用，最小改动是：**把「原点 w」与「遮挡 w」拆成两张纹理**（多一个 sampler，只改 ray 初始化那一行）。

本设计 **v1 不采用**这条路径：全局水走平面反射（D4），不需要进 SSR 的输入。

## 3. 全局水用平面反射，贵玻璃用 env

| | 平面反射 | SSR | env probe |
|---|---|---|---|
| 屏外 / 身后 / 边界 | ✅ 几何精确 | ❌ 出屏即丢，靠 env 兜底 | ✅（只有环境，无场景物体） |
| 质量 | 精确镜像 | 屏幕空间近似，掠射拉伸 | 无空间对应 |
| 成本 | **一次不透明场景重画** | 每像素一条 DDA，与场景无关 | 一次 128² 立方体 |
| 可支持数量 | 1~2（每个平面一次重画） | 任意（数量无关） | 任意 |
| 需水面进 G-buffer | 否 | 是（位置 + 法线） | 否 |

⇒ 分工：**全局水 = 平面反射；大量贵玻璃 = env probe（廉价）+ 将来按需 SSR（贵，但只付一次）。**

玻璃单面反射率低（F0 = 0.04），env probe 在多数视角下已经够用；真正的短板是「反射里没有场景物体」，这由 §5.4 的 querry 化解决，而不是必须给每块玻璃做平面反射。

## 4. 目标结构

### 4.1 链路（L4 之后的完整形态）

```
opaque 3D
  → HDR color(RGBA16F) + MRT#1(opaque depth) + attr(normal / F0 / roughness)
  → SSR（实心反射体，独立链路，照旧；只写 HDR 的 env 替换项）
  → 平面反射（镜像相机重画不透明 → 反射纹理）      ← 全局水（1~2 个）
  → raw WBO 生产者：
        粒子(1/2) / 体积火(1×) / 条带(1×) / 贵玻璃(1×, 无反射)
        贵玻璃同时写 ReflectionQuerry(z, N, F0, roughness)
  → FogBuild → FogField
  → SSR #2（querry 驱动；输入含"薄片集合"）→ ssr_rad
  → 贵玻璃着色：ssr_rad + Fresnel + Beer-Lambert → rf_wbo
  → fog composite：雾段 + N 个层（rf_wbo / 粒子 / 火 / 条带 / 水面）
  → highlight → bloom → tonemap
```

L1 / L2 阶段没有 SSR 与 querry，链路是：

```
opaque → SSR(实心) → [水面: 平面反射 + WBO] → [玻璃: env + WBO] → 粒子/火/条带 WBO
       → FogBuild → fog composite(雾段 + N 层) → highlight → bloom → tonemap
```

### 4.2 三个「产品」（生产者只写、不消费）

| 产品 | 形态 | 生产者 | 消费者 |
|---|---|---|---|
| **OpaqueGbuffer** | HDR color + `w` 深度 + attr | 不透明 3D pass | SSR、平面反射、薄片积分 |
| **TransparentLayerSet** | 每层 `accum / reveal / depth` + `scale` | 粒子 / 火 / 条带 / 水 / 玻璃 | fog composite（按像素）、SSR（沿射线） |
| **ReflectionQuerry** | 全屏一张：`has_query, z, N, F0, roughness, layer_id` | attr pass（实心）+ 水/玻璃 pass | SSR |

**核心约定：产品由生产者写出，消费者只读。** 任何"我要别人的结果"都必须表达成"读一个产品"，不允许 pass 之间点对点耦合。

## 5. 契约变更

### 5.1 `TransparentLayer` 必须先有 `depth`（现状为零）

`src/transparent_layer.h` 的 `valid()` 要求 `accum / reveal / depth` 三张全部非 0。而三个生产者今天全是：

```cpp
particles:    wbo_.Ensure({w, h, /*with_additive=*/true,  /*with_depth=*/false, true});
volume_fire:  wbo_.Ensure({w, h, /*with_additive=*/false, /*with_depth=*/false, true});
strip:        wbo_.Ensure({w, h, /*with_additive=*/with_additive, /*with_depth=*/false, false});
```

⇒ **一帧都凑不出一个合法层**，`fog_composite_.Draw(..., TransparentLayerSet{})` 传空是结构性接不上，不是"暂缓"。

必须补的三件事：

1. `with_depth = true`（`WboTarget` 会申请 att3 `R32F`，深度槽**恒 NEAREST**，不受 `linear_filter` 影响）；
2. FS 增加 `layout(location = 3) out`，写 `Σ(z_view · α · w)`；
3. 停掉各自 `Composite()`，改成把三张纹理 + `scale` 交给合成器。

`z̄ = att3 / accum.a` 是**加权平均深度**，且强烈偏向前方片元 —— `WeightWbo` 的深度因子 `clamp(0.03/(1e-5+(z/5)^4), 1e-2, 3e3)`，近处权重 3e3 对远处 1e-2。**它不是 min-z，也不是前表面。** 对薄片正好；对厚的透明团是近似（§8.5）。

### 5.2 加法集在 3 张纹理里没有位置

`TransparentLayer` 只有 `accum / reveal / depth`，而条带的 `kEmissive` 批走 att2 真加法。

设计文档 §4 曾说"加性发射层（cov = 0）走同一条公式，无需特判"——**这个不成立**：

```
C_premult = Cavg · (1 − T) = (accum.rgb / accum.a) · cov
```

加法集 α 恒 0 ⇒ `accum.a = 0` ⇒ 要么早退输出 0，要么除零。**cov = 0 就意味着颜色贡献恒为 0**，光全丢。

两个选项（**待定，见 §10**）：

- **A**：契约加第 4 张纹理 `add`，合成器加一项 `L += W · add`；
- **B**：加法集继续走独立 over（但同帧就出现两套顺序语义，需显式写进文档）。

### 5.3 `ReflectionQuerry`

```cpp
// 全屏一张（1×）：本像素的反射请求。每像素最多一个反射体。
struct ReflectionQuerryPixel {
    float z;          // 反射面在视空间的深度（米）
    vec3  normal;     // 视空间法线（扰动后）
    vec3  f0;         // 菲涅尔 F0
    float roughness;  // 供 SSR 的 LOD / 粗糙度预滤波
    uint  layer_id;   // 0 = 实心；>0 = 透明层序号（用于"别照见自己"）
    bool  has_query;
};
```

实现上不必是 AoS 结构，可以拆成 3~4 张附件；形态留给实现，**语义固定**。

### 5.4 仲裁规则：每像素一个反射体，取最前面

玻璃前面有一块金属时，同一像素有两个反射请求。**v1 规则：取视空间深度最小的那一个**（与合成器"每像素一个层"的限制语义一致）。

D5 的代价就在这里：**被玻璃遮住的那块金属在 v1 拿不到反射**（高光消失），退回 env specular。要修需要两趟 SSR（§10）。

## 6. SSR 的「薄片输入」（L4）

### 6.1 积分代数

射线沿途每个 screen cell，若该格存在薄片（`layer_id != 本反射体`），当射线深度越过薄片的 `z̄` 时：

```
C += T · (accum.rgb / accum.a) · (1 − reveal)
T *= reveal
```

与 fog composite 的层解算是**同一个代数**，只是采样位置从「本像素」换成「射线当前格」。

要点：

1. **命中实体仍然终止射线**；薄片**不终止**，只衰减与累加。⇒ 成本模型基本不变（终止条件仍是 solid hit 或预算耗尽）。
2. **必须排除自身**：反射体不能照见自己（`layer_id` 比对，或射线从 `z̄ + ε` 起步）。不做这一条，玻璃会自己把自己染绿。
3. **薄片集合用 `TransparentLayerSet`，不要合成成一层**。合并后的 `z̄ = Σ(z̄_i·a_i)/Σ(a_i)` 会把 3 米外的粒子云和 10 米外的玻璃压成一个切点，反射里的透明积分会糊成一片。契约支持 4 层，每格多 2~3 次 fetch，v1 不必优化。

### 6.2 分辨率不一致

粒子的 WBO 是 1/2 分辨率，全分辨率射线采样会出半像素错位的光晕。需要给射线一份**降采样的薄片表示**（粗格上取保守的 `z` 与平均 `reveal`）。

### 6.3 关于「金字塔」——两种含义要分开

| 含义 | 结论 |
|---|---|
| **用金字塔加速 DDA 遍历** | ❌ **不做**。`ssr_renderer.h` 的并行分段方案（2026-10-29 Danis 定）就是**替代** §5.5 min 金字塔的；契约第 7 条要求「成本可解析 ≤ 1.414·max_ray_pixels + T²，**与场景几何无关**」，层级遍历会让步数变成内容相关的变量，gold 也会跟着抖。 |
| **给射线用的薄片降采样表示** | ✅ 要做。这是**数据的表示**（粗格平均），不是**遍历的加速**。 |

## 7. 分阶段计划

| 阶段 | 内容 | 验收判据 | 依赖 |
|---|---|---|---|
| **L0** | 三家写 `att3` + 接进 fog composite（含 §5.2 的加法集方案定稿） | 关雾时逐字节零回归；开雾时"粒子在雾前/雾后"可分辨；gold 稳定 | 无（**当前唯一的前置**） |
| **L1** | 全局水 = 平面反射 + WBO 层；**不写 MRT#1** | 水下粒子不被剔除；水能挡住水面后的火（按 `z̄` 排序）；水面不污染粒子软深度 | L0 |
| **L2** | 贵玻璃 = env probe + WBO 层；box mesh，不用条带 | 玻璃挡火/挡粒子正确；玻璃板自身有菲涅尔反射；无"有色塑料膜"观感 | L0 |
| **L3** | SSR querry 化（反射服务）：实心与玻璃共用一趟 | 实心路径逐字节等价于现状；玻璃有屏幕空间反射；仲裁规则生效 | L1/L2 |
| **L4** | 薄片进反射（§6） | 镜面里能看到粒子/火/条带/玻璃；不自着色；成本在预算内 | L3 |
| **L5**（可选） | 两趟 SSR（玻璃后的金属也有高光） | 玻璃后金属的反射恢复 | L4 |

**L1 + L2 做完就应该能回答"大量水与大量玻璃的观感是否成立"。L3~L5 是加分项。**

## 8. 已知限制（v1 记账，别当 bug 追）

1. **玻璃后方的金属失去高光**（D5 / §5.4）：每像素一个反射请求，被遮挡的反射体退 env。
2. **水下雾用空气的 σ**：fog composite 的末段是"最后一层 → `z_op`"，用的是同一个雾场；水体的吸收/散射拿不到。要拿全需让 fog field 知道"自己在水下"（第二个场，或场里存两套 σ）。
3. **反射内容只含不透明 + 天空**（L4 之前）：平面反射的目标 FBO 只画不透明；SSR 读的是不透明 HDR。
4. **每像素一个反射体 / 一个层**：WBO 与 querry 的共同边界。
5. **WBO 单切点**：一个前后跨数米的透明团会被压成一个 `z̄`，内部的前后关系丢失。要修只能上 MBOIT / 逐像素链表。
6. **1/2 分辨率薄片进反射会有光晕**（§6.2）。
7. **无折射**：近处浅水缺"池底扭曲"，玻璃背后无位移。有意为之（D2）。

## 9. 明确不做

### 9.1 折射
跨像素位移 ⇒ 同像素的逐趟合成在数学上不可能，必须 pass 边界；且已有一次失败（锥缘拉条）。水/玻璃只做法线扰动（像素本地，可进 WBO）。

### 9.2 SSR 里的多次弹射 / 时间累积 / 降噪
与 `jpov_ssr_v2_design.md` §1.2 一致：JPOV 写死"每帧从零构建、可进 gold"。

### 9.3 用条带拼水缸
两个理由：

1. **法线语义对不上**：条带是 1D 参数化曲面，法线是管子/带子的解析法线；拼成盒子接缝处法线是断的，SSR 的"命中面朝向判据（`R·N < 0`）"在断面上会大量拒绝。
2. **条带没有 attr 通路**：`ssr_renderer.h` 明写"属性 pass 目前只覆盖 object3d（静态实例 / 蒙皮 / 图元各自还需要一份 attr VS）"。条带连第一档都没有，新开一条 attr VS 的代价大于直接建 box mesh。

⇒ 玻璃用 **box mesh**（object3d 的 attr pass 现成，每个面本来就是平面）；条带留给它擅长的东西（叶片 / 衣摆 / 火焰片）。

## 10. 待定项

1. **加法集在 `TransparentLayer` 中的表示**（§5.2 的 A/B）——**L0 之前必须定**。
2. **水是否也要进 querry**（与平面反射二选一，还是近处平面反射 + 远处 SSR 混合）。
3. **`rf_wbo` 是否要第二遍玻璃几何**：raw WBO 只为"薄片进反射"服务；如果玻璃量很大，可以省掉 raw（代价是玻璃照不见玻璃）。
4. **两趟 SSR 的形态**（L5）：是同一趟跑两次，还是一趟内对"被遮挡的反射体"做第二次短 march。
