# JPOV ARAP 软体查看器（arap_viewer）设计说明

> 状态：PR 交付物。作者：James（2026-09-22）。需求方：Danis。
> 目标：把「衣物自动贴合人模」这条链路里**动力学仿真**那一环先落地成可交互验证的工具。

---

## 1. 目标与非目标

**目标**

1. 一个与 `jpov_model_viewer` **并列**的交互式查看器：能加载 glb、调视角/光照/地面高度。
2. 额外提供**软体动力学**：把网格当作可变形软体，在重力场里从高处摔到地面，
   观察其形变与回弹。
3. 交代清楚「CPU 网格变形后，法线/切线怎么办」——这是需求方在 PR 拆分时点名的未决问题。
4. 物理参数（重力/阻尼/软硬/摩擦）**先代码内配置**；界面只暴露标高与光照量。

**非目标（本 PR 明确不做）**

- 不接骨骼/蒙皮（那是 `jpov_clothes_rig_design.md` 的 weight transfer 一环）。
- 不做自碰撞（衣服 vs 衣服）、不做真实人体碰撞（本 PR 的地面是平面）。
- 不做 bending（弯曲）刚度与体积保持——**这正是本 PR 得出的关键结论，见 §7**。

## 3. 力的模型（四个力，每个都能单独开关）

```
每子步：
  ① 预测        v += g·h ;   prev = x ;   x += v·h
  ② 局部旋转    每个质点算 1-ring 的最优旋转 R_i（极分解）
  ③ 形状恢复    goal_i = c_i + R_i·(rest_i − rest_c_i)   ← 每子步投影一次
  ④ 约束迭代    边长约束、地面碰撞（地面放最后）
  ⑤ 速度回写    v = (x − prev)/h · 阻尼 ;  接触点再乘切向摩擦
```

### 3.1 形状恢复力 = meshless shape matching（ARAP 同源）

出处：Müller et al. 2005《Meshless Deformations Based on Shape Matching》，
与 Sorkine & Alexa 2007 的 ARAP 同源（都是「局部形状 → 只允许旋转」）。

**关键点：这不是「全局拉回原始世界坐标」**。目标是**局部**的：

- `c_i` = 当前邻域质心、`rest_c_i` = 原始邻域质心、`R_i` = 邻域最优旋转。
- 因此整个物体可以**任意平移 + 旋转**而形状代价为零；
- 只有「局部形状被拉伸/压扁」才付能量。

`R_i` 由协方差矩阵 `A = Σ (x_j − c_i)⊗(rest_j − rest_c_i)` 的**极分解**得到
（Higham 不动点迭代 `R ← ½(R + R⁻ᵀ)`，先用 Frobenius 范数归一化）。

### 3.2 边长约束

普通 PBD 距离约束（把两端各移误差一半）。

### 3.3 地面碰撞 = PBD 位置投影（**完全非弹性**）

需求方 2026-09-22 定稿采纳此法（而非「入侵深度正相关的斥力」）：
**无条件稳定，且力的大小与时间步解耦**——避免罚函数法那种「10 倍斥力」拍脑袋刚度
带来的 `dt` 稳定性耦合。

### 3.4 摩擦

只有法向约束的话，落地后物体像在**冰面**上滑走（实测：滑出画面几个单位）。
故对**本子步与地面发生投影的质点**施加切向速度衰减
（`v_xz *= exp(−friction·h)`，法向不受影响——摩擦不产生法向力）。

## 4. 拓扑：物理用「焊接」，渲染用「不焊接」

**这两者必须分开，是两条独立的不变量。**

| 用途 | 拓扑 | 为什么 |
|---|---|---|
| **物理**（ARAP/边长/碰撞） | **按位置焊接**（ε = 1e-6，仅在 bind pose 判定一次） | UV 缝两侧的顶点几何上是同一表面点；不焊接会被约束力拉开成**裂缝** |
| **渲染**（法线/切线） | **不焊接**（按顶点索引取邻域） | 顶点分裂是数据的一部分：硬边（split normal）靠它保留。焊接一刀切会把棱磨圆（反例：直棱柱三条棱交会处一个位置三个顶点，法线分别是上/左/右面） |

`ε` **只在构建时（bind pose）判定一次，之后永久固定**——变形后位置会漂移，
若每帧重新焊接会把「本已分开的两点」错焊。

**焊接映射与符号 w 一样，属于「与几何变形无关的静态拓扑信息」。**

## 5. 变形后法线/切线怎么办（需求方点名的未决问题）

**结论：不「补」，也不「旋转旧值」——每帧用变形后的位置重跑同一个函数。**

```
Step() → WriteBackPositions() → RecomputeTangentSpace() → UpdateMesh() → Draw()
                                    ↑ 位置变了 ⇒ 法线/切线（位置的派生量）失效
```

- **法线**：面叉乘 → 面积加权累加到顶点 → 归一化（按**索引**，不焊接）。
- **切线**：`T = ∂P/∂u`，用**变形后的位置 + 不变的 UV** 解 2×2 线性方程组。
  公式与 `obj_loader.cc::ComputeTangents` / `gltf_loader.cc` **逐字一致**，
  保证与既有 JPOV 管线同源、不产生第二套约定。
- **B（副切线）不存**：shader 内 `B = cross(N,T)`。
- **法线贴图无需处理**：它存的是切线空间下的**相对**方向；只要 TBN 的 N/T 跟着
  几何走即可。**UV 不变**是本方案成立的前提（变形不改 UV）。
- `load 时` 与 `每帧` 调的是**同一个函数**（同源优先于省一点计算）。

**退化处理**：`|det(UV)| < 1e-8` 或面切线长度为 0 的三角形跳过切线贡献（不除零）；
全部退化时记 WARNING 且 tangents 全零，由调用方摘掉材质的法线贴图
（`AddPrimitive` 里已实现该回落，避免渲染侧 CHECK 崩溃）。

## 6. 相机、UI 与 headless

- **取景**：ViewConfig 的球面角相机恒以原点为目标点，而本场景是「模型在上、地面在下」，
  故把相机目标点下移到「模型顶 ↔ 地面」的中点（x/z 仍为 0），并按所需垂直半跨度反推 `R`。
  `ApplyInput` 只改 phi/theta/R，与目标点无关，故交互手感不变。
- **UI**：顶部两个按钮（动力学启停 / 重置 mesh）+ 状态文本（顶点/质点/边长畸变），
  底部 4 个滑条（太阳仰角 / 浊度 / 季节 R / 地面高度）。
  太阳仰角默认 **55°**（不取 90°：正顶光会让所有竖直面 N·L≈0 只吃 ambient 而发黑）。
- **headless**：`--headless_drop` 逐帧推进并落盘 PNG（每帧都走同一条 `OneIteration`，
  零分叉）；`--ui_shot` 单帧 + 面板，用于无显示器环境下检查 UI 布局/字体。

**两个诊断量的区别（踩过坑）**：

| 量 | 含义 |
|---|---|
| `shape_residual_rms()` | **约束违反度**。约束满足时接近 0，**即使整体已被压扁**（局部旋转跟着变了）→ 适合单测 |
| `edge_distortion_rms()` | **边长畸变 RMS**（旋转/平移不变）→ 才是「被压扁了多少」，适合面板显示 |

## 7. 🔑 关键实测结论：ARAP 不会自己变成「充气城堡」

需求方原始预期：给个重力场摔一下，看是不是「充气城堡」的样子。**实测不是。**

**证据（内质方块，不能翻倒，只能靠压缩响应）**：

- 边长畸变在落地时只到 ~4%~9%，包围盒高度在 `0.86 ↔ 1.07`（约 ±12%）间振荡，侧面横向鼓包 ±22%。
- 也就是说：**是弹性形变，但幅度不大，而且它会先选择「翻倒/弯曲」这条零能量路径。**

**根因（物理，不是 bug）**：

1. **ARAP 允许「等距变形」（弯曲/折叠/旋转）零代价**——它抵抗**拉伸/压缩**，不抵抗**弯曲**。
   所以一个能翻倒的物体（抛石机、树、钱包）在碰撞时会**翻倒**而不是压扁。
2. 面板上 `shape_restore_rate` 与 `stretch_restore_rate` 取大值时，二者叠加会把物体
   锁成**完全刚体**（连碰撞压扁都做不到，实测边长畸变 6e-6）。

**想要「充气城堡」需要补的东西**：

- **弯曲刚度（bending stiffness / dihedral 二面角弹簧）**：抵抗折叠；
- 和/或**体积保持约束**（气球感来自「体积几乎不可压」）。

这两项都是**独立的能量项**，可以后续按同样方式（PBD 约束）加进 `arap_sim.cc`。

**但对衣物（薄壳）而言，当前行为其实正是想要的**：薄壳会自然**折叠/垂坠**去贴附人体，
而不会被压成饼——「draping」而非「squash」。

## 8. 物理参数（代码内配置）

全部在 `ArapSimConfig`（`demo/arap_sim.h`），默认值在查看器里由 `sim_config_` 给出：

| 参数 | 默认 | 含义 |
|---|---|---|
| `gravity` | `(0,−9.8,0)` | 重力加速度（模型长度/秒²） |
| `velocity_damping_per_second` | 1.0 | 速度阻尼（1/秒，1−e^{−rate·h} 每子步） |
| `shape_restore_rate_per_second` | 0.08 | **形状恢复力每秒恢复率**（1/秒） |
| `stretch_restore_rate_per_second` | 4.0 | **边长约束每秒恢复率**（1/秒） |
| `substeps` | 6 | 每帧子步数 |
| `solver_iterations` | 4 | 每子步约束迭代次数（仅边长/地面） |
| `ground_y` / `ground_offset` | 由界面滑条 / 0.002 | 地面高度 / 离地间隙 |
| `ground_friction_per_second` | 6.0 | 接触点切向摩擦（1/秒） |
| `enable_shape/stretch/ground` | true×3 | **单变量消融开关**（一次只关一个，看差异归因于谁） |

> **量纲教训（写在代码注释里）**：PBD 里「每子步投影比例 s」**不是物理刚度**——
> 它等效于弹簧 `k ≈ s/h²`，而 `h` 很小（1/360 秒）⇒ `s` 取 0.1 看着小，实际等效刚度
> 是巨量级，物体表现得像刚体。故本实现改用**每秒恢复率** `rate`：
> `s = 1 − exp(−rate·h)`，才有直观量纲（误差按时间常数 `1/rate` 衰减）。

## 9. 踩过的坑（都已修 + 有单测/数据）

1. **初始穿透 ⇒ 碰撞凭空注入 120 m/s 速度 ⇒ 整个仿真炸飞。**
   根因：`prev`（速度回写的参考位置）本身落在不可行域（初始就与地面相交），
   于是 `v = (x − prev)/h` 把「地面把他推上来的那一段」当成了速度。
   **修法：把参考位置一并投射到可行域（地面以上）。** 合法的弹起不受影响
   （那种情形下 prev 在地面上、x 被约束推高，差值就是真实速度）。
2. **极分解在近奇异（压扁成近似平面）时爆炸。**
   `det` 是个极小**正数**而非 0，`det ≤ 0` 的判据漏过 ⇒ 3×3 求逆把 R 放大到 1e9 量级。
   **修法：改用归一化后的相对行列式阈值（`|det_n| < 1e-4` ⇒ 退回单位阵）。**
3. **无摩擦 = 冰面**：落地后一路滑出画面。
4. **形状匹配放进迭代循环 ⇒ 每帧 16 次投影 ⇒ 无论如何都刚性**，`softness` 旋钮失效。
   **修法：每子步只投影一次。**
5. **诊断量语义错**：约束违反度在约束满足时恒≈0，不能用来判断「压扁了多少」⇒ 另加边长畸变。

## 10. 多 primitive = 同一个物理物体（2026-09-22 交互反馈 #1 后修）

**现象**（Danis 实测路灯）：同一个模型"一部分结构能反抗重力立住，一部分彻底软化掉下去"。

**根因**：`lantern.glb` 是 Unity 导出，按材质切成 **3 个 primitive**
（`LanternPole_Body` / `_Chain` / `_Lantern`）。原实现**每个 primitive 独立仿真** ⇒
三块各自落下、互不碰撞、互不支撑 —— 看起来就像模型散了。

**修法**：把全部 primitive 的顶点并集当作**同一个物体**建一份仿真，**焊接跨
primitive 进行**，接缝处位置重合的顶点焊成同一质点 ⇒ 各部件互相支撑。
（primitive 不接触时焊接自然不连它们，退化为"两个独立物体"——这也正确。）

## 11. 局部旋转判定失败：薄壳退化（反馈 #1 的第二个根因）

**现象**：同一模型上"厚的地方撑得住、薄的地方瘫下去"，且**不是力学固有**（Danis 判断正确）。

**根因**：ARAP 的局部旋转 `R_i` 由 1-ring 协方差的 3×3 极分解得到，而
**薄片结构（灯罩玻璃、单层板、布料）的 1-ring 本身近似共面** ⇒ 协方差秩亏 ⇒
极分解没有唯一解 ⇒ 退化成单位阵 ⇒ 该处**失去旋转不变性**，形状恢复力方向跑偏。

**实测**（抛石机 4481 质点）：静止姿态就有 **1106/4481（25%）** 退化；
落地后 **4481/4481（100%）** 退化。

**修法**：协方差补一个"法向增广项" `δ² · n_cur ⊗ n_rest`（δ = 邻域平均边长）。
对刚性运动 `n_cur = R·n_rest` ⇒ `A = R·(Σd⊗d0 + δ²n_rest⊗n_rest) = R·B`（B 正定）
⇒ `polar(A) = R`，**不破坏刚性不变性**，只把秩补满到 3。

**实测修复效果**：静止退化 **1106 → 0**；落地后 **100% → 10%**（剩下的应是真共面接触区）。

## 12. 🔑 核心结论：ARAP 不会自己长成"充气城堡"（推翻我 2026-09-22 早先的预测）

**现象**（Danis 实测抛石机）："纸糊的，所有点都淌地上"。

**根因（物理，非 bug）**：**ARAP 允许"等距变形"（弯曲/折叠/旋转）零代价** ——
它只抵抗拉伸压缩，**不抵抗折叠**。抛石机/路灯是薄板拼装结构，重力把它像纸盒一样
折平；而**形状残差始终很小**（实测落地后残差 0.008，却整体拍平）—— 这正是
"纯等距折叠"的指纹。

**第二个机制（数值）**：PBD 松弛式中，约束影响沿约束图**一跳一衰减**，
所以一个"软"的刚度无法把力从地面接触点传递到结构顶部（需要的跳数 ~ 结构高度/边长）。
要"撑得住"必须让形状约束接近**硬约束**（每子步比例 ≈ 1）。

**实测对照**（抛石机，落地后包围盒高度 / 原始 0.881）：

| 形状恢复率 | 弯曲恢复率 | 高度 | 结论 |
|---|---|---|---|
| 3（软） | 0 | 0.04 | 拍平（等距折叠） |
| 38 | 0 | 0.12 | 仍折叠 |
| 38 | 200 | 0.17 | 折叠降到 8%，仍塌 |
| 2000（近硬） | 300 | 0.50 | 保住一半 |
| 2000 | **1500** | **0.76** | **保住 86%** ← 当前默认 |

⇒ **结论：要结构件"立得住"，必须同时给近硬的形状恢复率 + 足够硬的弯曲刚度。**
但那样它就不再"软糯"了 —— **软度与结构自支撑在松弛式 PBD 里是直接冲突的**
（要两者兼得需要隐式/全局求解，或 XPBD 的合规约束 + 正确的刚度量纲）。

**对衣物（薄壳）而言这反而正是想要的**：薄壳本来就该**折叠/垂坠**去贴合人体
（draping 而非 squash），而且**人体提供支撑**，不存在"结构自支撑"问题。

## 13. 其它为健壮性补的措施

1. **初始状态可行化**（`Reset()` 里先投射一次地面约束）：大模型（路灯高 20 单位）
   若一开始就与地面相交，第一步要修掉巨大穿透 ⇒ 约束被剧烈违反 ⇒ **爆开**
   （实测首帧畸变 120%、随后飞到 26000）。
2. **地面按模型自动定位**：装载时把地面放到模型底部下方 0.5 个模型高度处，
   滑条范围也按模型尺度自适应（固定 [-3,3] 装不下 20 单位的模型）。
3. **短边过滤**：真实资产常残留极短退化边（1e-5 量级），一拉就爆
   （近刚性投影一步能把它拉长千倍）。拓扑保留、**约束求解与度量跳过**。
4. **接触点法向速度钳制**（地面"完全非弹性"）：位置投影经 `v=(x−prev)/h` 会把
   约束位移变成速度；形状约束与地面夹断互相打架时会反复**泵能量** ⇒
   实测模型落地后横向弹飞 + 拉伸（飞 6 单位、畸变 32%）。钳掉接触点的 +y 速度即消除。
5. **整体平动摩擦**（滚动阻力近似）：逐质点摩擦管不住**滚动**（接触点近静止），
   实测抛石机滚走 5 个单位；本子步有接触时对整体平动速度也施加同一摩擦。
6. **发散保护**：边长畸变 > 100% 时**自动暂停并告警**（"仿真发散，已自动暂停"），
   不把糊掉的几何默默呈现给用户。

## 14. 已知边界 / 后续（诚实清单）

- **路灯（`Lantern.glb`）当前仍会在首步判为发散并自动暂停**：该资产 3 个 primitive
  合并焊接后，首步边长畸变即达 1.11。根因尚未定位（已排除：初始穿透、短边、
  跨 primitive 焊接本身）。**这是本 PR 遗留的未解问题**，但它现在"响亮地失败"
  而不是把模型炸飞到 15000。
- 抛石机默认参数下仍会**压到 86% 高度并横向滑约 2 个单位**；要完全"站住"需继续加大
  形状/弯曲恢复率（代价：失去软糯感）。
- 不接骨骼、不做人体碰撞、不做自碰撞。
- 无体积保持；`bend` 用"对顶点距离"近似二面角（外凸/内凹不对称，属近似）。
- 松弛式 PBD 的"软度 vs 结构自支撑"冲突是**方案级**问题（见 §12），
  若后续要做"既软又撑得住"的物体，需要换数值方案（隐式/XPBD）。
